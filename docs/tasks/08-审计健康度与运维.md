### T-AUD-01 审计骨架、日报载体与样例立法框架
- 里程碑 / 依赖: M3 ；01 文档 T-DB、02 文档 T-TIME
- 设计依据: 04 §10.1（头部样例立法、"凌晨 batch 段后跑"、"任一不过 → 标红 + 告警；连续 3 天不过 → 暂停时钟进人工"）、04 §2.1（`audit/daily.py`）、04 §2.2（`audit.daily_loop()` 协程）
- 目标: 搭起可扩展的审计执行器——6 项 SQL 注册表、违规样例机制、日报落盘、手动/自动双入口。
- 交付物: `server/worldsim/audit/daily.py`、`server/worldsim/audit/sql/`（每项一文件）、`server/worldsim/audit/samples/`（每项一个违规样例 SQL）、`server/scripts/audit_run.py`、`server/tests/audit/conftest.py`
- 实现要点:
  - `daily.py` 暴露 `run_daily_audit(conn) -> AuditReport` 与 `daily_loop()`；自动触发挂在凌晨 batch 段完成之后（TIME 提供钩子，04 §10.1"凌晨 batch 段后跑"）。
  - 每项审计 = `{id, name, sql_path, sample_path, severity}` 注册条目；SQL 文件即唯一实现，禁止在 Python 内拼 SQL 串绕过审计文件。
  - 日报载体：`logs/audit/<sim_day>.json`（机读）+ 同基名 `.md`（人读摘要）；任一不过 → 该日标红并写告警（接口先落内存队列，T-OPS-01 接通文件通道）；**连续 3 个模拟日不过 → 调 TIME 的 `clock.pause` 路径暂停时钟进人工**（04 §10.1；调用通道见"适配与偏差" D8）。
  - `scripts/audit_run.py`：手动跑全量或单项（`--only <id>`），exit code 0=全绿 / 1=有红（00 §2 布局已登记此脚本名）；`--self-test` 标志：在隔离事务/临时库逐条注入 `samples/*.sql` 并只跑对应审计项，断言该样例必报红且其余项不受影响，任一样例不触发即 exit 1——把 04 §10.1 头部"样例立法"落成可执行门禁。
  - 样例立法落实（04 §10.1 头部）：每个 `samples/*.sql` 构造一批确定违规数据；pytest 驱动"样例入库 → 对应审计必报红、其余审计不受影响"；无样例或样例不触发报警的条目不得并入日报。
- 验收标准:
  1. `cd server && uv run python scripts/audit_run.py` 对空库（仅 seed）exit 0，且 `logs/audit/` 生成 JSON+MD 各一。
  2. `cd server && uv run pytest tests/audit/test_framework.py -q` 绿：含"注册 6 项"断言与"样例缺文件即拒绝注册"断言。
  3. 构造连续 3 日标红（重放同一违规样例）→ 断言 `clock.pause` 被调用且出现 `time.paused` 事件（`trigger='system'`，payload 含 `reason`/`at_sim`，06 §1.2）。
  4. `cd server && uv run python scripts/audit_run.py --self-test` 对干净库跑全部样例 exit 0（每个样例均被对应审计捕获）；人为使任一样例失效后 exit 1。
- 实测回填: 无
