### T-SYN-01 payload 键白名单与同步规范形（canonical JSON）

- 里程碑 / 依赖: M6 ；无（模块内）；M0 的 01 T-CFG-05 `gen_event_types.py`（白名单单源派生链：`server/config/event_types.yaml` 转写 06 §1.2 全量为唯一手维护源，`payload_whitelist.yaml` 为其派生产物）；M1 的 02 T-ADJ-09 `worldsim/snapshot/canonical.py`（canonical/digest 唯一实现，R2 §A.7）
- 设计依据: 05 §2.1/§2.2（白名单与 canonical 算法）、06 §1.2"payload 键标注"列（唯一实现依据）、04 §5.1（payload 键约定）
- 目标: 键白名单模块同时服务本机 sync 与副本侧 digest 校验；canonical/digest 复用 02 T-ADJ-09 唯一实现（M1），产出"同步规范形"。
- 交付物: `server/worldsim/sync/whitelist.py`（键白名单）、`server/tests/sync/test_whitelist.py`、`server/tests/sync/test_canonical_consumer.py`（对 T-ADJ-09 实现的消费方回归）；canonical JSON + digest 函数唯一实现 = 02 T-ADJ-09 `server/worldsim/snapshot/canonical.py`（M1 提前交付，R2 §A.7）——本任务 import 消费、禁第二实现，原 `worldsim/sync/canonical.py` 交付物取消；消费 `server/config/payload_whitelist.yaml`（06 §1.2 标注列的机器可读派生物，由 01 T-CFG-05 `gen_event_types.py` 从 `event_types.yaml` 生成——本任务不持生成脚本、不维护第二份手维护镜像）
- 实现要点:
  1. 键白名单**唯一依据 = 06 §1.2 标注列**：public 放行、internal 剥除、`text_display` 条件放行（仅 `visibility='public'` 事件）；未登记键默认剥除（06 §1.2 兜底条款）。
  2. 保底剥除：`text_raw`、prompt 片段、检索上下文、内部评分中间量恒剥除（06 §1.2 通用保底）。
  3. `visibility='internal'` 事件（`state.needs_delta`/`relation.changed`/`time.*`/`system.llm.*`）：结构化 payload 照常放行，不携带任何展示文本键（05 §2.1）。
  4. canonical(payload) = 键白名单剥除 → 递归键名字典序 → 无冗余空白 UTF-8 JSON（05 §2.2）；`digest_events(sim_day)` = `sha256(string_agg(md5(canonical(payload)), '' ORDER BY seq))` + `COUNT(*)` + `SUM(seq)`，按 `date(sim_time)` 分组（05 §2.2）；以上函数实现唯一归 02 T-ADJ-09（M1），本任务 import 消费。
  5. **两端同一实现**（05 §2.2，R2 §A.7）：唯一实现 = 02 T-ADJ-09 `server/worldsim/snapshot/canonical.py`；本机 sync 与副本侧 digest 校验 import 同一实现，禁止两份实现。
- 验收标准:
  1. `cd server && uv run pytest tests/sync/test_whitelist.py::test_text_raw_always_stripped`——构造含 `text_raw` 的 public 事件，剥除后键集无 `text_raw`。
  2. `…::test_unregistered_key_stripped`——payload 塞入 06 §1.2 未登记键，剥除后不存在（默认剥除原则）。
  3. `…::test_text_display_public_only`——同一 `text_display` 键，`visibility='public'` 放行、`'internal'` 剥除。
  4. `…::test_per_type_annotations`——抽查：`agent.promoted` 的 `score 分解`/`gini` 剥除而 `from_tier`/`to_tier` 放行；`dialogue.gossip` 的 `cites[]` 放行；`agent.reflection` 仅 `text_display` 放行（06 §1.2 逐行）。
  5. `cd server && uv run pytest tests/sync/test_canonical_consumer.py::test_key_order_irrelevant`——同值不同键序/空白的 payload 产出同一 canonical 串与同一 md5。
  6. `…::test_digest_formula`——构造 3 事件两日数据集，断言 `digest_events` 返回值 = 手算 `COUNT/SUM(seq)/sha256(string_agg(md5 … ORDER BY seq))`（05 §2.2 公式逐步复算）。
  7. `cd server && uv run python scripts/gen_event_types.py --check` 退出码 0：派生的 `payload_whitelist.yaml` 覆盖 `event_types.yaml`（06 §1.2 全量转写）全部注册类型，差集为空（对拍模式归 01 T-CFG-05，本任务消费其产物）。
  8. `grep -rn "text_raw" server/worldsim/ingest/` 仅命中剥除/校验代码，无透传路径。

### T-SYN-03 sync ws_client：连接、攒批、ACK、断网缓冲

- 里程碑 / 依赖: M6 ；T-SYN-02
- 设计依据: 04 §1.3（帧格式、正常态/断网态流程、ACK 语义、约束块）、04 §9.1（Bearer 鉴权）、04 §2.1（`sync` 只读 `events`，不反向调用内核）
- 目标: 内核内独立 sync 协程，经单条 WS 长连把三流推到摄入 API，断网不阻塞内核。
- 交付物: `server/worldsim/sync/ws_client.py`、`server/tests/sync/test_ws_client.py`（fake WS server）；根 `.env.example` 追加七键（M6 sync env 唯一追加动作，R2 §A.6，00 §2 附表创建列归本任务）：`WSIM_REPLICA_PG_DSN`/`WSIM_INGEST_BIND`/`WSIM_SYNC_FRAME_DUMP`/`WSIM_DRILL_OUTAGE_S`/`WSIM_CLOUD_INGEST_HTTPS`，及开发期 loopback 值的 `WSIM_CLOUD_INGEST_URL`/`WSIM_INGEST_TOKEN`
- 实现要点:
  1. 连接：`WSIM_CLOUD_INGEST_URL`（04 §1.6；开发期 = `ws://127.0.0.1:<port>/v1/ingest/ws`，端口见"适配与偏差" D2）；upgrade 带 `Authorization: Bearer $WSIM_INGEST_TOKEN`（04 §9.1）；首帧 `hello{token,from_seq,kernel_ver}`（04 §1.3 帧样例）。
  2. 帧：`batch{from,to,events[]}` / `mem_batch{from,to,memories[]}` / `snapshot{sim_day,digest,state}`；每帧带 `schema_version`（04 §1.3 约束块）；事件攒批 **200 条或 2s**（04 §1.3）。
  3. ACK：`ack{upto,mem_upto,snap_upto}` 三流位点同帧回执，收到后 `UPDATE sync_state SET last_acked_seq=upto, last_acked_memory_id=mem_upto, last_acked_snapshot_day=snap_upto`（04 §1.3 流程）；ACK 语义 = 副本库**事务已提交**（摄入侧保证，T-SYN-05）。
  4. 断网态：发送超时 5s 标记 down，指数退避重连 1s→60s 上限、±20% 抖动（04 §1.3）；内核照常运行、事件主库自然积压（源方案 R6）；sync 崩溃后从 `sync_state` 续传。
  5. `nack{from,reason}` 处理：记 WARN 日志并从 `from` 位点重发（schema 类 nack 整批记 ERROR，04 §9.1）。
  6. `ping/pong` 心跳与 `hello_ack` 处理（04 §1.3 帧清单）。
- 验收标准:
  1. `cd server && uv run pytest tests/sync/test_ws_client.py::test_batching_200_or_2s`——fake server 断言：250 事件到达 → 首帧 200 条；不足 200 时 2s 窗口到点即发。
  2. `…::test_ack_updates_sync_state`——fake ack `upto/mem_upto/snap_upto` 后查 `sync_state` 三列同值。
  3. `…::test_send_timeout_marks_down`——fake server 挂起 6s，客户端 5s 标记 down 并进入退避。
  4. `…::test_reconnect_backoff`——断言重连间隔序列 ∈ 1s→60s 单调封顶且带抖动（mock 时钟）。
  5. `…::test_kernel_unblocked_when_down`——通道 down 时事件插入主库无等待（断言写路径不 await sync 发送）。
  6. `…::test_frame_schema`——出站帧逐字段对照 04 §1.3 帧样例（含 `snap_upto` 键存在于 ack 处理路径）。
  7. 集成冒烟：摄入 API（T-SYN-05 可后补联调）或 fake server 下一来一回，日志出现 `sync batch` INFO 行（04 §12.1 日志分级）。
- 实测回填: 无

- 里程碑 / 依赖: M6 ；T-SYN-03、T-SYN-05
