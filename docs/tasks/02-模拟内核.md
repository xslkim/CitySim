## 1. 范围

- 时间引擎：`clock.py`（sim/wall 换算、锚点持久化、暂停/恢复、追平）+ `speed_table.py`（变速表加载/校验/段切换）+ 凌晨 batch 段推进（含 batch 段回调注册表：world_agent 日历/审计钩子的唯一挂载点）。
- 裁决内核：`AdjudicationQueue` 优先级堆（世界事件 > 交互唤醒 > 时钟兜底，同 tick 同 agent 唤醒去重）、六步裁决管道与 `main.py` 主循环（LLM 接口与 deterministic mock provider 归 03 T-LLM-01/02 M1 段，本文消费注入）、19 动作校验器、对话整段落库、双人事件单源/目击投影/传播链落库、`state.needs_delta`/`relation.changed` 每 tick 合并聚合（≤2 条）、grade 自动打分初值（唯一实现归 T-ADJ-07）。
- LOD 调度：三层统一接口、时钟兜底排程、事件驱动即时升格（路径二）、secondary ≤16 硬上限 + LRU 挤出、基尼轮换（路径一迟滞）、升格追赶反思衔接、背景 NPC 校外驻留规则引擎（T-LOD-04，规则驱动零 LLM）。
- memory 子系统全量：store（投影写入）、retrieval（配额 N/M/K，见 04 §7.1）、reflect（双通道）、hygiene（膨胀治理）。
- REL：需求衰减、关系结算矩阵与自然回归（tension 非线性回归口径见 01 §3.2）、目标系统、意图冷却、邀约状态机（改期限 2 轮，见 01 §5.2）、话题系统（`config/topics.yaml` ≥60 条 + 话题冷却 + trigger_point 强制切入，见 01 §7）。
- 每模拟日 world_state 全量快照落盘（JSON gzip；白名单子集同源供 07 快照流/05 `world_state_snapshot`，备份恢复演练供 08 T-OPS-06）。
- `WSIM_REPLAY_MODE=replay`：重放 1 模拟日零 LLM 调用、状态一致对账（M1 出口）。

## 4. 任务表

### T-TIME-01 时钟锚点换算与暂停/恢复
- 里程碑 / 依赖: M1 ；无
- 设计依据: 04 §3.2（锚点/换算/暂停语义）、04 §2.2（tick=模拟 5 分钟）、00 §4 红线 10/11
- 目标: sim_time 换算、暂停/恢复语义落地，认知排程只读 sim_time
- 交付物: `server/worldsim/time_engine/clock.py`、`server/tests/time_engine/test_clock.py`
- 实现要点:
  - 锚点持久化在 `world_state`：`{anchor_sim, anchor_wall, ratio}`；continuous 段 `sim_time = anchor_sim + (wall_now − anchor_wall) × ratio`，跨段先把旧段积分进 `anchor_sim` 再换比（04 §3.2）。
  - `pause()` 写 `paused_at`，恢复时新锚点 `anchor_wall=now`、`anchor_sim` 不变——暂停期间模拟时间不流动。
  - tick = 模拟 5 分钟（04 §2.2）；提供 `now_sim()`、`tick_of(sim_time)` 供全内核使用；冷却/衰减/排程接口签名只接受 sim_time，禁止 wall_time 入排程（00 §4 红线 11）。
  - 进程重启从 `world_state` 锚点恢复时钟（04 §12.2 GPU 整机重启行）。
- 验收标准:
  1. `uv run pytest tests/time_engine/test_clock.py -q` 全绿：含换算精度、跨段积分、暂停不流动、重启恢复四个用例。
  2. 用例 `test_pause_freezes_sim_time`：pause 期间 `now_sim()` 差值为 0。
  3. SQL 验证锚点落库：`SELECT value FROM world_state WHERE key='clock.anchor';` 含 `anchor_sim/anchor_wall/ratio` 三键。
- 实测回填: 无

### T-TIME-03 故障追平与凌晨 batch 段推进
- 里程碑 / 依赖: M1 ；T-TIME-02
- 设计依据: 04 §3.2（追平两档策略）、04 §3.3（batch_advance 伪码/背景层日摘要单一时点）、06 §1.2（`time.paused/resumed/catchup.start/catchup.end/batch_advanced`）
- 目标: 致命依赖故障的暂停-追平闭环、batch 段粗粒度推进与 batch 段回调注册表
- 交付物: `server/worldsim/time_engine/clock.py`（追平段）、`server/worldsim/time_engine/batch.py`、`server/worldsim/time_engine/batch_hooks.py`（batch 段回调注册表）、`server/tests/time_engine/test_catchup.py`
- 实现要点:
  - 故障检测（主库不可用/全部 provider 熔断/磁盘满）→ `clock.pause()`：队列内已完成 LLM 调用正常落库，未发起的取消；每 30s 探测依赖（04 §3.2）。
  - 追平两档：停机 <2 真实小时 → `min(ratio×2, max_catchup_ratio)` 连跑；≥2 真实小时 → 落后部分按 batch 模式补齐，不追赶黄金档 1:1 对齐（上限值见 04 §3.1 constraints）。
  - `batch_advance` 按 04 §3.3 伪码：分 chunk 并发（chunk 大小见 04 §3.3）逐 agent 摘要快进；batch 段内明星/次要层不跑常规认知循环；背景层日摘要唯一时点即此段；编剧在该段的 A 级事件先插队结算再快进（M1 无编剧，留接口）。

  - 全程落事件：`time.paused`/`time.resumed`/`time.catchup.start`/`time.catchup.end`/`time.batch_advanced`，`trigger='system'`、`source='system'`，payload 字段逐字按 06 §1.2。

### T-ADJ-01 裁决优先级队列
- 里程碑 / 依赖: M1 ；无
- 设计依据: 04 §2.2（主循环伪码/tick 串行裁决语义/唤醒去重）、00 §4 红线 10
- 目标: `AdjudicationQueue` 优先级堆：世界事件 > 交互唤醒 > 时钟兜底，同 tick 同 agent 唤醒去重
- 交付物: `server/worldsim/adjudicator/queue.py`、`server/tests/adjudicator/test_queue.py`
- 实现要点:
  - 三类入队源优先级：世界事件 > 交互唤醒（`wakeup`）> 时钟兜底（`ClockTick`，04 §2.2 伪码）。
  - "事件唤醒 = 进队列、下一裁决点处理"：A 对 B 发起交互，B 不当场跑认知，收 wakeup 入队下一 tick 处理；同 tick 对同 agent 的多个唤醒去重合并。
  - 只有一个裁决协程消费队列（04 §2.2 写死）；队列本身不写状态。
  - tick 内 LLM 调用并发发出、结果按队列顺序串行回写的衔接点在本队列出口标注（供 T-ADJ-02 消费）。
- 验收标准:
  1. `uv run pytest tests/adjudicator/test_queue.py -q` 全绿：优先级顺序、同 tick 去重、跨 tick 不去重三用例。
  2. 用例 `test_wakeup_dedup_same_tick`：同 tick 对同一 agent 注入 3 个 wakeup，出队仅 1 个。
- 实测回填: 无

- 设计依据: 04 §6.3（单源/目击投影/涟漪落库约定）、04 §6.1 step5、06 §2（`source_event_seq`/`is_witness`/`caused_by`/`cites`/`fidelity`）、01 §4.1（失真链）

- 实现要点:
  - 同一场交互只生成一条 events 行，`actors=[A,B]`；双方各写 `kind='event'` 记忆投影（`source_event_seq` 相同、`content` 各自视角一句话）（04 §6.3）。
