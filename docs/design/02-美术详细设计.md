## 1. 分阶段策略与预算门禁

美术投入分三个阶段，每阶段有独立触发条件、预算上限与工期估算。**任何阶段未触发即不投入；已投入资产全部入版本库，渠道止损后仍可复用为技术资产。**

### 1.1 阶段 0：占位视觉（W1 起，与观察端同步）

**触发条件**：无（Web 观察端 W3 前置开发的第一天就使用）。
**定位**："不难看且信息清晰"——观察端是开发期**唯一的调试手段**，占位图必须能承载调试信息（谁在哪、在做什么、什么情绪），而不是随意涂鸦。

#### 1.1.1 占位视觉规范（强制）

| 元素 | 规范 |
|---|---|
| 地图 | SVG 格子图。公寓 6 层 × 4 房绘为 6 行 4 列矩形网格，每房间 96×64 viewBox 单位；公司按部门分区块；房间/区块内可再分 2×2 子格表示位置 |
| 角色 | 直径 20px 圆形色块 + 2 字符缩写名牌（如"林"），色块填充取 §4.3 的角色签名色（阶段 0 即启用签名色，**调试期就要能远观认人**） |
| 状态 | 头顶 emoji 占位：💬聊天 / 🍚吃饭 / 😴睡觉 / 💼工作 / 💢争执 / 🚶移动；情绪用色块外圈描边（正面 #3FB96B / 负面 #E05555 / 中性 #8A93A0） |
| 文字名牌 | 12px 思源黑体（Noto Sans SC），白字 80% 不透明黑底圆角标签，常驻显示前 2 字 |
| 连线 | 对话中双方之间画虚线（#8A93A0，dash 4 4），对话结束消失 |
| 禁止项 | 不允许使用默认黑方块/无标签纯色点；不允许未经签名色表取色 |

**预算上限**：¥100（仅允许购买字体授权或图标库，原则上全用免费资源）。
**工期估算**：0.5 人日，与 03-客户端文档的地图组件同批交付。
**验收**：观察端五张核心视图（地图/角色详情/事件时间轴/涟漪追踪/关系演化）全部可用人眼 3 秒内定位任意指定角色。

### 1.2 阶段 1：像素美术（门禁③通过后）

**触发条件**：门禁③通过 = 每周 3 条 × 4 周切片发布后，完播率与涨粉趋势达到 W0 市场调研校准的阈值（阈值数值在 W0 写死，本文不预设）。
**投入顺序**（与内容价值对齐，而非与资产面积对齐）：

1. **明星层 8 人角色 sprite**（行走 + 6 组行为动画）——镜头 80% 时间在他们身上；
2. **公寓主场景 tileset**（6 层 × 4 房 + 公共区）——黄金档 18:00~24:00 的主舞台；
3. **公司场景 tileset**（各部门 + 茶水间/会议室）；
4. 次要层 ~12 人 sprite（动画可裁剪为 idle/walk/chat/eat 四组）；
5. 背景层 ~20 人 sprite（idle/walk 两组即可，远景为主）；
6. 外部场所（餐厅等）与道具特效。

**预算上限**：¥2,000。拆分参考：AI 工具订阅/素材授权 ≤¥600；外包修图或急单补画 ≤¥1,400。超上限即停，剩余资产留到观察端订阅收入回血后再补。
**工期估算**：AI 辅助管线（§8.2）下 3~4 周（单人兼职），其中角色 sprite 2 周、场景 1.5 周、特效道具 0.5 周。
**验收**：§9.2 checklist 全过 + 用新资产重剪 1 条历史切片对比盲测（2~3 个不了解项目的人，同门禁①外部评判口径），多数认为"明显更好看"。

### 1.3 阶段 2：VN 立绘与切片包装（阶段 1 完成后）

**触发条件**：阶段 1 验收通过，且切片数据在换上像素美术后**没有回落**（防止美术风格本身劝退观众）。
**内容**：明星层 8 人优先的 VN 立绘（§5）；切片包装模板全套（§6）；观察端 UI 换肤应用 §7 token（阶段 0 的 token 已就位，此处仅替换占位控件样式）。
**预算上限**：¥1,000（立绘以 AI 生成 + 人工修图为主，成本主要是工时与工具）。
**工期估算**：2 周（明星 8 人立绘约 1.5 周，包装模板 0.5 周；其余 32 人立绘列为"有条件再做"，不阻塞任何东西）。

### 1.4 三阶段总表

| 阶段 | 触发 | 预算上限 | 工期 | 失败处置 |
|---|---|---|---|---|
| 0 占位 | W1 自动开始 | ¥100 | 0.5 人日 | 不适用（必做） |
| 1 像素 | 门禁③通过 | ¥2,000 | 3~4 周 | 门禁③不过 → 不投，触发渠道止损评估 |
| 2 立绘+包装 | 阶段1验收 + 数据不回落 | ¥1,000 | 2 周 | 数据回落 → 回滚观察端皮肤，立绘归档 |

> 决策理由：预算合计 ¥3,100，占 ¥8,000 总止损的 39%——美术是"放大器"而非"发动机"，源方案把 LLM 单价（¥/模拟日）定为唯一成本口径，美术预算必须给 LLM 迭代轮数留出主体空间。

## 2. 视觉风格指南

### 2.1 整体基调

**都市日常 + 轻喜剧**。参照系：星露谷物语式的暖色像素小镇（生活感）× 日剧《下辈子我再好好过》式的都市单身公寓群像（成人轻喜剧）。明确规避：奇幻、赛博朋克、萌系 Q 版过度——本项目角色是 24 名都市白领 + 16 名公司同事，视觉要服务"这是一个可信的小社会"。

### 2.2 参考风格锚点

| 参照 | 借鉴 | 不借鉴 |
|---|---|---|
| Stardew Valley | 32px 网格、暖色调、俯视 3/4 视角 | 乡村题材 |
| AI Town（a16z） | 头顶气泡、常驻名牌的信息密度 | 其美术粗糙度 |
| 开罗游戏 | 小比例角色的行为辨识度 | 过度 Q 版头身比（本项目用 3.5~4 头身） |
| 日剧群像海报 | VN 立绘的都市写实比例 | 真人摄影 |

### 2.3 统一调色板（HEX 色值表）

**全局基础色**（所有场景共用，保证跨场景统一感）：

| 角色 | 色名 | HEX | 用途 |

| 主木色 | 胡桃木 | `#A9714B` | 地板、家具 |
| 主强调 | 砖橙 | `#E07856` | 重要交互物、海报点缀 |
| 辅色 1 | 鼠尾草绿 | `#7FA98C` | 植物、床品 |
| 辅色 2 | 雾蓝 | `#5B7B9A` | 金属、电子设备 |
| 深色 | 墨青 | `#2E3A45` | 轮廓线、阴影（像素描边统一用此色，不用纯黑） |

**场景变体**：

## 3. 像素资产规格（阶段 1）

### 3.1 Tile 尺寸与网格

| 项 | 规格 | 理由 |
|---|---|---|
| 基础 tile | **32×32 px** | 行业最通用，素材/工具生态最好；32px 在 1080p 缩放下仍可辨认 |
| 视角 | 俯视 3/4（顶面:侧面 ≈ 2:1） | 星露谷同款，家具顶面与立面都可见，生活感强 |
| 场景网格 | 公寓单间 10×8 tile（320×256 px）；走廊宽 2 tile；公司部门区 16×12 tile | 单间容纳床+桌+柜+2 人对话不挤 |
| 渲染缩放 | 逻辑 1×，显示 2×~3× 整数缩放（最近邻，禁双线性） | 整数缩放保证像素不糊 |
| 碰撞格 | 1 tile = 1 移动格，与内核地点节点图对齐：房间内子格 = 节点内位置 | 美术网格不反向约束内核，仅作呈现 |

### 3.2 角色 sprite 规格

| 项 | 规格 |
|---|---|
| 尺寸 | **32×48 px**（宽 1 tile，高 1.5 tile），3.5~4 头身 |
| 方向 | 4 方向：下/左/右/上（左=右水平镜像的，**仍各存一份**，避免配饰镜像穿帮） |
| 基准点 | 脚底中心 (16, 47) |
| 轮廓 | 统一 1px 墨青 `#2E3A45` 描边 |
| 调色约束 | 每角色 sprite 总色数 ≤24（不含描边色），签名色占视觉面积 ≥15%（远观辨认用，§4） |

#### 动画帧表（帧率统一 8 fps，pingpong=来回播放）

| 动画 | 帧数/方向 | 播放 | 触发（动作枚举映射，源方案 §4.4） |
|---|---|---|---|
| idle | 2 | pingpong | 默认站立（呼吸浮动） |
| walk | 4 | loop | `move` |
| eat | 4 | loop | `eat`（坐持餐具 2 帧 + 咀嚼 2 帧） |
| chat | 2 | pingpong | `chat`/`gossip`（面向对方倾身 + 手势） |
| sleep | 2 | 4 fps | `rest`（躺卧呼吸，zZ 特效另算） |
| work | 4 | loop | `work`（坐姿打字 2 帧 + 看屏幕 2 帧） |
| argue | 4 | loop | `argue`（激动手势 2 帧 + 跺脚 2 帧） |
| phone | 2 | pingpong | `trade_stock`/`invite` 发消息（持手机） |
| refuse | 2 | 单发 | `refuse`（摆手/转身） |
| sit | 1 | 静态 | 公共区/餐厅坐姿 |

**规格决策**：明星层 8 人全 10 组动画（4 方向 × walk + 其余单方向），约 54 帧/人；次要层 12 人给 idle/walk/chat/eat 4 组，约 20 帧/人；背景层 20 人 idle/walk 2 组，约 10 帧/人。总帧数 ≈ 8×54 + 12×20 + 20×10 = **872 帧**，AI 辅助管线下可控（§8.2）。
> 理由：动画预算按 LOD 分层复用——明星层承担镜头，帧数全；背景层远景为主，两组动画足够，与认知成本分层同构。

## 4. 角色视觉符号系统

### 4.1 人设卡 → 资产的映射规则

人设卡的**标志性视觉符号**字段（源方案 §4.10 预留，"后期美术用"）在阶段 1 启动时按下表落为资产。**该字段在人设生成流水线（LLM 批量生成 → 规则校验）阶段就按本表约束生成，不得自由发挥。**

| 符号字段 | 取值域 | 资产映射 |
|---|---|---|
| `hair` 发型 | 8 款男 + 8 款女 | sprite 发型层 + 立绘发型 |
| `outfit` 服装类型 | 6 类（西装/商务休闲/卫衣/连衣裙/工装/运动） | sprite 身体层 |
| `signature_color` 签名色 | §4.3 矩阵唯一分配 | 服装主色 + 名牌底条 + 字幕色块（§6.2） |
| `accessory` 配饰（≤1） | 眼镜/发带/耳环/围巾/耳机/工牌 | sprite 叠加层，远观可辨的第二特征 |
| `build` 体型 | 3 档（瘦/标准/壮） | sprite 肩宽 ±2px 变体 |

### 4.2 40 人差异化规范

**三维度组合矩阵**：发型(16) × 服装(6) × 签名色(16) = 1536 种组合空间，40 人分配规则：

1. **签名色全局唯一**（16 色池，每人 1 色，同名角色不撞色）——这是远观辨认的第一信号；
2. 同部门同事**服装类型相邻但不相同**（公司场景同框可区分）；
3. 同楼层邻居**发型不重复**（公寓走廊同框可区分）；
4. 明星层 8 人**强制配饰**（镜头主角必须有第二特征）；
5. 校验自动化：人设 YAML 入库时跑规则脚本，违反任一条即打回（并入 §4.10 的规则校验环节）。

## 5. VN 立绘规格（阶段 2）

### 5.1 基础规格

| 项 | 规格 | 理由 |
|---|---|---|
| 画布 | **1600×2400 px**（2:3），角色实际占高 ≥2000px | 覆盖 1080p 竖屏切片与 16:9 横屏裁切双需求 |
| 输出 | PNG 透明底 + 分层 PSD 源文件 | 演出层需要独立换表情 |
| 分层 | **底（身体+服装）/ 头部 / 表情层（眉眼+嘴）/ 姿势层（手臂）** 4 层结构 | 表情差分只重画表情层，成本降一个量级 |
| 风格 | 都市写实偏日剧插画，7 头身，半厚涂 | 与像素小人同一角色的"成人版"，签名色与发型必须严格对应 |
| 色约束 | 立绘主色 = 角色签名色的高饱和版（§4.3 色值直接用于服装主色） | 观众从像素小人切换到立绘时的"认出率"靠签名色 |

### 5.2 表情差分（基础 ≥8 种）

| # | 表情 | 典型触发场景 |
|---|---|---|
| 1 | 平静（默认） | 旁白、日常 |
| 2 | 微笑 | 邀约成功、和解 |
| 3 | 大笑 | 八卦、庆祝 |
| 4 | 害羞/脸红 | 暗恋线（40 人关系拓扑必有暗恋链） |
| 5 | 生气 | `argue` |
| 6 | 难过 | 被拒、挫败 |
| 7 | 惊讶 | 突发事件、股价暴跌 |
| 8 | 严肃/职场脸 | 绩效谈话、经理场景 |
| 9+ | 可选：流汗尴尬、得意、疲惫 | 按切片高频场景追加 |

规格：每表情 = 眉眼层 1 张 + 嘴型层 1 张（可混拼出组合表情）；脸红/汗滴为叠加贴片。**明星层 8 人：8 表情 × 2 姿势（立/坐）起步；其余角色只做平静/微笑/生气/难过 4 表情 × 1 姿势，排期不保证。**

### 5.3 构图与裁切规范

| 项 | 规范 |
|---|---|
| 站位 | 面向镜头 3/4 侧身，视线朝画面内侧（对话场景左右对摆） |
| 横屏裁切 | 16:9 取胸部以上（裁切线 y=300~1500），左右各留 ≥10% 安全区 |
| 竖屏裁切 | 9:16 取腰部以上居中，头顶留 5% |
| 对话双人位 | 左位角色锚点 x=25%，右位 x=75%，立绘宽 ≤45% 画面宽 |
| 禁止 | 立绘超出下边缘（裁腿会破坏比例感）；非说话方降亮度 15% 的"演出暗角"由呈现层实现，不画进资产 |

> 决策理由：**明星层 8 人优先原则**直接来自源方案——切片主角就是明星层，立绘投入与认知成本投入同向；给背景层画立绘是把预算花在不上镜头的人身上，明确不做。

## 6. 切片视觉包装模板（阶段 2，占位版可提前）

> 切片是 W4 起的首发内容形态（每周 3 条 × 3~8 分钟）。**包装模板在阶段 0 就可以用纯图形做第一版**（不依赖像素/立绘资产），阶段 2 再换皮——这样门禁③的 4 周数据不被"零包装"拖累，又不违反"门禁③通过才投美术"。

### 6.1 片头片尾

| 项 | 时长 | 信息要素 |
|---|---|---|
| 片头 | **3~5 秒**（硬上限 5s，短视频前 3 秒定生死） | 系列 logo + 本集标题（一句话钩子，如"一句话如何在三天内毁掉两段关系"）+ 集数 |
| 片尾 | 8~10 秒 | 下期预告（1 个悬念事件截图 + 1 句旁白）+ 关注引导 + "本故事由 AI 社会模拟生成"标识（合规） |

### 6.2 字幕样式

| 项 | 规格 |
|---|---|
| 说话人色块 | 字幕条左侧 8px 宽竖条，颜色 = 角色签名色（§4.3），色块内白字角色名 2~3 字 |
| 字体字号 | 思源黑体 Bold；1080p 下 42px，字距 0，描边 3px `#000000` 80% 透明 |
| 位置安全区 | 底部安全区：竖屏下缘留 220px（抖音 UI 遮挡区），横屏留 120px；字幕基线固定在安全区上缘 |
| 单句上限 | 20 字/行，≤2 行；**与内核一致：对话整段生成、逐句播放，每句 2~4 秒**（源方案 §3.4），字幕时长即播放时长 |
| 旁白 | 无签名色块， italic 灰色 `#C9D2DA`，顶部居中（与角色台词视觉隔离） |

### 6.3 信息卡模板（布局规格，1080×1920 竖屏基准）

| 卡片 | 布局 | 内容字段 |
|---|---|---|
| 关系变化卡 | 上半：两人头像（阶段 0 用色块圆，阶段 2 用立绘）+ 之间连线；下半：affinity 变化箭头 + 一句话摘要 | `A→B 亲密度 32→68 ↑`，关系标签（暗恋/对头/老乡），源事件 1 句 |
| 股价卡 | 全宽折线图（最近 7 模拟日）+ 大字涨跌百分比 | 股票名、现价、涨跌幅（红涨绿跌，本地口径）、受影响角色持仓 |
| 旁白卡 | 纯色底 `#1F2630` + 居中文字 ≤40 字 | 时间跳转（"三天后"）、背景补述、编剧注释 |
| 需求/状态卡 | 角色头像 + 6 需求条（饥饿/精力/情绪/社交/成就/财富，0~100） | 用于"他为什么会爆发"的动机解释，字段直接取世界状态 |

### 6.4 3~8 分钟结构模板（时长分配）

| 段落 | 时长占比 | 内容 |
|---|---|---|
| 开场钩子 | 0:00~0:15（≤5%） | 本集最高潮的 1 句话/1 帧前置（倒叙开场），+ 片头 |
| 发展 | 60% | 2~3 条事件线推进，每条线 ≥1 场完整对话（6~8 轮），穿插信息卡补动机 |
| 高潮 | 25% | A 级事件完整呈现（每模拟日 ≥1 个，源方案 §4.8 保证供给） |
| 结尾悬念 | 10% | 1 个未解决的张力点（邀约未回复/争执未收场），接片尾预告 |

> 依据：源方案叙事节奏目标"每模拟日 ≥1 个可剪辑的 A 级事件"，一集 3~8 分钟约消耗 1~2 模拟日的素材——每周 3 条约消耗 3~6 模拟日，低于每真实周 ≥8 模拟日的产出下限（§4.1），素材供给有余量。

### 6.5 封面图模板（三平台）

| 平台 | 尺寸 | 模板要素 |
|---|---|---|
| 抖音 | **1080×1920**（9:16） | 上半大字标题（≤10 字，站酷高端黑 120px）+ 冲突双方立绘对切，底部系列条 |
| B站 | **1920×1080**（16:9，实际显示 1146×717，按 16:10 安全区排版） | 左 60% 标题+看点标签，右 40% 主角立绘；关键文字避开右下时长角标区 |

## 7. Web 观察端 UI 视觉规范（阶段 0 生效，与 03-客户端衔接）

> 本节是**视觉 token 的唯一定义处**：03-客户端文档实现时，色值/字号/间距一律以本节为准，不得在客户端代码里另起炉灶。阶段 0 用 token + 占位控件，阶段 2 换皮肤时 token 不变。

### 7.1 配色（深色优先）

理由：观察端是开发期唯一调试手段，开发者长时盯屏；深色底上签名色（§4.3 为浅底优化）整体提亮 10% 使用。

| token | HEX | 用途 |
|---|---|---|
| `bg-0` | `#0E1116` | 页面底色 |
| `bg-1` | `#161B22` | 面板/卡片底 |
| `bg-2` | `#1F2630` | 悬浮层、选中态 |
| `border` | `#2D333D` | 分割线、卡片描边 |
| `text-0` | `#E6E9EF` | 主文字 |
| `text-1` | `#9AA4B2` | 次要文字、时间戳 |
| `accent` | `#4FC3F7` | 选中角色/当前跟拍 |
| `positive` | `#3FB96B` | affinity 正值、收益 |
| `negative` | `#E05555` | tension 高、亏损、干预标记 |
| `warn` | `#F5B14C` | 告警（熔断接近、基尼系数预警） |
| `director` | `#9B6BC9` | 编剧干预事件专属色（`trigger=director`，全 UI 统一） |

### 7.2 地图视觉层级（z-order 自下而上）

1. 场景底图（阶段 0 SVG 格子 / 阶段 1 像素 tileset）；
2. 房间高亮层（hover/选中房间，8% `accent` 填充）；
3. 对话连线层（虚线）；
4. 角色层（色块圆/sprite，跟拍角色带 2px `accent` 外圈）；
5. 情绪符号与气泡层；
6. 名牌层（始终不被遮挡）。

### 7.3 面板/卡片样式

| token | 值 |
|---|---|
| 卡片圆角 | 8px |
| 卡片内边距 | 12px |
| 面板间距 | 8px（8px 网格系统，所有间距取 8 的倍数） |
| 字号 | 标题 14px / 正文 13px / 辅助 12px / 时间戳 11px |
| 需求条 | 高 6px 圆角 3px，填充色随值渐变（≤25 用 `negative`） |
| 事件条目 | 左 4px 色条标识 trigger 类型（autonomous=`text-1` / world=`accent` / director=`director` / gift/vote=预留），`干预率 <15%` KPI 的 UI 呈现就靠这个色条密度 |

### 7.4 涟漪追踪可视化语言（独有功能）

| 视觉元素 | 规范 |
|---|---|
| 源事件节点 | 直径 24px 实心圆，`accent` 色，带脉冲动画（1.5s 循环） |
| 记忆投影节点 | 直径 12px 圆，颜色 = 接收者签名色，半透明 70% |
| 传播边 | 有向箭头，**第 1 手传播实线、第 2 手起虚线且逐手递减透明度**（n 手 = 100%−20%×n） |
| 失真标注 | 边中点挂 11px 标签，显示内容失真度（如"金额 ¥500→¥5000"），失真 >30% 的边整体变 `warn` 色 |
| 引发后续事件 | 菱形节点 `#E8A33D`，点击跳转事件时间轴 |
| 关系边改变 | 终点处显示关系变化卡迷你版（§6.3 同源字段） |
| 布局 | 力导向 + 时间从左向右分层（传播代数=列），禁止纯力导向乱跑 |

### 7.5 关系图演化动画规范

| 项 | 规范 |
|---|---|
| 节点 | 角色签名色圆，明星层带白描边 |
| 边宽 | ∝ \|affinity\|（1~5px 线性映射） |
| 边色 | affinity>0 用 `positive`，<0 用 `negative`；tension>50 叠加 `warn` 色 1px 内芯 |
| 时间轴动画 | 拖动时间轴时边宽/边色以 300ms 缓动过渡；节点位置锁死不漂移（演化期间布局冻结，**只变边不变位**——观众要看的是结构变化，位置漂移会制造假变化） |
| 出场/退场 | 新关系边从 0 宽生长 500ms；断裂边闪烁 2 次后消失 |

## 8. 制作管线与工具链

### 8.1 工具与工作流

| 环节 | 工具 | 说明 |
|---|---|---|
| 像素绘制 | Aseprite（买断 ≈¥70，计入阶段 1 预算） | 动画帧、tileset；调色板文件 `.gpl` 随资产入库 |

| 切片剪辑 | 剪映专业版（免费） | 字幕模板、封面模板以剪映工程文件入库 |

### 8.2 AI 辅助生成 + 人工修图的比例与质检点

| 资产类型 | AI 生成占比 | 人工修图 | 质检点（不过即返工） |
|---|---|---|---|
| 角色 sprite | ~70%（AI 出初稿+风格统一 prompt 模板） | 逐帧修动画连贯性、签名色校准 | ①调色板合规（≤24 色）②签名色面积 ≥15% ③4 方向一致性 |
| tileset | ~60% | 接缝、透视统一 | ①tile 无缝拼接测试 ②3/4 视角一致性 ③描边色统一 `#2E3A45` |
| VN 立绘 | ~85% | 表情差分、手（AI 重灾区）、签名色 | ①与 sprite 的发型/签名色对照表逐项核对 ②分层完整性 ③裁切安全区 |
| 切片模板 | 0%（纯排版，人工） | — | 按 §6 规格逐项对 |

**原则**：AI 只做初稿，**所有入库资产必须过人工质检点**；质检脚本（色数、尺寸、命名）自动化，审美项人工。

### 8.3 资产命名规范

```

├── palette/worldsim.gpl                # 统一调色板
├── stage0-placeholder/                 # 占位 SVG（阶段 0，入库供回溯）

│   │   ├── spr_{char_id}_idle.png
│   │   ├── spr_{char_id}_walk_{down,left,right,up}.png
│   │   └── spr_{char_id}_{eat,chat,sleep,work,argue,phone,refuse,sit}.png
│   ├── tileset/
│   │   ├── apt_{room,corridor,lobby,rooftop,laundry}_v{n}.png
│   │   ├── office_{desk,manager,pantry,meeting,front}_v{n}.png
│   │   └── ext_{restaurant,street,store}_v{n}.png
│   └── fx/{bubble,emotion,nameplate,spark}.png
├── vn/
│   └── {char_id}/vn_{char_id}_base.psd
│       vn_{char_id}_expr_{calm,smile,laugh,shy,angry,sad,surprised,serious}.png
└── packaging/
    ├── template_{intro,outro,subtitle,infocard}_v{n}.mp4|png
    └── cover_{douyin,bili,xhs}_v{n}.png
```

文件名模式：`{类型}_{主体}_{变体}_v{版本}.png`，全小写下划线；版本号只在**破坏性修改**（尺寸/配色变更）时递增，微调覆盖原文件（git 历史即版本）。

### 8.4 版本管理与游戏内引用

- 全部 PNG/SVG/工程文件直接入 git（像素资产体积小）；PSD 源文件 >10MB 的用 git-lfs，或存 `assets/_src/` 并在 `.gitattributes` 标记。
- 游戏内引用**只按 `char_id` + 变体键查表**（`manifest.json`：资产注册表，记录 char_id→文件路径→帧表元数据），代码不硬编码路径；观察端与切片素材渲染共用同一 manifest。
- 占位资产与正式资产同键不同文件：阶段切换 = manifest 指向从 `stage0-placeholder/` 改到 `pixel/`，**客户端零改动**。
> 决策理由：manifest 间接层让阶段 0→1 的切换成为纯数据变更，符合"门禁③不过就不投、随时可回滚"的止损逻辑。

- [ ] 总支出 ≤¥2,000，工时 ≤4 周

### 9.3 阶段 2（VN 立绘 + 包装）

- [ ] 明星 8 人立绘：分层 PSD 完整（底/头/表情/姿势），≥8 表情 × 2 姿势
- [ ] 立绘与 sprite 的发型/签名色逐项核对通过
- [ ] 16:9 与 9:16 裁切安全区验证（直接套 §5.3 裁切线截图检查）
- [ ] 包装模板全套：片头 ≤5s、片尾含下期预告与 AI 生成标识、字幕签名色块、4 类信息卡
- [ ] 三平台封面各 1 模板，实测单张制作 ≤15 分钟
- [ ] 观察端换肤后 §7 token 无回归

### 9.4 常见返工原因（前置预防）

| 返工原因 | 预防 |
|---|---|
| AI 生成 sprite 4 方向不一致（左脸痣跑到右脸） | 配饰只允许对称款或固定侧；质检点③逐项对 |
| 签名色在夜晚场景变体下不可辨认 | 阶段 1 中期做一次"夜间大堂全员同框"截图评审 |
| 立绘与像素小人"认不出是同一个人" | 对照表硬性核对发型/签名色/配饰三项 |
| 字幕被抖音 UI 遮挡 | §6.2 安全区数值写进剪映模板参考线，不凭感觉 |
| tileset 风格漂移（多批次 AI 生成） | 统一 prompt 模板 + 调色板锁死 + 每批先做 3 tile 样张确认 |
| 资产路径硬编码导致换皮改代码 | manifest 间接层（§8.4），代码评审拦截 |
