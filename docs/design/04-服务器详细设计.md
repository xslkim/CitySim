## 1. 部署拓扑（核心章节）

### 1.1 两台机器的分工

```
本机（NAT 后，无任何入站端口）
├── worldsim-kernel   Python 3.12 asyncio 单进程（内核；内置 llm_gateway/sync_client/audit 协程）
├── worldsim-vllm-safety   Qwen3-4B 内容安全初筛（常驻，OpenAI 兼容端点 :8101）
├── worldsim-vllm-fallback Qwen3-8B 次要层兜底（进程常驻、默认 sleep，:8102）
├── worldsim-embed         bge-m3 embedding（常驻，:8103）
└── PostgreSQL 16 + pgvector 0.8（主库，append-only 事件表）
        │ 仅出站：WSS（事件推送）+ HTTPS（批量回退/备份/心跳）
云端（公网 IP）
├── worldsim-ingest  FastAPI 摄入 API（WSS + HTTPS 双通道）
├── PostgreSQL 16 副本库（独立实例，由摄入写入，非流复制）
├── worldsim-web + slice-pipeline  Web 观察端（静态页+WS订阅+呈现队列 worker）与切片素材/发布管线
```

分工原则（与源方案 §3.1 一致，阶段 1 单体）：

- **本机是唯一事实源**：事件先生效于本机主库，再异步复制到云端；云端永不回写，只做只读投影与呈现（摄入 → 副本库 → Web WS 订阅，即源方案 §6 的"事件库只读投影 + WebSocket 推送"）。
- **LLM 网关是内核进程内模块**而非独立服务：阶段 1 只有内核一个调用方，独立成服务只增加 IPC 与运维面；接口（§8）按服务边界设计，阶段 2 可原样拆出。
- **本地模型全部走 vLLM 的 OpenAI 兼容 HTTP 端点**，内核只依赖 `openai` SDK 协议，本地/云端模型在路由表里是同构的 `provider`。

### 1.2 推理运行时选型：vLLM（而非 Ollama）

vLLM 0.10+：PagedAttention + 连续批处理（安全初筛与 embedding 是高频负载，需要吞吐）；原生支持 bge-m3 pooling，与对话模型同一运行时；`--enable-sleep-mode` 可 API 控制睡/醒，正好实现"8B 兜底按需加载"而不用起停进程。Ollama 并发弱、卸载粒度粗，仅作 W1 实测出基准的工具，不进生产。**决策**：全部本地模型用 vLLM，`--gpu-memory-utilization` 显式控显存。

### 1.3 出站同步通道协议（本机 → 云端）

**决策：用主库 `events.seq`（单调递增 IDENTITY）作为全局复制位点，outbox 即事件表本身**，不另建缓冲表/文件队列。理由：append-only 事件表天然是 WAL 语义的 outbox，`sync_state.last_acked_seq` 一行记录进度即可，少一套一致性风险。通道：单条 WSS 长连（`wss://cloud/v1/ingest/ws`），断线回退 HTTPS 批量接口（§9）。帧格式（JSON 一行一帧）：

```json
{"frame":"hello","token":"<ingest_token>","from_seq":12345,"kernel_ver":"0.4.0"}   // 本机→云端
{"frame":"batch","from":12345,"to":12404,"events":[ ... 原样 events 行 ... ]}
{"frame":"ack","upto":12404}          // 云端→本机：副本库已事务提交到 upto
{"frame":"nack","from":12400,"reason":"schema"}   // 另有 hello_ack / ping / pong
```

完整流程：

```
正常态：事件事务提交后 → sync 协程攒批（200 条或 2s）→ 发 batch → 收 ack
        → UPDATE sync_state SET last_acked_seq=upto
断网态：发送超时 5s → 通道标记 down，指数退避重连（1s→…→60s 上限，±20% 抖动）；
        内核照常运行（世界不等人），事件在主库自然积压，无额外动作
恢复态：重连 → hello 携 last_acked → 云端 hello_ack 回 max_seq
        → max_seq < last_acked 说明副本缺数据，按 max_seq 重发（幂等兜底）
        → 追平模式：每批 500 条、窗口 8 批流水化，追平后回正常态；
          追平期间观察端照常展示（按 seq 有序可见，只是延迟大）
```

约束：**顺序与幂等**——严格按 seq 升序推，云端 `ON CONFLICT (seq) DO NOTHING`，重复批安全；**ACK 语义**=副本库已事务提交，不是"收到"；**断网不影响内核**（源方案 R6），sync 是独立协程，崩溃后从 `sync_state` 续传；每帧带 `schema_version`，云端拒收未知版本，防 W1 冻结后字段漂移静默丢数据。

### 2.2 asyncio 主循环伪代码与 tick 串行裁决语义（写死）

```python
async def main():
    db = await create_pool(WSIM_PG_DSN)
    clock = TimeEngine(db, load(WSIM_SPEED_TABLE))
    queue = AdjudicationQueue()          # 优先级堆：世界事件 > 交互唤醒 > 时钟兜底
    gw    = LLMGateway(db, load(WSIM_MODELS_CONFIG))
    async with asyncio.TaskGroup() as tg:
        tg.create_task(clock.run(on_tick=lambda t: queue.put(ClockTick(t))))
        tg.create_task(adjudication_loop(db, queue, gw))   # 唯一写协程，串行裁决
        tg.create_task(sync.run()); tg.create_task(audit.daily_loop())
        tg.create_task(memory.hygiene_loop()); tg.create_task(scheduler.rotation_loop())
```

tick 串行裁决语义（写死）：

- **只有一个裁决协程消费队列**——所有状态写（位置/余额/关系/记忆/事件）都发生在这里，天然无并发写冲突（源方案 §4.9"后到者收到已被占用事实"）。
- **tick = 模拟 5 分钟**（内部裁决粒度）：明星层"每模拟 15 分钟兜底"= 每 3 tick 排程一次；次要层"每模拟 2 小时"= 每 24 tick 一次。
- **"事件唤醒"= 进队列、下一个裁决点处理**（源方案 §3.4）：A 对 B 发起对话，B 不当场跑认知，而是收 `wakeup` 入队，下一 tick 裁决点处理；同 tick 对同 agent 的多个唤醒去重合并。
- tick 内 LLM 调用**并发发出**，结果写回**按队列顺序串行落库**——"LLM 并发、落库串行"，吞吐与一致性兼得。
- 单 tick 预算：黄金档 1:1 时 tick=真实 5 分钟，明星层 8 人并发认知 + 对话生成，p95 须 < 预算 60%（W2 实测校准）。

## 3. 时间引擎

### 3.1 时段变速表：配置 schema 与切换逻辑

`config/speed_table.yaml`：

```yaml
segments:                    # 按真实本地时间覆盖全天 24h，不允许空洞
  - { start: "00:30", end: "08:00", mode: batch, sim_hours_per_run: 8 }   # 凌晨批量粗粒度
  - { start: "08:00", end: "18:00", mode: continuous, ratio: 3.0 }        # 白天 2~4× 区间内取 3
  - { start: "18:00", end: "24:00", mode: continuous, ratio: 1.0 }        # 黄金档 ≈1:1
  - { start: "00:00", end: "00:30", mode: continuous, ratio: 2.0 }        # 深夜缓冲
constraints:
  min_sim_days_per_real_week: 8        # 源方案 §4.1 底线，加载时校验
  max_catchup_ratio: 6.0               # 追平模式上限
```

按上表：每真实日推进 `8 + 10×3 + 6×1 + 0.5×2 = 45 模拟小时 ≈ 1.9 模拟日`，每真实周 ≈13 模拟日 ≥8 ✔；月成本 = ¥/模拟日 × ~57 模拟日/月（排期选择，源方案 §5.2）。切换：真实时刻跨段边界触发 `SegmentSwitch`；continuous 段间仅改压缩比；进入 batch 段发起凌晨批量推进（§3.3）并暂停 tick 排程，离开后恢复。**压缩比只调观看节奏，不调世界密度**（v3.3 语义）：所有认知排程读 sim_time，切比不改变一个模拟日内任何 agent 被排程的次数。

### 3.2 模拟时间换算、故障暂停与恢复追平

锚点持久化在 `world_state`：`{anchor_sim, anchor_wall, ratio}`。continuous 段 `sim_time = anchor_sim + (wall_now − anchor_wall) × ratio`，跨段先把旧段积分进 `anchor_sim` 再换比。暂停写 `paused_at`，恢复时新锚点 `anchor_wall=now`、`anchor_sim` 不变——**暂停期间模拟时间不流动**（源方案 §5.2）。所有 DB 行同时存 `sim_time`（业务语义）与 `wall_time`（运维/计费语义）；认知频率、冷却、衰减一律只用 `sim_time`。

故障暂停与恢复追平流程：

```
检测致命依赖故障（主库不可用 / 全部 LLM provider 熔断 / 磁盘满）：
1. clock.pause()：写 paused_at，停止排程新认知；队列内已完成 LLM 调用正常落库，未发起的取消
2. 每 30s 探测依赖；恢复后追平：
   - 停机 <2 真实小时：min(ratio×2, 6×) 连跑直到回到计划 sim 位置
   - 停机 ≥2 真实小时：落后部分按 batch 模式补齐（逐 agent 摘要快进 §3.3），
     不追赶黄金档 1:1 对齐——宁可世界落后半天，不用 6× 稀释观看体验
3. 全程写事件 time.paused / time.resumed / time.catchup_{start,end}（trigger=system）
```

理由：认知调用量 ∝ 模拟时间，6× 连跑会把实时成本脉冲打穿熔断线；batch 补齐成本 ≈ 背景层日摘要，便宜一个量级。

### 3.3 凌晨批量粗粒度推进实现

```python
async def batch_advance(agents, sim_hours=8):        # 进入 batch 段（真实 00:30）
    await clock.enter_batch_mode(sim_hours)
    for chunk in chunked(agents, 10):                # 40 人分 4 批，并发 10
        await gather(*[background_summarize(a, sim_hours) for a in chunk])
        # 每人一次调用：总结 8h → 摘要记忆 + 需求/情绪状态变更
    await world_agent.run_batch_calendar()           # 跨日日历事件（如 8:00 打卡）一次性结算
    emit("time.batch_advanced", payload={"sim_hours": sim_hours}, trigger="system")
    await clock.exit_batch_mode()
```

batch 段内明星/次要层**不跑常规认知循环**（正是源方案"背景层日摘要模式扩展到全员"）；编剧若在该段排了 A 级事件，在 batch 前插队认知循环结算掉再快进。

## 4. LOD 调度器

### 4.1 三层统一接口

**认知模式是 `agents.cognition_tier` 字段**（`'star'|'secondary'|'background'`，源方案 §9 W1~W2 即按此预留接口），调度器按字段分发到同一接口的三个实现：

```python
class CognitiveUnit(Protocol):
    agent_id: int
    def next_due(self, sim_now) -> SimTime: ...   # star:+15min; secondary:+2h; background:每日23:00
    async def run(self, ctx) -> list[EventDraft]: ...  # star:六步全循环; secondary:廉价决策; background:日摘要
```

调度器每 tick 收集 `next_due <= sim_now` 的 unit 进裁决队列（时钟兜底），交互唤醒直接插队。**W1~W2 的 8 人小世界全员 `'star'`，升降格逻辑 W3~W4 才启用**（源方案 §9，接口此时已就位）。

### 4.2 明星层轮换算法（叙事线 + 出场基尼系数驱动，带迟滞）

```python
def rotation_tick():                                  # 每模拟日 1 次
    gini = gini_coefficient(appearances_7d)           # §10.2 指标直接驱动架构（同向）
    for a in all_agents:
        score[a] = ( w_arc * in_active_arc(a)         # 在活跃叙事线
                   + w_dir * director_nominated(a)    # 被编剧点名
                   + w_int * recent_interactions(a)   # 近 2 模拟日被交互/进镜头
                   + w_cold * cold_bonus(a, gini) )   # 基尼超标时给冷门角色升格资源
    for a in secondary_or_background:                 # 迟滞：避免每日 churn
        if score[a] > PROMOTE_IN and a.consecutive_over(PROMOTE_IN) >= 2: promote(a)
    for a in stars:
        if score[a] < DEMOTE_OUT and a.consecutive_under(DEMOTE_OUT) >= 3: demote(a)
    enforce(star_count == 8 and daily_churn <= 2)  # 超员末位降格/缺员补位；每模拟日最多变动 2 人
```

`PROMOTE_IN > DEMOTE_OUT`（0.62 / 0.45）形成滞回带；基尼超阈值（§10.2）时 `cold_bonus` 权重自动上调——指标与架构同向，不需人工干预。

### 4.3 升格/降格衔接与次要层/背景层 prompt 结构

- 每次变动落事件 `agent.promoted` / `agent.demoted`（`trigger=system`，payload 含 score 分解与 gini），进每日审计（§10.1 "LOD 升降格记录完整"）。
- **升格衔接**（源方案 §3.2"升格无记忆断档"）：升格后立即跑一次**追赶反思**——取最近 1 条日摘要 + 配额检索（§7.1）一次 → 生成当前计划与心境，作为首个明星层认知循环的初始上下文。次要/背景层内心状态本就在演化，衔接的不是"公开事实"而是其最新内心状态。
- 降格不丢数据：次日日摘要自然接管；未完成的对话/邀约以事件结算后再降格。

次要层廉价决策与背景层日摘要的 prompt 结构。次要层（每模拟 2 小时，GLM 免费档/本地 8B，全 prompt ≤900 tokens）：

```
[system] 你是角色扮演引擎。只输出 JSON。
人设卡压缩版(姓名/年龄/职业/Big Five 概括/一句话当前目标) | 当前时间/地点/在场者
近 2 小时相关事件摘要(≤5 条) | 六需求值 | 关系增量变化(≤3 条)
输出: {"intent":"≤30字高层意图","emotion_delta":{...},"action":{"type":"枚举|null",...},
       "gossip":"想传播的一句话|null"}
```

约束：只出高层意图与情绪变化，**可主动发起事件**（invite/chat/gossip 进裁决队列；对象在明星层则走正常六步管道），保证"有动机、会邀约、关系会演化"（源方案 §3.2，次要层不可砍）。

背景层（每模拟日 1 次批量摘要）：

```
[system] 总结该角色今天的模拟日。输出 JSON。
人设卡压缩版 | 今日发生在其身上的事件(系统流水 ≤10 条) | 目击投影(≤5 条) | 昨日摘要
输出: {"diary":"≤120字第一人称摘要(写为摘要记忆,重要性3~5)","needs_delta":{...},
       "mood":"...","tomorrow_plan":"≤40字"}
```

## 5. 事件 Schema v1 与 PostgreSQL DDL

### 5.1 事件 Schema v1（W1 冻结）

字段集与源方案 §3.3 逐字对齐：`tick / sim_time / type / source / payload / rng_seed / trigger(autonomous|world|director|gift|vote) / arc_id / UI 展示字段预留`。本文补充工程字段（`seq/wall_time/actors/location_id/visibility/schema_version`），不进入语义层；冻结指**语义字段与枚举不得破坏性变更**，新增事件类型与 payload 键属兼容演进。

### 5.2 DDL（PostgreSQL 16 + pgvector）

```sql
CREATE EXTENSION IF NOT EXISTS vector;

-- 事件表：append-only，按 sim_time 周分区（pg_partman 模板）
CREATE TABLE events (
  seq BIGINT GENERATED ALWAYS AS IDENTITY,
  tick BIGINT NOT NULL,
  sim_time TIMESTAMPTZ NOT NULL, wall_time TIMESTAMPTZ NOT NULL DEFAULT now(),
  type TEXT NOT NULL,                 -- dialogue/invite.*/agent.promoted/economy.settle/...
  source TEXT NOT NULL,               -- 'agent:<id>' | 'world' | 'director' | 'system'
  trigger TEXT NOT NULL CHECK (trigger IN ('autonomous','world','director','gift','vote','system')),
  arc_id TEXT, location_id TEXT,          -- 故事弧线(可空) / 地点节点（目击投影依据）
  actors INT[] NOT NULL DEFAULT '{}', -- 参与者（双人事件=[A,B]）
  rng_seed BIGINT,                    -- 只复现规则骰子（§5.3）
  payload JSONB NOT NULL,
  visibility TEXT NOT NULL DEFAULT 'internal' CHECK (visibility IN ('public','internal')),
  ui JSONB,                           -- UI 展示字段预留（气泡样式/镜头提示/切片标记/A级）
  schema_version SMALLINT NOT NULL DEFAULT 1,
  PRIMARY KEY (sim_time, seq)
) PARTITION BY RANGE (sim_time);
CREATE UNIQUE INDEX events_seq_uidx ON events (seq);        -- 云端幂等的依据
CREATE INDEX events_tick_idx ON events (tick); CREATE INDEX events_type_time ON events (type, sim_time DESC);
CREATE INDEX events_actors_gin ON events USING GIN (actors);
CREATE INDEX events_arc_idx ON events (arc_id) WHERE arc_id IS NOT NULL;
CREATE INDEX events_loc_time ON events (location_id, sim_time DESC);
-- append-only：REVOKE UPDATE,DELETE + 触发器 RAISE EXCEPTION 双保险

CREATE TABLE agents (
  id INT PRIMARY KEY, name TEXT NOT NULL, gender TEXT NOT NULL, age INT NOT NULL,
  room_no TEXT, department TEXT, job_title TEXT,   -- 租客 24 / 公司员工 16
  cognition_tier TEXT NOT NULL DEFAULT 'background'
    CHECK (cognition_tier IN ('star','secondary','background')),
  persona JSONB NOT NULL,                       -- 人设卡全量（Big Five/经历/视觉符号）
  needs JSONB NOT NULL,                         -- 六需求 0~100
  mood JSONB, balance_cents BIGINT NOT NULL DEFAULT 0,
  position TEXT NOT NULL, holdings JSONB NOT NULL DEFAULT '{}',  -- 地点节点 / 持仓
  next_due_sim TIMESTAMPTZ,                     -- 调度器下次兜底时间
  consecutive_over INT NOT NULL DEFAULT 0, consecutive_under INT NOT NULL DEFAULT 0,  -- 迟滞计数
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE world_state (  -- 唯一事实源 KV：时钟锚点/股价/公告/暂停态
  key TEXT PRIMARY KEY, value JSONB NOT NULL,
  updated_tick BIGINT NOT NULL, updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE memories (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  agent_id INT NOT NULL REFERENCES agents(id), sim_time TIMESTAMPTZ NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('event','projection','reflection','summary','plan')),
  content TEXT NOT NULL,
  importance SMALLINT NOT NULL CHECK (importance BETWEEN 1 AND 10),
  embedding vector(1024),              -- bge-m3 1024 维
  source_event_seq BIGINT,             -- 双人事件单源：双方记忆指向同一 seq
  archived BOOLEAN NOT NULL DEFAULT FALSE, created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX mem_agent_time ON memories (agent_id, sim_time DESC) WHERE NOT archived;
CREATE INDEX mem_agent_imp ON memories (agent_id, importance DESC, sim_time DESC) WHERE NOT archived;
CREATE INDEX mem_src_event ON memories (source_event_seq);
CREATE INDEX mem_embed_hnsw ON memories USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);  -- pgvector 0.8；查询侧 ef_search=40

CREATE TABLE relations (  -- 有序对 (A→B)
  a_id INT NOT NULL REFERENCES agents(id), b_id INT NOT NULL REFERENCES agents(id),
  affinity SMALLINT NOT NULL DEFAULT 0 CHECK (affinity BETWEEN -100 AND 100),
  tension SMALLINT NOT NULL DEFAULT 0,
  labels TEXT[] NOT NULL DEFAULT '{}', one_line TEXT,
  last_event_seq BIGINT, updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (a_id, b_id), CHECK (a_id <> b_id)
);

CREATE TABLE goals (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  agent_id INT NOT NULL REFERENCES agents(id), sim_week INT NOT NULL, goal TEXT NOT NULL,
  blocked_count INT NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','done','abandoned')),
  frustration SMALLINT NOT NULL DEFAULT 0   -- 长期受阻→挫败→换策略/迁怒/放弃
);

CREATE TABLE intent_cooldown (  -- 意图冷却（按模拟时间）
  agent_id INT NOT NULL, intent_key TEXT NOT NULL,   -- 如 invite:7:dinner

);

CREATE TABLE interventions (  -- 编剧干预审计（干预率 <15% KPI 的数据源）
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  sim_time TIMESTAMPTZ NOT NULL,
  level TEXT NOT NULL CHECK (level IN ('L0','L1','L2')),   -- L3 永禁
  arc_id TEXT, reason TEXT NOT NULL, payload JSONB NOT NULL,
  event_seq BIGINT NOT NULL            -- 对应 events.seq（trigger='director'）
);

CREATE TABLE llm_calls (  -- 全量记录：¥/模拟日 计量的唯一依据
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  wall_time TIMESTAMPTZ NOT NULL DEFAULT now(), sim_time TIMESTAMPTZ,
  task_type TEXT NOT NULL,   -- star_decision/dialogue/secondary/bgsummary/reflection/director/safety/embed
  agent_id INT, provider TEXT NOT NULL, model TEXT NOT NULL,
  prompt_tokens INT NOT NULL, completion_tokens INT NOT NULL,
  cost_micro_cny BIGINT NOT NULL,      -- 微元，按 models.yaml 价格表算
  latency_ms INT NOT NULL, status TEXT NOT NULL,   -- ok/retry/failed/fallback
  fallback_from TEXT, request_id TEXT, prompt_hash TEXT   -- fallback_from=降级链来源 provider
);
CREATE INDEX llm_calls_simday ON llm_calls (date_trunc('day', sim_time));

CREATE TABLE sync_state (  -- 单行：出站复制位点
  id SMALLINT PRIMARY KEY DEFAULT 1 CHECK (id = 1),
  last_acked_seq BIGINT NOT NULL DEFAULT 0, updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE presentation_queue (  -- 呈现队列（§6.4）：本机生成、云端消费
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  event_seq BIGINT NOT NULL,           -- 源事件（dialogue 整段）
  line_no INT NOT NULL, text TEXT NOT NULL, speaker_id INT NOT NULL,
  play_at TIMESTAMPTZ NOT NULL         -- wall_time：逐句播放时刻（每句间隔 2~4s）
);
```

规模估算：40 人、每真实日 ≈1.9 模拟日 → 事件 ≈2~4 万/真实日、记忆 ≈3~5 万/真实日；以 `archived` 过滤把在线检索集控制在百万内（§7.3），HNSW 在该量级召回稳定。

### 5.3 可回放语义 = 重放事件流（实现约束写死）

- `REPLAY_MODE=replay`：LLM 网关拒绝一切真实调用，规则骰子一律从 `events.rng_seed` 取数，时钟以事件流 `sim_time` 为准。
- **LLM 输出即使 temperature=0 服务端也不保证确定性**——A/B 实验只能分叉重跑并接受 LLM 噪声（源方案 §3.3），代码注释与文档不得暗示"重算世界"。观察端"事件时间轴倒带"= 对副本库 `WHERE sim_time <= t` 的只读投影，天然满足。

## 6. 裁决管道（认知循环六步）

### 6.1 六步逐步伪代码

```
step1 感知注入（不让 LLM 编事实，源方案 §4.9）：
  obs = build_observation(agent)  # 结构化：sim_time/地点/在场者/需求/余额/日程/
                                  # 未读事件(按 visibility 过滤)/人设卡(每次必带)
step2 配额制记忆检索：mems = quota_retrieve(agent, query=obs.summary, N=10, M=5, K=10)  # §7.1
step3 LLM 决策：
  raw = llm_gateway.call(task='star_decision', prompt=render(agent, obs, mems, goals))
  decision = parse_json(raw)      # {intent, action:{type:枚举, args}, say?, emotion_delta}
  解析失败 → 重试 1 次(追加格式纠错后缀) → 仍失败记 think 动作("走神了")并落 llm_calls
step4 校验执行（§6.2）：verdict = validators.check(agent, decision.action, world_state)
  非法 → 拦截，写 memory("想做X但被现实阻止:原因")，必要时进 intent_cooldown
  合法 → 结算状态变更（移动扣时间、购物扣余额、日程冲突拒绝）
step5 同源写入（§6.3）：
  event = events.insert(type=..., actors=[...], rng_seed=本tick骰子, ...)
  参与者各写 kind='event' 记忆投影（source_event_seq=event.seq）
  同地点旁观者写 kind='projection' 简略投影（§6.3）
  relations/goals/needs 按规则结算（数值只由系统改，LLM 不直接写）
step6 反思（§7.2）：importance_acc += Σ事件重要性; if acc >= 20: deep_reflect(agent)
```

### 6.2 动作校验器（枚举动作空间）

动作枚举：`move / chat / invite / work / rest / eat / shop / trade_stock / think / argue / gossip / refuse`（源方案 §4.4/§4.6）。校验规则表：

| 规则 | 拦截条件 |
|---|---|
| 可达性 | `move` 目标须相邻或经公共区可达；`chat/invite` 对象须同地点或可通讯 |
| 时间 | 动作消耗模拟时间（标准耗时表）；与既有约定冲突 → 拒绝 |
| 经济 | `shop/trade_stock` 余额/持仓校验，只由系统按事件结算 |
| 冷却 | 命中 `intent_cooldown`（`until_sim > now`）→ 拦截 |
| 状态 | 精力 <10 强制 `rest`；饥饿 >85 时非进食动作降权提示；背景层主动发起的动作先经升格判定（§4.3） |

### 6.3 双人事件单源写入与目击投影

同一场交互（对话/邀约/争执）**只生成一条 events 行**，`actors=[A,B]`，双方记忆均为该行投影（`source_event_seq` 相同，`content` 为各自视角一句话）；审计"双人记忆同源"即校验此约束（§10.1）。事件落库时，查 `position = event.location_id` 且不在 `actors` 内的在场者（LOD 不限），每人写一条 `kind='projection'` 记忆：系统模板压缩（"你看到 A 和 B 在茶水间激烈争论"），重要性 = 原事件 −2（下限 1），embedding 照常。这是八卦自然传播的载体，也是观察端涟漪追踪的数据基础。

### 6.4 对话：整段落库与逐句播放解耦（呈现队列）

```
内核侧（一次性）：dialogue_gen(A, B, topic)：两 agent 交替产出共 6~8 轮（源方案 §4.7）
  → 整段过安全初筛（§11.1）→ 写一条 events(type='dialogue', payload.lines=[...])
  → 拆句写 presentation_queue：line_no, play_at = now + line_no × uniform(2,4)s
云端侧：呈现 worker 从副本库 presentation_queue 按 play_at 到期逐句推 WS → 气泡逐句出现
```

**呈现时间 vs 内核时间偏移**：观众看到的"现在"是内核的"过去"（整段 16~40s 生成 + 逐句播放）。剪辑/观察端形态无影响；直播形态下礼物/投票无法影响正在播放的缓冲，互动必须指向"下一段"排期——落地为：**`trigger IN ('gift','vote')` 的事件，其 `sim_time` 必须晚于副本库当前播放位点**，由裁决器校验。

## 7. 记忆系统

### 7.1 配额制检索（top-k = 近期 N + 高重要性 M + 语义相关 K）

不用混合排序（长跑后 top-k 会被"语义相关但无关紧要"的旧记忆挤占，源方案 §4.5），分桶取后合并去重：

```sql
WITH recent AS (    -- N=10：近期
  SELECT id, 1 AS bucket FROM memories
  WHERE agent_id=$1 AND NOT archived ORDER BY sim_time DESC LIMIT 10),
important AS (      -- M=5：近 7 模拟日高重要性
  SELECT id, 2 AS bucket FROM memories
  WHERE agent_id=$1 AND NOT archived AND sim_time > now_sim() - interval '7 days'
  ORDER BY importance DESC, sim_time DESC LIMIT 5),
semantic AS (       -- K=10：语义相关（排除已选），$2=感知摘要 embedding
  SELECT id, 3 AS bucket FROM memories
  WHERE agent_id=$1 AND NOT archived
    AND id NOT IN (SELECT id FROM recent UNION SELECT id FROM important)
  ORDER BY embedding <=> $2 LIMIT 10)
SELECT m.* FROM memories m
JOIN (SELECT DISTINCT ON (id) id, bucket FROM
      (SELECT * FROM recent UNION ALL SELECT * FROM important UNION ALL SELECT * FROM semantic) t
     ) q USING (id)
ORDER BY bucket, sim_time DESC;
```

配额 `N/M/K=10/5/10` 为默认，写入 `models.yaml` 可调；门禁① 的采访评估是其最直接的检验手段。

### 7.2 反思双通道

- **重要性触发**：每 agent 维护 `importance_acc`（落 `agents.mood` JSON 持久化），累计 ≥20 触发深度反思：取窗口内记忆 → 明星层模型生成 2~3 条洞察（`kind='reflection'`，重要性 7~9）→ 更新计划。用明星层模型，因为反思质量直接决定人格可信度。
- **每日兜底**：每模拟日 23:00（或就寝时）强制一次廉价摘要式反思（次要层模型），防平淡期人格僵化。
- 反思受人设卡约束（人设卡必带，源方案 §4.9）；Big Five 周测脚本每周跑漂移检测。

### 7.3 膨胀治理

| 措施 | 周期 | 规则 |
|---|---|---|
| 摘要合并 | 每模拟日（凌晨 batch 段） | 7 模拟天前、`kind='event'`、importance ≤4 的连续记忆由次要层模型合并为一条 `summary`，原条目 `archived=true`（不删，可回溯） |
| 归档 | 每模拟日 | importance ≤3 且 30 模拟天前 → `archived=true`；归档集不进配额检索 |
| 索引重建 | 每周日凌晨（真实） | `REINDEX INDEX CONCURRENTLY mem_embed_hnsw`；行数 >100 万或召回抽检退化（采样 50 条已知相关对命中率 <85%）时提前重建；embedding 模型更换时离线批跑重算、新列灰度切换 |

## 8. LLM 网关

### 8.1 路由表（`config/models.yaml`）

| task_type | 主路由 | 降级链 | 说明 |
|---|---|---|---|
| `star_decision` / `dialogue` / `reflection`(深度) | DeepSeek V4-Flash 档（前缀缓存开） | 重试3次→GLM 付费档→暂停时钟 | 明星层决策/对话/深度反思，全价 |
| `secondary` / `bgsummary` | GLM Flash 免费档 | 撞墙→本地 Qwen3-8B（唤醒） | 次要层/背景层，~144+40 次/模拟日 |
| `director` / `world_copy` | Kimi K3 档 | 失败→任务排队延后（不降级换模型，保文风） | 编剧/世界文案，限 ~50 次/真实日 |
| `safety` | 本地 Qwen3-4B（常驻） | 无（故障=暂停发布通道，内核照跑） | 内容安全初筛，高频 |
| `embed` | 本地 bge-m3 | GPU 忙→云端批量（`WSIM_EMBED_BACKEND=cloud`） | 每次决策都调用 |

型号 ID 与定价**开工当天以官方文档核实**后写入 `models.yaml` 的 `providers:` 段（源方案 §5 警告）；上表只绑 task_type→provider 别名，不硬编型号。

### 8.2 GLM 免费档撞墙判定（降级链触发条件）

满足任一即切本地 8B，冷却 30 分钟后单请求探测恢复：① 连续 3 次 HTTP 429/5xx（重试耗尽）；② 滑动 5 分钟窗口 RPM 使用率 >90%（上限按开工当天核实值配置）；③ 滑动 5 分钟 p95 延迟 >8s。切换与恢复各写 `events(type='llm.failover', trigger='system')`，`llm_calls.fallback_from` 全程留痕——W2 实测单价时要能区分"免费档实际扛了多少"。

### 8.3 全量记录与 ¥/模拟日 计量

每次调用（含失败与重试）写 `llm_calls` 一行；`cost_micro_cny = prompt_tokens×in_price + completion_tokens×out_price`，价格表在 `models.yaml`；本地模型记 0 但记录耗时（归账 GPU 预算）。**¥/模拟日 = `SUM(cost)/COUNT(DISTINCT date(sim_time))`**，滚动 7 模拟日窗口平滑；月成本 = ¥/模拟日 × 每月模拟日数（§3.1）。

### 8.4 熔断线（基线 1.5× 报警 / 2× 自动降速）

基线 = W2 初测单价（W4 复测后更新），写死进 `WSIM_COST_LIMIT_CNY_PER_SIMDAY`。

| 级别 | 触发 | 动作 |
|---|---|---|
| 报警 1.5× | 滚动窗口单价 ≥1.5× 基线持续 1 模拟日 | 告警 + 日报置顶 + 要求人工确认；内核不变 |
| 降速 2× | ≥2× 持续 1 模拟日 | ① `secondary/bgsummary` 强制本地 8B；② 编剧 K3 调用减半；③ 每模拟日对话场次上限降为 60%；④ 深度反思阈值 20→35；⑤ 告警升级。**不降明星层兜底频率**（密度是可信度底线，宁可暂停时钟）；24 真实小时后仍 >2× → 暂停时钟等人工 |
| 恢复 | 回落 <1.3× | 逐级撤销，写 `llm.throttle_*` 事件 |

### 8.5 RPM 管理与重试退避

每 provider 一个令牌桶（容量=核实的 RPM）；任务优先级 `safety > star_decision > dialogue > secondary > bgsummary > director`，桶空时低优先级排队、高优先级可抢占低优先级待发请求。重试：指数退避 1s/2s/4s 最多 3 次，±20% 抖动，429 优先读 `Retry-After`；耗尽走降级链（§8.2）。

## 9. 云端摄入 API 与副本库

### 9.1 API 契约

| 端点 | 方法 | 说明 |
|---|---|---|
| `/v1/ingest/ws` | WSS | 主通道（§1.3 帧协议），Bearer token 鉴权（upgrade header） |
| `/v1/events:batch` | POST HTTPS | WSS 断时回退；body `{from_seq, events:[...]}`，单批 ≤500 条，响应 `{acked_upto}` |
| `/v1/health` | GET | 副本库 max(seq)、摄入延迟、最近 digest 校验结果 |

约定：**鉴权**——`Authorization: Bearer $WSIM_INGEST_TOKEN`，云端只存 token 的 SHA-256 哈希，TLS 强制。**幂等**——副本库 `events.seq` 全局唯一索引，`ON CONFLICT (seq) DO NOTHING`；乱序批拒绝（`from_seq` 必须等于 `max(seq)+1`，否则 `409 {expected_seq}` 由本机重发）；追平模式流水化产生的窗口内乱序由副本库缓冲（8 批）排序，超窗按乱序拒绝。**schema 校验**——逐事件校验 `schema_version=1` 与必填字段，不合格整批 `nack` 记日志，不静默丢弃。副本库与主库**同一份 DDL**（§5.2），仅去掉写保护触发器；对观察端是只读账号。

### 9.2 副本一致性校验与延迟预算

每日 04:30（备份之后）云端发起 digest 校验：按 `date(sim_time)` 分组算 `COUNT(*)`、`SUM(seq)`、`sha256(string_agg(md5(payload::text), '' ORDER BY seq))`，与本机 HTTPS 上报的 digest 逐日比对；不一致 → 该日全量重传（删该日分区重灌，append-only 使重灌安全）。结果写入审计日报。

| 链路 | 预算 |
|---|---|
| 事件落主库 → 发出 batch | ≤2s（攒批窗口） |
| 传输 + 副本库提交 | ≤1s（正常态） |
| 副本库 → Web WS 推送 | ≤1s；对话逐句播放按 `play_at`，不受复制延迟影响 |
| **端到端（事件→观众可见）** | **p95 ≤5s（黄金档）；追平模式不承诺** |
| 追平吞吐 | ≥2000 events/min（断网 1 真实日 ≈3 万事件，15 分钟内追平） |

## 10. 审计与健康度

### 10.1 每日自动审计 SQL（凌晨 batch 段后跑，结果落审计日报）

```sql
-- ① 余额守恒：全体余额 = 初始注资 + Σ 经济类事件结算额
SELECT (SELECT SUM(balance_cents) FROM agents) AS actual,
       (SELECT SUM((v->>'amount_cents')::bigint) FROM events WHERE type LIKE 'economy.%')
       + :initial_fund AS expected;
-- ② 不在两地：同一 agent 的相邻 move 事件，5 模拟分钟内不得出现在互斥地点
SELECT a.id FROM agents a
JOIN events e1 ON a.id = ANY(e1.actors) JOIN events e2 ON a.id = ANY(e2.actors)
WHERE e1.seq < e2.seq AND e1.type='move' AND e2.type='move'
  AND e1.location_id <> e2.location_id
  AND e2.sim_time BETWEEN e1.sim_time AND e1.sim_time + interval '5 minutes';
-- ③ 双人记忆同源：dialogue 参与者在事件窗口内的记忆不得指向多个源事件
SELECT e.seq FROM events e WHERE e.type='dialogue' AND EXISTS (
  SELECT 1 FROM memories m WHERE m.agent_id = ANY(e.actors)
   AND m.sim_time BETWEEN e.sim_time - interval '1 hour' AND e.sim_time + interval '1 hour'
  GROUP BY m.source_event_seq HAVING COUNT(DISTINCT m.source_event_seq) > 1);
-- ④ 干预率 <15%（滚动 7 模拟日）
SELECT COUNT(*) FILTER (WHERE trigger='director')::float / COUNT(*) AS intervention_rate
FROM events WHERE sim_time > now_sim() - interval '7 days';
-- ⑤ LOD 记录完整：快照对比 tier 变动须有对应 promoted/demoted 事件，且 promoted 后 1 模拟日内有追赶反思
```

任一不过 → 报告标红 + 告警；连续 3 天不过 → 暂停时钟进人工（宁可停，不带病跑，呼应"门禁不达标顺延"）。

### 10.2 叙事健康度五指标（计算口径）

| 指标 | 口径 | 阈值（初始，门禁后校准） |
|---|---|---|
| A 级事件间隔 | 相邻 `ui->>'grade'='A'` 事件 sim_time 差的中位数 | ≥1 个/模拟日（源方案 §4.8） |
| 事件类型熵 | 每模拟日 `type` 分布的香农熵（按 24 类归一化） | 7 日滑动下降 >20% 报警 |
| 出场基尼系数 | 7 模拟日内各 agent `events.actors` 出现次数的基尼系数 | >0.6 报警并上调轮换 `cold_bonus`（§4.2） |
| 对话 n-gram 重复度 | 7 日内 dialogue lines 的 3-gram 重复率（去 speaker） | >15% 报警（台词套路化） |
| 关系图周变化率 | `|Δaffinity|>5` 或 label 变更的边数 / 总边数，每模拟周 | <5% 报警（关系死水） |

五指标与审计同跑，输出到观察端"叙事健康度面板"（源方案 §6）。

## 11. 安全合规

### 11.1 内容三层过滤管线（剪辑/观察端形态，源方案 §10）

```
L1 本地初筛：Qwen3-4B 分类器（常驻，safety task）——所有将置 visibility='public' 的文本
   （对话、公告、反思摘要）入库前过一遍；标签 {pass, soft, block}。
   soft → 降权不进切片素材池；block → 同事件重生成一次 → 仍 block 则置 internal 并记安全审计。
L2 规则层：敏感词表 + 正则（政治/色情/暴恐/未成年人），本地毫秒级，先于 L1 短路。
L3 云端复核：切片发布前素材文本过云端内容安全 API + 人工终审（"审后发布"是 R1 风险低的根因）。
```

### 11.2 双通道分离与密钥管理

`events.visibility` 与 `memories.kind` 构成内外双通道：**观察端与切片只消费 `visibility='public'` 的事件投影**；记忆全文、需求值、干预审计属 internal，永不出站（sync 层按 visibility 过滤 + payload 脱敏白名单）。角色详情页的"最新反思"展示 public 化摘要（反思落库时同时生成一句对外口径）。

密钥管理：**所有云端 LLM API key（DeepSeek/GLM/Kimi）只存本机** `/etc/worldsim/worldsim.env`（权限 600，属主 worldsim），云端不持有任何 LLM key——云端被入侵 ≠ LLM 账单被盗刷。云端仅持有：副本库 DSN、ingest token 哈希、切片存储凭据，分别独立可轮换。密钥不进 git、不进日志（`llm_calls` 只记 `prompt_hash`）；轮换流程：新 key 写 env → `systemctl reload worldsim-kernel` → 旧 key 作废。

## 12. 运维

### 12.1 日志分级与快照/备份策略

| 级别 | 内容 | 去向 |
|---|---|---|
| DEBUG | 检索配额命中、校验器判定明细 | 本地文件日轮转留 7 天，默认不开 |
| INFO | tick 节律、事件落库计数、sync 批/ack、LOD 升降格 | journald + 文件留 30 天 |
| WARN | 重试、降级链切换、熔断报警、审计单项不过 | + 告警通道（聚合 15 分钟） |
| ERROR | 落库失败、schema 校验失败、时钟暂停 | + 告警通道（立即） |

LLM prompt/响应全文不进日志（在 `llm_calls` 关联查），日志只记 `request_id`。

快照/备份策略：

| 类型 | 频率 | 保留 |
|---|---|---|
| 快照（world_state/agents/relations/goals 全量 JSON gzip） | 每模拟日结束 | 本地 14 天，云端 90 天 |
| pg_dump（custom 全库） | 每真实日 04:10 | 本地 7 天，云端 30 天 |

推送：备份完成后经出站 HTTPS（rclone/restic）推云端；断网顺延，恢复后补推。

### 12.2 故障恢复 runbook

| 故障 | 处置 |
|---|---|
| 云端 LLM API 故障/限流 | 网关降级链自动走（§8.2）；全部 provider 熔断 → §3.2 暂停时钟，恢复后追平 |
| 断网 | 内核照跑（§1.3）；恢复自动追平；>24h 人工确认 digest 校验 |
| 主库宕机/损坏 | 停内核 → 最近 pg_dump 恢复 → 快照 + 事件流重放（`REPLAY_MODE=replay`）补齐 → digest 校验 → 重启。RPO ≤1 真实日；当日已 sync 部分可从副本库只读导出反向灌回（人工执行） |
| GPU 整机重启 | systemd 拉起 vLLM 三实例 → kernel `After=` 依赖启动 → 时钟从 `world_state` 锚点恢复 → §3.2 追平 |
| 云端机器故障 | 本机不受影响；云端恢复后 hello 握手报 max_seq，本机从断点重发 |

### 12.3 监控告警

最小集（systemd + 内核 metrics 端点 + 云端探针）：内核存活；sync 滞后（`max(seq) − last_acked_seq > 5000` 或延迟 >5 分钟）；黄金档 30 分钟无事件；¥/模拟日熔断两级；GPU 显存 >90%；磁盘 >80%；审计标红；副本 digest 不一致。通道：Webhook 到个人 IM。
