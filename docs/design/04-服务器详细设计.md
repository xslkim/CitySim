## 1. 部署拓扑（核心章节）

### 1.1 两台机器的分工

```
本机（NAT 后，无任何入站端口）
├── worldsim-kernel   Python 3.12 asyncio 单进程（内核；内置 llm_gateway/sync_client/audit 协程）
├── worldsim-vllm-safety   Qwen3-4B 内容安全初筛（常驻，OpenAI 兼容端点 :8101）
├── worldsim-vllm-fallback Qwen3-8B 次要层兜底（进程常驻、默认 sleep，:8102）
├── worldsim-embed         bge-m3 embedding（常驻，:8103）
└── PostgreSQL 16 + pgvector 0.8（主库，append-only 事件表）
        │ 仅出站：WSS（事件推送）+ HTTPS（批量回退/备份/心跳）
云端（公网 IP）
├── worldsim-ingest  FastAPI 摄入 API（WSS + HTTPS 双通道）
├── PostgreSQL 16 副本库（独立实例，由摄入写入，非流复制）
├── worldsim-web + slice-pipeline  Web 观察端（静态页+WS订阅）与切片素材/发布管线
```

分工原则（与源方案 §3.1 一致，阶段 1 单体）：

- **本机是唯一事实源**：事件先生效于本机主库，再异步复制到云端；云端永不回写，只做只读投影与呈现（摄入 → 副本库 → Web WS 订阅，即源方案 §6 的"事件库只读投影 + WebSocket 推送"）。
- **LLM 网关是内核进程内模块**而非独立服务：阶段 1 只有内核一个调用方，独立成服务只增加 IPC 与运维面；接口（§8）按服务边界设计，阶段 2 可原样拆出。
- **本地模型全部走 vLLM 的 OpenAI 兼容 HTTP 端点**，内核只依赖 `openai` SDK 协议，本地/云端模型在路由表里是同构的 `provider`。

### 1.2 推理运行时选型：vLLM（而非 Ollama）

vLLM 0.10+：PagedAttention + 连续批处理（安全初筛与 embedding 是高频负载，需要吞吐）；原生支持 bge-m3 pooling，与对话模型同一运行时；`--enable-sleep-mode` 可 API 控制睡/醒，正好实现"8B 兜底按需加载"而不用起停进程。Ollama 并发弱、卸载粒度粗，仅作 W1 实测出基准的工具，不进生产。**决策**：全部本地模型用 vLLM，`--gpu-memory-utilization` 显式控显存。

### 1.3 出站同步通道协议（本机 → 云端）

**决策：用主库 `events.seq`（单调递增 IDENTITY）作为事件流全局复制位点，outbox 即事件表本身**，不另建缓冲表/文件队列。理由：append-only 事件表天然是 WAL 语义的 outbox，`sync_state` 记录进度即可，少一套一致性风险。

**同步内容 = 三条流**（云端物化层的全部输入；逐表定义见 `docs/design/05-云端物化层设计.md`，下称 05）：

| 流 | 内容 | 复制位点 | 频次 |
|---|---|---|---|
| events 白名单 | `events` 白名单列（§5.2 DDL 标注），payload 经键白名单剥除 `text_raw` 等内部键后为"同步规范形"（05 §2） | `sync_state.last_acked_seq` | 实时攒批（200 条或 2s） |
| memories 投影 | `memory_projection` 行：记忆条目的展示通道投影（`content_display`，无原文/embedding），含 `kind='reflection'`（05 §3.2） | `sync_state.last_acked_memory_id` | 与事件批同连发送 |
| world_state 日快照 | 每模拟日全量状态 JSONB（字段白名单，05 §3.6），带本机 digest | `sync_state.last_acked_snapshot_day` | 每模拟日 1 次 |

通道：单条 WSS 长连（`wss://cloud/v1/ingest/ws`），断线回退 HTTPS 批量接口（§9）。帧格式（JSON 一行一帧）：

```json
{"frame":"hello","token":"<ingest_token>","from_seq":12345,"kernel_ver":"0.4.0"}   // 本机→云端
{"frame":"batch","from":12345,"to":12404,"events":[ ... 白名单规范形 events 行 ... ]}
{"frame":"mem_batch","from":8001,"to":8120,"memories":[ ... memory_projection 行 ... ]}
{"frame":"snapshot","sim_day":"2026-10-12","digest":"sha256:…","state":{ ... 白名单全量状态 ... }}
{"frame":"ack","upto":12404,"mem_upto":8120,"snap_upto":"2026-10-12"}   // 云端→本机：副本库已事务提交；三流各位点同帧回执（snap_upto = 快照流位点，评审二轮 P2-7 增补）
{"frame":"nack","from":12400,"reason":"schema"}   // 另有 hello_ack / ping / pong
```

完整流程：

```
正常态：事件事务提交后 → sync 协程攒批（200 条或 2s）→ 发 batch → 收 ack
        → UPDATE sync_state SET last_acked_seq=upto, last_acked_memory_id=mem_upto,
          last_acked_snapshot_day=snap_upto（三流各推各位点，快照位点由 ack 帧 snap_upto 显式回执）
断网态：发送超时 5s → 通道标记 down，指数退避重连（1s→…→60s 上限，±20% 抖动）；
        内核照常运行（世界不等人），事件在主库自然积压，无额外动作
恢复态：重连 → hello 携 last_acked → 云端 hello_ack 回 max_seq
        → max_seq < last_acked 说明副本缺数据，按 max_seq 重发（幂等兜底）
        → 追平模式：每批 500 条、窗口 8 批流水化，追平后回正常态；
          追平期间观察端照常展示（按 seq 有序可见，只是延迟大）；
          快照断档按 sim_day 补发，派生表由云端按 05 §4.3 重算覆盖
```

约束：**顺序与幂等**——events 严格按 seq 升序推，云端 `ON CONFLICT (seq) DO NOTHING`，重复批安全；memories 投影同理按 id 升序、`ON CONFLICT (memory_id) DO NOTHING`（投影行不可变）；快照按 `sim_day` 幂等覆盖。**ACK 语义**=副本库已事务提交，不是"收到"；**断网不影响内核**（源方案 R6），sync 是独立协程，崩溃后从 `sync_state` 续传；每帧带 `schema_version`，云端拒收未知版本，防 W1 冻结后字段漂移静默丢数据。**trigger 全枚举透传**——含工程扩展 `'system'`（时钟暂停/追平、LLM 降级等系统事件，§5.1），同步层不按 trigger 过滤；下游 UI 过滤/映射枚举必须包含 `system`，否则严格校验会静默剥除系统事件（评审 P2-17）。**digest 相容性**：digest 一律在同步规范形（双方同一白名单剥除 `text_raw` 后的 canonical payload）上计算，或仅 `COUNT/SUM(seq)`，与"副本库物理剥除内部键"天然相容（§9.2、05 §2，评审 P1-3）。

### 2.2 asyncio 主循环伪代码与 tick 串行裁决语义（写死）

```python
async def main():
    db = await create_pool(WSIM_PG_DSN)
    clock = TimeEngine(db, load(WSIM_SPEED_TABLE))
    queue = AdjudicationQueue()          # 优先级堆：世界事件 > 交互唤醒 > 时钟兜底
    gw    = LLMGateway(db, load(WSIM_MODELS_CONFIG))
    async with asyncio.TaskGroup() as tg:
        tg.create_task(clock.run(on_tick=lambda t: queue.put(ClockTick(t))))
        tg.create_task(adjudication_loop(db, queue, gw))   # 唯一写协程，串行裁决
        tg.create_task(sync.run()); tg.create_task(audit.daily_loop())
        tg.create_task(memory.hygiene_loop()); tg.create_task(scheduler.rotation_loop())
```

tick 串行裁决语义（写死）：

- **只有一个裁决协程消费队列**——所有状态写（位置/余额/关系/记忆/事件）都发生在这里，天然无并发写冲突（源方案 §4.9"后到者收到已被占用事实"）。
- **tick = 模拟 5 分钟**（内部裁决粒度）：明星层"每模拟 15 分钟兜底"= 每 3 tick 排程一次；次要层"每模拟 2 小时"= 每 24 tick 一次。
- **"事件唤醒"= 进队列、下一个裁决点处理**（源方案 §3.4）：A 对 B 发起对话，B 不当场跑认知，而是收 `wakeup` 入队，下一 tick 裁决点处理；同 tick 对同 agent 的多个唤醒去重合并。
- tick 内 LLM 调用**并发发出**，结果写回**按队列顺序串行落库**——"LLM 并发、落库串行"，吞吐与一致性兼得。
- 单 tick 预算：黄金档 1:1 时 tick=真实 5 分钟，明星层 8 人并发认知 + 对话生成，p95 须 < 预算 60%（W2 实测校准）。

## 3. 时间引擎

### 3.1 时段变速表：配置 schema 与切换逻辑

`config/speed_table.yaml`：

```yaml
segments:                    # 按真实本地时间覆盖全天 24h，不允许空洞
  - { start: "00:30", end: "08:00", mode: batch, sim_hours_per_run: 8 }   # 凌晨批量粗粒度
  - { start: "08:00", end: "18:00", mode: continuous, ratio: 3.0 }        # 白天 2~4× 区间内取 3
  - { start: "18:00", end: "24:00", mode: continuous, ratio: 1.0 }        # 黄金档 ≈1:1
  - { start: "00:00", end: "00:30", mode: continuous, ratio: 2.0 }        # 深夜缓冲
constraints:
  min_sim_days_per_real_week: 8        # 源方案 §4.1 底线，加载时校验
  max_catchup_ratio: 6.0               # 追平模式上限
```

按上表：每真实日推进 `8 + 10×3 + 6×1 + 0.5×2 = 45 模拟小时 ≈ 1.9 模拟日`，每真实周 ≈13 模拟日 ≥8 ✔；月成本 = ¥/模拟日 × ~57 模拟日/月（排期选择，源方案 §5.2）。切换：真实时刻跨段边界触发 `SegmentSwitch`；continuous 段间仅改压缩比；进入 batch 段发起凌晨批量推进（§3.3）并暂停 tick 排程，离开后恢复。**压缩比只调观看节奏，不调世界密度**（v3.3 语义）：所有认知排程读 sim_time，切比不改变一个模拟日内任何 agent 被排程的次数。

### 3.2 模拟时间换算、故障暂停与恢复追平

锚点持久化在 `world_state`：`{anchor_sim, anchor_wall, ratio}`。continuous 段 `sim_time = anchor_sim + (wall_now − anchor_wall) × ratio`，跨段先把旧段积分进 `anchor_sim` 再换比。暂停写 `paused_at`，恢复时新锚点 `anchor_wall=now`、`anchor_sim` 不变——**暂停期间模拟时间不流动**（源方案 §5.2）。所有 DB 行同时存 `sim_time`（业务语义）与 `wall_time`（运维/计费语义）；认知频率、冷却、衰减一律只用 `sim_time`。

故障暂停与恢复追平流程：

```
检测致命依赖故障（主库不可用 / 全部 LLM provider 熔断 / 磁盘满）：
1. clock.pause()：写 paused_at，停止排程新认知；队列内已完成 LLM 调用正常落库，未发起的取消
2. 每 30s 探测依赖；恢复后追平：
   - 停机 <2 真实小时：min(ratio×2, 6×) 连跑直到回到计划 sim 位置
   - 停机 ≥2 真实小时：落后部分按 batch 模式补齐（逐 agent 摘要快进 §3.3），
     不追赶黄金档 1:1 对齐——宁可世界落后半天，不用 6× 稀释观看体验
3. 全程写事件 time.paused / time.resumed / time.catchup.start / time.catchup.end（trigger=system）
```

理由：认知调用量 ∝ 模拟时间，6× 连跑会把实时成本脉冲打穿熔断线；batch 补齐成本 ≈ 背景层日摘要，便宜一个量级。

### 3.3 凌晨批量粗粒度推进实现

```python
async def batch_advance(agents, sim_hours=8):        # 进入 batch 段（真实 00:30）
    await clock.enter_batch_mode(sim_hours)
    for chunk in chunked(agents, 10):                # 40 人分 4 批，并发 10
        await gather(*[background_summarize(a, sim_hours) for a in chunk])
        # 每人一次调用：总结 8h → 摘要记忆 + 需求/情绪状态变更
    await world_agent.run_batch_calendar()           # 跨日日历事件（如 8:00 打卡）一次性结算
    emit("time.batch_advanced", payload={"sim_hours": sim_hours}, trigger="system")
    await clock.exit_batch_mode()
```

batch 段内明星/次要层**不跑常规认知循环**（正是源方案"背景层日摘要模式扩展到全员"）；**背景层日摘要的唯一时点即凌晨 batch 段**（原 §4.1 `next_due` 的 23:00 排程定义已合并至此，全项目只此一处，评审 P2-4）：batch 调用对背景层兼作 §4.3 的日摘要（一次性总结刚结束的模拟日），明星/次要层仅做 8 小时快进摘要。编剧若在该段排了 A 级事件，在 batch 前插队认知循环结算掉再快进。

## 4. LOD 调度器

### 4.1 三层统一接口

**认知模式是 `agents.cognition_tier` 字段**（`'star'|'secondary'|'background'`，源方案 §9 W1~W2 即按此预留接口），调度器按字段分发到同一接口的三个实现：

```python
class CognitiveUnit(Protocol):
    agent_id: str                                       # 'A01'~'A40'（DB TEXT，全链路统一，§5.1）
    def next_due(self, sim_now) -> SimTime: ...   # star:+15min; secondary:+2h; background:凌晨batch段(§3.3)
    async def run(self, ctx) -> list[EventDraft]: ...  # star:六步全循环; secondary:廉价决策; background:日摘要
```

调度器每 tick 收集 `next_due <= sim_now` 的 unit 进裁决队列（时钟兜底），交互唤醒直接插队；**被唤醒对象当前非明星层时，按 §4.2 路径二当 tick 升格后再响应**（事件驱动即时升格，评审 P1-5）。**W1~W2 的 8 人小世界全员 `'star'`，升降格逻辑 W3~W4 才启用**（源方案 §9，接口此时已就位）。

### 4.2 明星层轮换与升格：双路径（迟滞只管基尼轮换；事件驱动当 tick 升格）

升格/降格有**两条互补路径**，管辖范围写死（评审 P1-5：源方案 §3.2/01 §5.1 要求"被邀约→触发升格、按次要层响应"，若升格只剩每日轮换一条路，被邀约者最快次日才能响应，邀约协议当场失效）：

**路径一：基尼驱动每日轮换（唯一受迟滞约束的路径，只决定明星层 8 个席位）**：

```python
def rotation_tick():                                  # 每模拟日 1 次
    gini = gini_coefficient(appearances_7d)           # §10.2 指标直接驱动架构（同向）
    for a in all_agents:
        score[a] = ( w_arc * in_active_arc(a)         # 在活跃叙事线
                   + w_dir * director_nominated(a)    # 被编剧点名
                   + w_int * recent_interactions(a)   # 近 2 模拟日被交互/进镜头
                   + w_cold * cold_bonus(a, gini) )   # 基尼超标时给冷门角色升格资源
    for a in secondary_or_background:                 # 迟滞：避免每日 churn
        if score[a] > PROMOTE_IN and a.consecutive_over(PROMOTE_IN) >= 2: promote(a, to='star')
    for a in stars:
        if score[a] < DEMOTE_OUT and a.consecutive_under(DEMOTE_OUT) >= 3: demote(a, to='secondary')
    enforce(star_count == 8 and daily_churn <= 2)  # 超员末位降格/缺员补位；每模拟日最多变动 2 人
```

`PROMOTE_IN > DEMOTE_OUT`（0.62 / 0.45）形成滞回带；基尼超阈值（01 §9，口径见 §10.2）时 `cold_bonus` 权重自动上调——指标与架构同向，不需人工干预。

**路径二：事件驱动即时升格（不受迟滞约束、不占每日 churn 名额）**：

- **触发集**（裁决协程内当 tick 生效）：① 被交互/被邀约——成为他人动作对象（`chat/invite/argue/give_gift/help/borrow_money/repay_money/confess/apologize` 的 target，或邀约送达，01 §5.1）；② 进镜头——成为 `visibility='public'` 或 A 级候选事件的非发起参与者/直接目击；③ 被编剧点名（L1/L2 干预附带 `director_nominated`）。
- **升格目标层**：①② background → secondary（已在 secondary/star 不动作；次要层即可响应交互，01 §5.1"按次要层廉价决策响应"）；③ 直达 star（随后纳入路径一迟滞管理）。
- **落库**：当 tick 写 `agent.promoted`（`trigger='system'`，与 01 §5.1 及 06 注册表一致；`payload.reason='event_driven'/'director_nominated'` 区分来源，`payload.caused_by='<seq>'`（裸 seq 数字字符串，§5.1 值形态口径）记触发事件），本 tick 即按新层响应——被邀约 B 当 tick 升格、当 tick 跑次要层决策给出接受/拒绝/改期。
- **回落**：事件驱动升入 secondary 者，连续 2 模拟日零新交互 → 写 `agent.demoted`（`reason='cooldown'`）回 background；此回落同样不受迟滞约束，且不触碰明星层席位（secondary 不占 star 数）。明星层席位进出只由路径一管辖。
- **规模硬上限（评审二轮 N-P1-7）**：secondary 层总人数 **≤16 人**（源方案 §3.2 目标水位 ~12，16 为工程硬顶，成本模型硬约束）。事件驱动升格导致超额时，按 **LRU（最久无新交互）** 把最久未作为交互参与者/目标的 secondary 成员当 tick 挤出回 background，写 `agent.demoted`（`reason='lru_evict'`；LRU 键 = 该 agent 最近一次出现在事件 `actors` 或动作 target 的 sim_time，由调度器随事件流维护）——挤出即时生效，不等"连续 2 模拟日零交互"回落。路径一降格入 secondary 同样受此上限约束（超员先 LRU 挤出再落入）。单价假设与 W4 验收随之改"secondary ≤16 人 × 12 次 = **≤192 次/模拟日**"上限口径（§8.1/§13 W4，W2 实测定稿）。

三层进出全矩阵（行=当前层，列=目标层）：

| from \ to | star | secondary | background |
|---|---|---|---|
| **star** | — | 路径一：score < `DEMOTE_OUT` 且连续 3 次（迟滞，受 churn ≤2/日 约束）；落入 secondary 超额时先按 LRU 挤出（上限 16 人） | 禁止直达（必须先经 secondary） |
| **secondary** | 路径一：score > `PROMOTE_IN` 且连续 2 次（迟滞，占 churn 名额）；或编剧点名（即时，不占名额） | — | 事件驱动回落：连续 2 模拟日零交互（即时）；或超额 LRU 挤出（即时，`reason='lru_evict'`） |
| **background** | 编剧点名直达（即时，不占名额） | 事件驱动升格：被交互/被邀约/进镜头（当 tick，即时；受 ≤16 人硬上限约束） | — |

### 4.3 升格/降格衔接与次要层/背景层 prompt 结构

- 每次变动落事件 `agent.promoted` / `agent.demoted`（`trigger='system'`；路径一 payload 含 score 分解与 gini，路径二含 reason 与 `caused_by`，§4.2），进每日审计（§10.1 "LOD 升降格记录完整"）。
- **升格衔接**（源方案 §3.2"升格无记忆断档"）：升入**明星层**后立即跑一次**追赶反思**——取最近 1 条日摘要 + 配额检索（§7.1）一次 → 生成当前计划与心境，作为首个明星层认知循环的初始上下文。事件驱动升入次要层不需要追赶反思（次要层内心状态本就在演化，衔接的不是"公开事实"而是其最新内心状态）。
- 降格不丢数据：次日日摘要自然接管；未完成的对话/邀约以事件结算后再降格。

次要层廉价决策与背景层日摘要的 prompt 结构。次要层（每模拟 2 小时，GLM 免费档/本地 8B，全 prompt ≤900 tokens）：

```
[system] 你是角色扮演引擎。只输出 JSON。
人设卡压缩版(姓名/年龄/职业/Big Five 概括/一句话当前目标) | 当前时间/地点/在场者
近 2 小时相关事件摘要(≤5 条) | 六需求值 | 关系增量变化(≤3 条)
输出: {"intent":"≤30字高层意图","emotion_delta":{...},"action":{"type":"枚举|null",...},
       "gossip":"想传播的一句话|null"}
```

约束：只出高层意图与情绪变化，**可主动发起事件**（invite/chat/gossip 进裁决队列；对象在明星层则走正常六步管道），保证"有动机、会邀约、关系会演化"（源方案 §3.2，次要层不可砍）。

背景层（每模拟日 1 次批量摘要）：

```
[system] 总结该角色今天的模拟日。输出 JSON。
人设卡压缩版 | 今日发生在其身上的事件(系统流水 ≤10 条) | 目击投影(≤5 条) | 昨日摘要
输出: {"diary":"≤120字第一人称摘要(写为摘要记忆,重要性3~5)","needs_delta":{...},
       "mood":"...","tomorrow_plan":"≤40字"}
```

## 5. 事件 Schema v1 与 PostgreSQL DDL

### 5.1 事件 Schema v1（W1 冻结）

字段集与源方案 §3.3 逐字对齐：`tick / sim_time / type / source / payload / rng_seed / trigger / arc_id / UI 展示字段预留`。本文补充工程字段（`seq/wall_time/actors/location_id/visibility/schema_version`），不进入语义层；冻结指**语义字段与枚举不得破坏性变更**，新增事件类型与 payload 键属兼容演进。

跨文档统一口径（W1 冻结的一部分，全项目一致，不得另创方言；评审 P1-2）：

- **agent 标识**：字符串 `'A01'~'A40'`，DB `TEXT`、人设 YAML（01 §2.2）、UI 全链路统一。
- **事件标识**：DB 主键 `seq BIGINT`；叙事/日志/UI 中的引用形态为字符串 `'e<seq>'`（如 `e1102`）。**值形态口径（评审二轮 N-P1-12，全项目一致，不得另创）**：payload 内一切事件/记忆引用值一律为**裸 seq 数字字符串**（如 `'1089'`——便于 `(payload->>'caused_by')::bigint` 转换与索引）；`'e<seq>'` 仅是叙事/日志/UI 展示形态，**禁止作为 payload 值**。
- **trigger 枚举**：`autonomous|world|director|gift|vote|system`——`system` 为工程扩展（时钟暂停/追平/批量推进、LLM 降级/熔断等系统事件），随同步协议原样透传（§1.3），下游过滤/映射枚举必须包含（评审 P2-17）。
- **事件类型命名**：`<domain>.<object>[.<verb>]`（如 `dialogue.chat`、`agent.move`、`relation.changed`、`time.paused`、`system.llm.failover`）；**全量类型注册表唯一持有方 = `docs/design/06-契约登记表.md`**，本文不复制全表，行文出现的类型名若与 06 不一致，以 06 为准并回改本文。
- **payload 键约定**（Schema v1 组成部分，06 逐类型登记并标注 public/internal——同步白名单依据）：
  - `caused_by: '<seq>'`——裸 seq 数字字符串（如 `'1089'`，禁止 `'e<seq>'` 作值，见上"事件标识"值形态口径）。因果链：本事件由哪个事件直接触发，裁决写入；01 旧字段 `parent_event_id` 废弃，统一改此名；
  - `cites: ['<memory_id>', …]`——gossip 引用本人记忆条目的 id 列表（`memories.id` 的裸数字字符串数组，值形态同上；06 §2），涟漪追踪递归依据（03 §3.4）；gossip 传播深度上限统一 4 手（01 §4.1）；
  - `lines: [{speaker, text_display, at_offset_s}]`——对话整段与逐句相对时间表（§6.4）；
  - `text_raw` / `text_display`——内部原文 / 展示通道文本（§11.2 双通道）；`text_raw` 永不出站。
- **UI 展示字段统一在 `ui.*` 下**：`ui.grade`（事件等级 A/B/C **初值**，随事件落库写入、此后该行永不 UPDATE；编剧复核修正走追加事件 `director.grade_revise`，§6.6），气泡样式/镜头提示/切片标记等预留键同。

- `REPLAY_MODE=replay`：LLM 网关拒绝一切真实调用，规则骰子一律从 `events.rng_seed` 取数，时钟以事件流 `sim_time` 为准。

### 6.3 双人事件单源写入与目击投影

同一场交互（对话/邀约/争执）**只生成一条 events 行**，`actors=[A,B]`，双方记忆均为该行投影（`source_event_seq` 相同，`content` 为各自视角一句话）；审计"双人记忆同源"即校验此约束（§10.1）。事件落库时，查 `position = event.location_id` 且不在 `actors` 内的在场者（LOD 不限），每人写一条 `kind='projection'` 记忆：系统模板压缩（"你看到 A 和 B 在茶水间激烈争论"），重要性 = 原事件 −2（下限 1），embedding 照常。这是八卦自然传播的载体，也是观察端涟漪追踪的数据基础。

涟漪追踪落库约定（03 §3.4 依赖，本文承接写入）：目击投影记忆落库时置 `is_witness=true`（06 §2，同步直传到 05 `memory_projection`）；`gossip` 事件 `payload.cites` 记录引用的本人记忆 id 列表（裸数字字符串数组，值形态见 §5.1；06 §2）；凡由事件直接触发的事件（含转述、响应、状态结算）`payload.caused_by='<seq>'`（裸 seq 数字字符串，禁止 `'e<seq>'` 作值）记前因；gossip 转述链深度上限 4 手（01 §4.1，跨文档统一口径）。

### 6.4 对话：整段落库与逐句播放（客户端唯一节拍权威）

```
内核侧（一次性）：dialogue_gen(A, B, topic)：两 agent 交替产出共 6~8 轮（源方案 §4.7）
  → 整段过安全初筛（§11.1）→ 写一条 events(type='dialogue.chat')
    payload.lines=[{speaker, text_display, at_offset_s}, ...]
    at_offset_s = 该句相对事件起点的播放偏移秒（生成时按每句 uniform(2,4)s 累计写死）
云端/客户端：观察端收到完整事件后，由客户端播放时钟按 at_offset_s ÷ 当前播放倍率逐句弹气泡
```

**播放节拍唯一权威 = 客户端倍率**（03 §3.2，评审 P2-7）：内核只在生成时写死相对时间表 `at_offset_s`，不维护任何服务端播放队列/播放位点——原 `presentation_queue` 独立通路取消（双节拍权威会让云端 worker 与客户端倍率打架，且该表本就不在同步协议内）。暂停/seek/倍率切换是纯客户端行为，不影响数据完整性。

**呈现时间 vs 内核时间偏移**：观众看到的"现在"是内核的"过去"（整段 16~40s 生成 + 逐句播放）。剪辑/观察端形态无影响；直播形态下礼物/投票无法影响正在播放的缓冲，互动必须指向"下一段"排期——落地为：**`trigger IN ('gift','vote')` 的事件，其 `sim_time` 必须晚于观察端当前播放位点**，由裁决器校验。

### 6.5 状态变更事件化（state.needs_delta / relation.changed，评审 P1-4）

裁决点增设两类**聚合型状态事件**，每 tick 合并写入（无变更不落）：

- `state.needs_delta`：`payload.changes=[{agent_id, need, delta, new_value, cause:'<seq>'}]`（`cause` 值为裸 seq 数字字符串，§5.1）——本 tick 全部六需求变更（衰减 + 满足 + 事件伤害）合并为一条；情绪摆动同结构携带（`need='mood'`）。
- `relation.changed`：`payload.changes=[{a_id, b_id, delta_affinity, delta_tension, labels_added?, labels_removed?, cause:'<seq>'}]`（值形态同上）——本 tick 全部关系边变更（含债务逾期日结算 §6.2、每周自然回归 01 §3.2）。

规则：

- 两类事件 `trigger` 取引发源（交互结算 `'autonomous'`、系统结算 `'system'`），`visibility='internal'`——无展示文本、前端非调试态不渲染，但**仍随白名单同步出站**（回放与副本库 state_diff 依赖，05 §3.3/§4）。
- `agents.needs` / `agents.mood` **降为缓存列**：事实源 = 初始值 + Σ `state.needs_delta`；缓存仅供裁决热路径读，每日审计对账"缓存值 == 事件流重算值"（§10.1 ⑥）。`relations` 表同理可由 `relation.changed` 全量重建——03 §3.3"每个数值可反查来源事件"与回放引擎状态重建（03 §4.3）由此获得地基。
- 事件量影响：每 tick 至多 +2 条（有变更才落），上限 = 当日 tick 数 ×2，计入 §5.2 规模估算（W2 实测回填）。

### 6.6 A 级 grade：自动打分写初值 + 编剧复核追加事件（评审 P1-11 / 二轮 N-P0-1）

判定标准唯一持有方 = 01 §6.4，本节是其工程落点。step5 落库**同事务内**，grade 打分器对该事件按 4 条**可程序化**规则即时判定，判定结果随 INSERT 写入 `ui.grade`（**初值**，append-only 约束下落库后该行永不 UPDATE，§5.2）：

1. 卷入 ≥2 名 Agent（`actors` + `witnesses` + gossip `payload.cites` 波及者并集计数）；
2. 至少一条关系边 `|Δaffinity| ≥5` 或有标签增删（本 tick `relation.changed` 中有本事件 `cause` 的记录）；
3. 至少一名参与者情绪摆动 ≥15（step5 情绪结算增量，落 `state.needs_delta`）；
4. 因果链完整：`payload.caused_by` 非空，或结算产生了可预期后续（新约定/新冷却/新意图入队）。

**按命中数定级**：命中 ≥3 条 → 候选 A 级；2 条 → B；0~1 条 → C。**编剧 K3 复核**（每模拟日批量 1 次，控成本，调用计入 `director` 预算 §8.1）：对全部候选 A 级按两条编辑维度终审——①"可在 3~8 分钟内讲清楚（含上下文铺垫）"；②戏剧张力/爽点维度（01 §11.3 目录）——终审可上调 B→A（**每日 ≤2 个**，保稀缺性）或下调 A→B。

**复核结果不改写原事件行，而是产生追加事件 `director.grade_revise`**（评审二轮 N-P0-1：旧稿"复核结果回写 `ui.grade`"与 §5.2 append-only 触发器（REVOKE UPDATE + RAISE EXCEPTION）、副本库 `ON CONFLICT DO NOTHING`、digest 不含 ui 列三方冲突，作废）：`source='director'`、`trigger='director'`（计入干预率统计，量极小——每日上调 ≤2 个加下调若干），payload = `{target_seq, new_grade, reason}`（`target_seq` 为裸 seq 数字字符串，§5.1 值形态口径），复核理由同时落 `arc_id` 关联记录。**events 表永不 UPDATE**——**有效 grade = `ui.grade` 初值被 `target_seq` 指向行的最新一条 `director.grade_revise.new_grade` 覆盖后的值**；副本端最新 grade 由 05 派生任务物化到查询视图 `event_grade_view`（定义唯一持有方 = 05），健康度指标（§10.2）、切片选题（01 §8.1）、时间轴 A 级过滤与"今日热涟漪"推荐位（03 §3.2/§3.4）一律读有效 grade（本机侧 = `ui.grade` ⊕ 最新复核事件；副本侧 = `event_grade_view`）。

## 7. 记忆系统

### 7.1 配额制检索（top-k = 近期 N + 高重要性 M + 语义相关 K）

不用混合排序（长跑后 top-k 会被"语义相关但无关紧要"的旧记忆挤占，源方案 §4.5），分桶取后合并去重：

```sql
WITH recent AS (    -- N=10：近期
  SELECT id, 1 AS bucket FROM memories
  WHERE agent_id=$1 AND NOT archived ORDER BY sim_time DESC LIMIT 10),
important AS (      -- M=5：近 7 模拟日高重要性
  SELECT id, 2 AS bucket FROM memories
  WHERE agent_id=$1 AND NOT archived AND sim_time > now_sim() - interval '7 days'
  ORDER BY importance DESC, sim_time DESC LIMIT 5),
semantic AS (       -- K=10：语义相关（排除已选），$2=感知摘要 embedding
  SELECT id, 3 AS bucket FROM memories
  WHERE agent_id=$1 AND NOT archived
    AND id NOT IN (SELECT id FROM recent UNION SELECT id FROM important)
  ORDER BY embedding <=> $2 LIMIT 10)
SELECT m.* FROM memories m
JOIN (SELECT DISTINCT ON (id) id, bucket FROM
      (SELECT * FROM recent UNION ALL SELECT * FROM important UNION ALL SELECT * FROM semantic) t
     ) q USING (id)
ORDER BY bucket, sim_time DESC;
```

配额 `N/M/K=10/5/10` 为默认，写入 `models.yaml` 可调；门禁① 的采访评估是其最直接的检验手段。

### 7.2 反思双通道

- **重要性触发**：每 agent 维护 `importance_acc`（落 `agents.mood` JSON 持久化），累计 ≥20 触发深度反思：取窗口内记忆 → 明星层模型生成 2~3 条洞察（`kind='reflection'`，重要性 7~9）→ 更新计划。用明星层模型，因为反思质量直接决定人格可信度。
- **每日兜底**：每模拟日 23:00（或就寝时）强制一次廉价摘要式反思（次要层模型），防平淡期人格僵化。
- 反思受人设卡约束（人设卡必带，源方案 §4.9）；Big Five 周测脚本每周跑漂移检测。
- **落库双通道（评审二轮 N-P1-2）**：每次反思（深度 / 每日兜底）除写 `memories`（`kind='reflection'`，原文仅内部通道，`content_display` 过安全管线后经 `memory_projection` 出站，§11.2）外，**同时落一条 `agent.reflection` display-only 事件**——`visibility='public'`、`trigger='autonomous'`，payload 白名单仅 `text_display`（06 §1.2 标注），经 events 流出站，是 03 §3.1 💭 调试态气泡与 §5.3 映射行的数据源；反思原文仍只走 `memory_projection`，永不随事件出站。生产点 = §6.1 step6（每日兜底在 23:00 批量反思点同样执行）。

### 8.2 GLM 免费档撞墙判定（降级链触发条件）

满足任一即切本地 8B，冷却 30 分钟后单请求探测恢复：① 连续 3 次 HTTP 429/5xx（重试耗尽）；② 滑动 5 分钟窗口 RPM 使用率 >90%（上限按开工当天核实值配置）；③ 滑动 5 分钟 p95 延迟 >8s。切换与恢复各写 `events(type='system.llm.failover', trigger='system')`，`llm_calls.fallback_from` 全程留痕——W2 实测单价时要能区分"免费档实际扛了多少"。

### 8.3 全量记录与 ¥/模拟日 计量

每次调用（含失败与重试）写 `llm_calls` 一行；`cost_micro_cny = prompt_tokens×in_price + completion_tokens×out_price`，价格表在 `models.yaml`；本地模型记 0 但记录耗时（归账 GPU 预算）。**¥/模拟日 = `SUM(cost)/COUNT(DISTINCT date(sim_time))`**，滚动 7 模拟日窗口平滑；月成本 = ¥/模拟日 × 每月模拟日数（§3.1）。

### 8.4 熔断线（基线 1.5× 报警 / 2× 自动降速）

基线 = W2 初测单价（W4 复测后更新），写死进 `WSIM_COST_LIMIT_CNY_PER_SIMDAY`。

| 级别 | 触发 | 动作 |
|---|---|---|
| 报警 1.5× | 滚动窗口单价 ≥1.5× 基线持续 1 模拟日 | 告警 + 日报置顶 + 要求人工确认；内核不变 |
| 降速 2× | ≥2× 持续 1 模拟日 | ① `secondary/bgsummary` 强制本地 8B；② 编剧 K3 调用减半；③ 每模拟日对话场次上限降为 60%；④ 深度反思阈值 20→35；⑤ 告警升级。**不降明星层兜底频率**（密度是可信度底线，宁可暂停时钟）；24 真实小时后仍 >2× → 暂停时钟等人工 |
| 恢复 | 回落 <1.3× | 逐级撤销，写 `system.llm.throttle` 事件 |

## 9. 云端摄入 API 与副本库

### 9.1 API 契约

| 端点 | 方法 | 说明 |
|---|---|---|
| `/v1/ingest/ws` | WSS | 主通道（§1.3 帧协议：events 白名单批 / memories 投影批 / 日快照），Bearer token 鉴权（upgrade header） |
| `/v1/events:batch` | POST HTTPS | WSS 断时事件回退；body `{from_seq, events:[...]}`，单批 ≤500 条，响应 `{acked_upto}` |
| `/v1/memories:batch` | POST HTTPS | 记忆投影回退；body `{from_id, memories:[...]}`，单批 ≤500 条，响应 `{mem_acked_upto}` |
| `/v1/snapshot` | POST HTTPS | world_state 日快照；body `{sim_day, digest, state}`，按 `sim_day` 幂等覆盖 |
| `/v1/digest` | POST HTTPS | 本机每日 digest **主动推送**端点（评审二轮 P2-7：本机零入站，"云端发起"拉取不可行）；body `{sim_day, events:{count, sum_seq, digest}, memories:{count, sum_id}, snapshot_digest}`，云端收后与本端自算值逐日比对（§9.2） |
| `/v1/health` | GET | 副本库 max(seq)、摄入延迟、最近 digest 校验结果 |

约定：**鉴权**——`Authorization: Bearer $WSIM_INGEST_TOKEN`，云端只存 token 的 SHA-256 哈希，TLS 强制。**幂等**——副本库 `events.seq` 全局唯一索引，`ON CONFLICT (seq) DO NOTHING`；`memory_projection.memory_id` 同理；快照按 `sim_day` 覆盖。乱序批拒绝（`from_seq` 必须等于 `max(seq)+1`，否则 `409 {expected_seq}` 由本机重发）；追平模式流水化产生的窗口内乱序由副本库缓冲（8 批）排序，超窗按乱序拒绝。**schema 校验**——逐事件校验 `schema_version=1` 与必填字段，不合格整批 `nack` 记日志，不静默丢弃。**副本库 schema 不与主库共用 DDL**（评审 P0-1）：原始层 = `events`（白名单列）+ `memory_projection` + `world_state_snapshot`，派生层 = `relation_change_log` / `relation_daily` / `health_daily` / `ripple_edge`——逐表定义、产生方与刷新频率见 05；观察端只读账号见 05 §5。

### 9.2 副本一致性校验与延迟预算

每日凌晨（本机 batch 段与 04:10 备份完成之后）由**本机主动推送** digest 到 `/v1/digest`（§9.1；本机零入站、云端无法发起拉取，评审二轮 P2-7），云端对同一"**同步规范形**"自算并逐日比对（评审 P1-3）：payload 先经键白名单剥除 `text_raw` 等内部键（键标注见 06 注册表），再做 canonical JSON（UTF-8、键递归字典序、无冗余空白，两端同一实现，05 §2.2）——**绝不对 `payload::text` 直接 hash**（jsonb 键序不保证，且本机含 `text_raw` 而副本物理剥除，直接 hash 必致每日"不一致→全量重传"死循环）。按 `date(sim_time)` 分组：`COUNT(*)`、`SUM(seq)`、`sha256(string_agg(md5(canonical_payload), '' ORDER BY seq))`；内容无关的快速校验可只用 `COUNT(*)/SUM(seq)`。**比对窗口截止 T-2 模拟日**（T = 当前模拟日，评审二轮 P2-7）：最近 2 个模拟日可能有追平在途与安全管线时滞（`memory_projection` 只计"已出行"——`content_display` 未过审的行两侧同时缺席，强行比对必致假不一致），不参与比对，定稿后自然滚入窗口。`memory_projection` 用 `COUNT(*)/SUM(memory_id)`（投影行不可变，无需内容 hash，同一"已出行"过滤口径两端一致，05 §2.2）；`world_state_snapshot` 复核快照自带 `digest` 字段。不一致 → 该日全量重传（删该日数据重灌，append-only 使重灌安全；派生表按 05 §4.3 随重灌重算）。结果写入审计日报。**W1 演练必过项**（§13）：人为删改副本库一行 → 校验报不一致 → 当日重灌 → 复检一致，闭环走通方算 W1 达标。

| 链路 | 预算 |
|---|---|
| 事件落主库 → 发出 batch | ≤2s（攒批窗口） |
| 传输 + 副本库提交 | ≤1s（正常态） |
| 副本库 → Web WS 推送 | ≤1s；对话逐句播放由客户端按 `payload.lines[].at_offset_s` 与自身倍率驱动（§6.4），不受复制延迟影响 |
| **端到端（事件→观众可见）** | **p95 ≤5s（黄金档）；追平模式不承诺** |
| 追平吞吐 | ≥2000 events/min（按"断网 1 真实日 ≈3 万事件、15 分钟追平"规划；事件量为容量假设，W2 实测回填校准） |

## 10. 审计与健康度

### 10.1 每日自动审计 SQL（凌晨 batch 段后跑，结果落审计日报）

> **审计样例立法（评审二轮 P2-2）**：每条审计 SQL 必须随附一个**已知违规样例**——构造一批确定违规的数据入库，该条审计**必报红**；样例数据与 SQL 同入 `audit/` 目录并进 CI 常跑。无样例或样例不触发报警的审计条目不得上线：静默全绿的死检查（如修复前 ③ 的 `GROUP BY` 错误）比没有检查更危险——它给出虚假的安全感。

```sql
-- ① 余额守恒：全体余额 = 初始注资 + Σ 经济域事件结算额（amount_cents 带符号）
--    经济域类型集合唯一持有方 = 06 注册表（审计域=economy 标记，06 §1.3），审计进程从
--    config/event_types.yaml（06 导出生成，§1.5）读入 :economy_types——禁止按
--    'economy.%' 前缀对账（agent.eat/shop/trade_stock、social.give_gift/borrow_money/repay_money
--    等动作域结算类型带 economy 审计标记但不带 economy 前缀，前缀法系统性漏账）
SELECT (SELECT SUM(balance_cents) FROM agents) AS actual,
       (SELECT SUM((payload->>'amount_cents')::bigint) FROM events
         WHERE type = ANY(:economy_types))
       + :initial_fund AS expected;
-- ② 不在两地/瞬移：同一 agent 相邻两次 move，后一次的 from 必须等于前一次的 to
--   （旧口径"5 模拟分钟内出现在互斥地点"把合法的连续移动/换乘误判为穿帮，废弃）
WITH mv AS (
  SELECT e.seq, u.agent_id, e.location_id AS to_loc, e.payload->>'from' AS from_loc,
         LAG(e.location_id) OVER (PARTITION BY u.agent_id ORDER BY e.sim_time, e.seq) AS prev_to
  FROM events e CROSS JOIN LATERAL unnest(e.actors) AS u(agent_id)
  WHERE e.type = 'agent.move')
SELECT agent_id, seq FROM mv
WHERE prev_to IS NOT NULL AND from_loc IS DISTINCT FROM prev_to;
-- ③ 双人记忆同源：同一 dialogue.chat 事件的同一参与者，窗口内对话投影记忆
--    必须指向唯一源事件（"同 agent 同事件双投影比对"，按 m.agent_id 分组）。
--    评审二轮 P2-2：旧写法 GROUP BY m.source_event_seq 组内恒 1 行、
--    COUNT(DISTINCT) 恒 1、EXISTS 永假——死检查，已废。
--    已知违规样例（必报红）：同一对话被错误落成两条 dialogue.chat（seq x、y），
--    参与者 A 的记忆同时含 source_event_seq=x 与 =y 的投影 → 本查询命中 (y, A)。
SELECT e.seq, m.agent_id
FROM events e
JOIN memories m ON m.agent_id = ANY(e.actors)
JOIN events se ON se.seq = m.source_event_seq AND se.type = 'dialogue.chat'
WHERE e.type = 'dialogue.chat'
  AND m.sim_time BETWEEN e.sim_time - interval '1 hour' AND e.sim_time + interval '1 hour'
GROUP BY e.seq, m.agent_id
HAVING COUNT(DISTINCT m.source_event_seq) > 1;
-- ④ 干预率 <15%（滚动 7 模拟日）
SELECT COUNT(*) FILTER (WHERE trigger='director')::float / COUNT(*) AS intervention_rate
FROM events WHERE sim_time > now_sim() - interval '7 days';
-- ⑤ LOD 记录完整：快照对比 tier 变动须有对应 agent.promoted/agent.demoted 事件，
--    且升入明星层后 1 模拟日内有追赶反思（§4.3）
-- ⑥ 缓存对账（§6.5）：agents.needs/mood 缓存值 == 初始值 + Σ state.needs_delta 重算值（抽样 5 人）
```

任一不过 → 报告标红 + 告警；连续 3 天不过 → 暂停时钟进人工（宁可停，不带病跑，呼应"门禁不达标顺延"）。

### 10.2 叙事健康度指标（计算口径：五项基础指标 + 01 §9 两项结构指标）

> **阈值数字唯一持有方 = 01 §9**（评审 P1-1）：本文与 03 只持有计算口径，不各自持有数字；W2/W4 门禁复测校准阈值时只改 01 §9 并同步引用点。

| 指标 | 口径（本文持有） | 阈值 |
|---|---|---|

### 11.1 内容三层过滤管线（剪辑/观察端形态，源方案 §10）


### 11.2 双通道分离与密钥管理

`events.visibility` 与双文本字段构成内外双通道（字段级规则见 03 §7，评审 P0-1 后口径如下）：**观察端与切片只消费展示通道**——事件 `payload.text_display`、记忆 `content_display`（经 `memory_projection`，05 §3.2）、状态快照中的需求/情绪数值。**永不出站（本机-only）**：`payload.text_raw`、`memories.content` 原文、embedding 向量、`llm_calls` 明细、`interventions` 审计明细、prompt/检索上下文。`visibility='internal'` 的事件（含 `state.needs_delta`、`relation.changed`、`time.*`、`system.llm.*`）**元数据与结构化 payload 仍同步出站**（回放/健康度/涟漪/调试依赖），只是不带展示文本、前端非调试态不渲染。角色详情页的"最新反思"来自 `memory_projection` 中 `kind='reflection'` 行的 `content_display`（反思落库时同时生成一句对外口径）。

密钥管理：**所有云端 LLM API key（DeepSeek/GLM/Kimi）只存本机** `/etc/worldsim/worldsim.env`（权限 600，属主 worldsim），云端不持有任何 LLM key——云端被入侵 ≠ LLM 账单被盗刷。云端仅持有：副本库 DSN、ingest token 哈希、切片存储凭据，分别独立可轮换。密钥不进 git、不进日志（`llm_calls` 只记 `prompt_hash`）；轮换流程：新 key 写 env → `systemctl reload worldsim-kernel` → 旧 key 作废。

## 12. 运维

### 12.1 日志分级与快照/备份策略

| 级别 | 内容 | 去向 |
|---|---|---|
| DEBUG | 检索配额命中、校验器判定明细 | 本地文件日轮转留 7 天，默认不开 |
| INFO | tick 节律、事件落库计数、sync 批/ack、LOD 升降格 | journald + 文件留 30 天 |
| WARN | 重试、降级链切换、熔断报警、审计单项不过 | + 告警通道（聚合 15 分钟） |
| ERROR | 落库失败、schema 校验失败、时钟暂停 | + 告警通道（立即） |

LLM prompt/响应全文不进日志（在 `llm_calls` 关联查），日志只记 `request_id`。

快照/备份策略：

| 类型 | 频率 | 保留 |
|---|---|---|
| 快照（world_state/agents/relations/goals 全量 JSON gzip） | 每模拟日结束 | 本地 14 天，云端 90 天；字段白名单子集同时经快照流实时送副本库 `world_state_snapshot`（§1.3、05 §3.6） |
| pg_dump（custom 全库） | 每真实日 04:10 | 本地 7 天，云端 30 天 |

推送：备份完成后经出站 HTTPS（rclone/restic）推云端；断网顺延，恢复后补推。

### 12.2 故障恢复 runbook

| 故障 | 处置 |
|---|---|
| 云端 LLM API 故障/限流 | 网关降级链自动走（§8.2）；全部 provider 熔断 → §3.2 暂停时钟，恢复后追平 |
| 断网 | 内核照跑（§1.3）；恢复自动追平；>24h 人工确认 digest 校验 |
| 主库宕机/损坏 | 停内核 → 最近 pg_dump 恢复 → 快照 + 事件流重放（`REPLAY_MODE=replay`）补齐 → digest 校验 → 重启。RPO ≤1 真实日；当日已 sync 部分可从副本库只读导出反向灌回（人工执行） |
| GPU 整机重启 | systemd 拉起 vLLM 三实例 → kernel `After=` 依赖启动 → 时钟从 `world_state` 锚点恢复 → §3.2 追平 |
| 云端机器故障 | 本机不受影响；云端恢复后 hello 握手报 max_seq，本机从断点重发 |

### 12.3 监控告警

最小集（systemd + 内核 metrics 端点 + 云端探针）：内核存活；sync 滞后（`max(seq) − last_acked_seq > 5000` 或延迟 >5 分钟）；黄金档 30 分钟无事件；¥/模拟日熔断两级；GPU 显存 >90%；磁盘 >80%；审计标红；副本 digest 不一致。通道：Webhook 到个人 IM。

### 12.4 配置热更（SIGHUP，评审 P2-9）

改阈值/价格不必重启内核（重启会触发时钟暂停 §3.2）。`worldsim-kernel` 收到 `SIGHUP` 时热重载：

- `config/models.yaml`：LLM 路由/价格/生成参数（§8）——改价即刻生效于 `llm_calls` 计量；
- 阈值表：熔断线倍数、轮换 `PROMOTE_IN/DEMOTE_OUT`、反思阈值、健康度指标告警阈值等，集中 `models.yaml` 的 `thresholds:` 段（数字口径仍以 01 §9/本文为源，配置文件是其部署镜像）；
- `config/speed_table.yaml`：变速表在**下一个段边界**生效（当前段不中断，§3.1）；
- `/etc/worldsim/worldsim.env` 中的密钥项：进程自行重读（`systemctl reload` 不会重读 `EnvironmentFile`，密钥轮换流程见 §11.2）。

reload 校验失败（YAML 语法、§3.1 `min_sim_days_per_real_week` 等约束）→ 保留旧配置并 WARN 告警。systemd 侧 `systemctl reload worldsim-kernel`（`ExecReload=/bin/kill -HUP $MAINPID`，§1.4）。DSN/token 等连接类配置仍需重启生效。
