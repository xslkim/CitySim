## 0. 部署上下文与技术选型

### 0.1 部署上下文（硬约束）

观察端部署在**云端公网机**，数据链路：

```
本机 GPU 机（NAT 后，零入站端口）
  └─ 模拟内核 ──出站 HTTPS/WSS 推事件──► 云端摄入 API ──► 云端事件副本库(PostgreSQL)
                                                            │ 只读
                                    Web 客户端 ◄──WS/REST── 观察端服务(nginx + 只读 API/WS 网关)
```

- 观察端服务**只连接云端副本库，永不回连本机**。断网期间本机正常跑、事件堆积，恢复后批量追平副本库——观察端因此对"副本库延迟于内核"完全无感，设计上把副本库当唯一事实源。
- 观察端感知到的"现在"本来就是内核的"过去"（源方案 §3.4 呈现/内核时间偏移），断网追平只是把这个偏移拉大，语义不变。UI 顶部常驻 `数据延迟：副本 tick - 最新事件 tick` 指示条。

### 0.2 技术选型（定死版本与理由）

| 项 | 选型 | 版本 | 理由 |
|---|---|---|---|
| 框架 | React + TypeScript | React 18.3 / TS 5.5 | 团队（单人）最熟生态；并发特性用不上但 18 的 `useSyncExternalStore` 是接 Zustand 与 WS 增量合并的标准姿势 |
| 构建 | Vite | 5.x | dev 启动 <300ms；库模式与单页构建都够；不引入 Next.js——没有 SEO 与服务端渲染需求，纯内部工具/订阅产品形态 |
| 状态管理 | Zustand | 5.x | 事件流是高频外部队列，Redux 的 action/reducer 模板是负担；Zustand 可在 React 外读写 store，WS 回调直接 `store.setState`，绕过组件树 |
| 样式 | Tailwind CSS | 3.4 | 单人开发免去命名与样式文件切换；三栏布局、卡片、告警色全是 utility 一把梭 |
| 地图渲染 | **SVG + CSS transform**（门禁③ 前）→ 预留 Canvas/精灵图切换 | — | 源方案 §6 明定"先用简洁 SVG/格子图，像素美术是门禁③ 之后的事"。SVG  DOM 可点选、可吸附事件委托、调试可见，40 个 Agent + 30 个地点节点远低于 SVG 性能红线（~1k 动态节点）；切 Canvas 时只换渲染层，数据层（坐标/布局描述 JSON）不动 |
| 关系图与曲线 | **Apache ECharts 5.5** | 5.5 | 关系结构演化要 force graph + 时间轴动画 + 双曲线图，ECharts 的 `graph`+`timeline`+双 y 轴 line 开箱即用；D3 自由度更高但单人开发要把力导向、缩放、tooltip 全手写，不值。涟漪追踪的传播树是定制布局（分层 DAG + 失真标注），ECharts 树图不够，用 **D3-hierarchy 算布局 + SVG 自绘**——只用 D3 的布局算法不用其 DOM 绑定 |
| WebSocket | 原生 `WebSocket` 自封装（~150 行） | — | 不引 socket.io：它绑定服务端实现，而我们服务端是 Python；协议自己定（§5），需要 resume-from-tick、心跳、指数退避，socket.io 的机制反而对不上 |
| 表格/虚拟列表 | `@tanstack/react-virtual` 3.x | — | 事件时间轴/事件流可能滚动上万条，必须窗口化 |
| 测试 | Vitest + React Testing Library（store 合并逻辑与协议解析的纯函数测试为主） | — | UI 组件不做重测试，调试工具阶段 ROI 低 |

## 1. 产品定位与信息架构

### 1.1 定位

观察端是目标②"观察这个小社会"的载体，也是开发期**唯一的调试手段**（源方案 §1.3）。两个身份决定信息架构：

- **观察者视角**：跟拍角色、看关系演化、追八卦传播——读故事的界面。
- **调试者视角**：同一套数据换个切法——某事件为什么发生（trigger 链）、某角色当时看到了什么（感知注入）、涟漪是否按预期扩散（目击投影验证）、干预率是否越线（trigger 字段审计）。

因此所有页面共用一个原则：**每个 UI 元素都能反查到事件 seq**。气泡、关系边、曲线点、健康度指标，全部可点击跳到 `/timeline?focus=e1102`（`e<seq>` 引用形态，§5）。调试 = 顺着事件链走。

### 1.2 页面清单与路由表

| 路由 | 页面 | 观察者用途 | 调试者用途 | 主要数据源 |
|---|---|---|---|---|
| `/map` | 空间地图（首页） | 看全公寓/公司谁在干嘛、点气泡读对话 | 位置一致性（"不在两地"审计）、LOD 层分布 | WS 实时流 + `/api/snapshot` |
| `/agent/:id` | 角色详情 | 人设、心情、关系、今日干了啥 | 认知循环产物检查：最新反思、需求值、检索是否生效 | `/api/agents/:id` + `/api/events?actor=`（反思读 `memory_projection`，05） |
| `/location/:id` | 地点详情 | 这个房间/部门发生了什么 | 目击投影覆盖验证、场所容量校验 | `/api/events?location=` |
| `/timeline` | 事件时间轴 | 倒带看任意时段（**W3 简化回放的事件维度**，§4.2） | 全文过滤检索事件、trigger 审计 | `/api/events?from&to&type` |
| `/ripple[/:eventId]` | 涟漪追踪 | "一句话如何毁掉两段关系"；无参落地页="今日热涟漪"推荐位（§3.4） | 记忆投影数、八卦链路、失真度 | `/api/ripple/*`（读 `memory_projection`/`ripple_edge`/`relation_change_log`，05） |
| `/relations` | 关系结构演化 | 全网关系动画、两人曲线 | 关系图周变化率、负向社交动作效果 | `/api/relations` 系列（读 `relation_daily`/`relation_change_log`，05） |
| `/health` | 叙事健康度（**调试态**，§3.6） | 这剧最近好不好看 | 五指标（阈值口径 01 §9）+ 干预率 + 成本熔断状态 | `/api/health`（读 `health_daily`，05） |

导航：顶部固定导航条（6 项 + 数据延迟指示 + 当前模拟时钟 + 压缩比档位；调试态开关下追加"健康度"）。所有跨页跳转带上下文 query，如 `/agent/:id?at=<tick>`。

## 3. 核心组件详设

### 3.1 空间地图（`/map`）

**布局数据**：静态 JSON（`map_layout.json`，随前端发版），描述节点图：

```jsonc
{
  "sites": [
    { "id": "apt", "name": "单身公寓", "type": "building",
      "floors": 6, "roomsPerFloor": 4,
      "rooms": [{ "id": "apt.L3.302", "floor": 3, "col": 1, "w": 80, "h": 64 }],
      "commons": [{ "id": "apt.lobby" }, { "id": "apt.roof" }] },
    { "id": "corp", "name": "公司",
      "zones": [{ "id": "corp.tech" }, { "id": "corp.market" },
                { "id": "corp.pantry" }, { "id": "corp.meeting" }] },
    { "id": "ext", "name": "外部", "zones": [{ "id": "ext.restaurant" }] }
  ]
}
```

- 公寓渲染为 6×4 网格 + 走廊横带，公司为分区平面；三个 site 用顶部 tab 切换（同屏只渲染一个 site，降低 SVG 节点数）。
- **坐标系对齐（02 §1.1.1 铁律）**：阶段 0 逻辑网格 = 阶段 1 tile 网格的整数分之一（统一换算因子 4：房间 80×64 逻辑单位 ↔ 320×256 像素，1 tile=32px=8×8 单位，双向整数）。门禁③ 切像素美术时逻辑坐标 ×4 整数换算，布局 JSON 不动。
- **像素渲染**：切像素皮肤后，精灵图与 tile 一律 `image-rendering: pixelated` + 整数倍最近邻缩放，禁双线性模糊（02 §8.4）。
- **缩放平移**：一个外层 `<g transform="translate(x,y) scale(k)">`，滚轮缩放（0.5×~4×）、拖拽平移、双击归位。所有角色名牌/气泡反缩放（`transform: scale(1/k)`）保证文字恒定字号。
- **角色名牌与气泡**：每个 Agent 一个 `<g class="pawn">`：圆形头像占位（门禁③ 后换精灵图）、下方名牌（姓名+LOD 徽标）、头顶气泡。气泡三态：`💬对话中`（双人连线）、`💭内心/反思`（灰虚线框，调试态才显示全文）、`📢公告波及`。
- **对话播放节奏**：对话整段已在内核生成完并落库（6~8 轮，源方案 §3.4），观察端收到的是**完整事件**，逐句相对时刻在 `events.payload.lines[].at_offset_s`（内核生成时按每句 2~4s 写入，独立 `presentation_queue` 通路已取消，见 04 §6.4 / 05）。**客户端播放倍率是唯一节拍权威**：逐句弹气泡的实际间隔 = 相邻 `at_offset_s` 差值 ÷ 当前倍率；服务端不做逐句推送。正在播放的对话气泡带进度点 `●●○○○`。
- **跟拍模式**：勾选后，被跟拍角色移动时中栏视口平滑跟随（`requestAnimationFrame` 插值），角色进另一 site 自动切 tab。跟拍中右栏锁定该角色摘要卡。
- **移动动画**：`agent.move` 事件到达时，pawn 沿节点间直线 300ms 缓动；跨 site 移动淡出/淡入。倍率 >2× 时跳过动画直接跳变（防队列堆积）。
- **调试叠加层**（快捷键 `d` 切换）：显示每个房间当前在场人数与 `location_id`、事件 id 悬浮 tooltip——直接服务"不在两地"审计的目检。

### 3.2 事件时间轴（`/timeline`）

- **数据**：REST 分页拉取（§5.1 `/api/events`），live 模式下 WS 增量追加。
- **倒带浏览**：scrub bar 以模拟时间为轴；拖到过去 → 自动从 live 切到历史模式（顶部"跳至 live"按钮提示），再拖回右端恢复订阅。

### 3.4 涟漪追踪（`/ripple/:eventId`，独有功能）

源方案 §6 明确要求：选中任意源事件，可视化其扩散——记忆投影数、八卦几手传到谁、内容失真、后续事件链、最终改变的关系边。

**数据查询逻辑**（云端副本库 SQL，封装为 `/api/ripple/:eventId` 单接口，避免前端多次往返）。只读 05 契约清单中的物化表——`events`(白名单) / `memory_projection` / `relation_change_log` / `ripple_edge`；`:e0` = 源事件 seq（URL 中 `e<seq>` 去掉前缀）：

```sql
-- 1) 直接投影：哪些 Agent 的记忆含来源事件 e0（双人单源投影 + 目击投影）
SELECT m.agent_id, m.memory_id, m.importance, m.is_witness, m.content_display
FROM memory_projection m WHERE m.source_event_seq = :e0;

-- 2) 八卦传播链：直接读 05 物化的 ripple_edge（按源事件预聚合的传播边，hop ≤ 4）
SELECT dst_event_seq, teller_id, listener_id, hop, distortion, sim_time
FROM ripple_edge WHERE root_event_seq = :e0 ORDER BY hop, sim_time;
-- ripple_edge 的派生口径（由 05 持有并物化，此处仅说明观察端假设）：
--   从 memory_projection.source_event_seq = :e0 的记忆出发，找 payload.cites
--   引用这些记忆 id 的 agent.gossip 事件，沿同一规则递归，深度上限 4 手
--   （gossip 传播深度统一 4 手，01 §4.1；type 命名以 06 注册表为准）。

-- 3) 失真度：ripple_edge.distortion 已由 05 离线任务预计算
--    （每手 gossip 展示文本与源事件展示文本的编辑距离/语义相似度），前端只读。

-- 4) 后续事件链：payload.caused_by = e0 或链上任意事件 seq（裁决因果）
SELECT seq, type, sim_time, payload FROM events
WHERE (payload->>'caused_by')::bigint IN (:e0_plus_chain) ORDER BY sim_time;

-- 5) 关系边变化：链上事件引发的 relation 变更日志
SELECT a_id, b_id, delta_affinity, delta_tension, event_seq
FROM relation_change_log WHERE event_seq IN (:chain_seqs);
```

> 数据依赖**已由 `05-云端物化层设计.md` 承接**（本节原为"向上游提出的依赖"）：上述物化表的产生方（sync 直传 / 摄入任务派生 / 从 events 投影）、刷新频率与脱敏规则均由 05 定义。字段级要求保留如下（05 必须满足，观察端硬依赖）：
>
> - `memory_projection` 行含 `agent_id / memory_id / source_event_seq / is_witness / importance / content_display`，且覆盖 `kind='event'|'projection'|'reflection'` 各类记忆（"最新反思"同样查此表，§3.3）；
> - gossip 事件 `payload.cites` = 引用的记忆 id 列表（传播链的唯一依据）；
> - 被事件直接触发的事件 `payload.caused_by` = 前因事件 seq；
> - `ripple_edge` 行含 `root_event_seq / dst_event_seq / teller_id / listener_id / hop / distortion / sim_time`；
> - `relation_change_log` 行含 `a_id / b_id / delta_affinity / delta_tension / event_seq`。
>
> 全部 append-only、payload 内扩展，符合 Schema v1 扩展方向（不改顶层字段）。

## 4. 回放

### 4.1 语义锚定

源方案 §3.3 写死：**可回放 = 重放事件流（replay），不是重算世界（recompute）**。任何回放形态都只消费 append-only 事件流与其物化投影，不重跑规则/LLM——回放所见 = 当时所发生（同一份 append-only 事件）。

### 4.2 W3 交付：简化回放（时间轴倒带 + 地图按 tick 重建）

**W3 不建独立回放页与回放引擎**（评审 P1-6：源方案 §9 的 W3 范围本就不含回放页；独立引擎的 ~25 个 reducer 与 seek <500ms 指标超出单人 1 周的现实工期，省下的时间正是内核最需要的 buffer）。W3 用两个既有页面的组合覆盖"补看"需求：

- **事件维度**：`/timeline` scrub bar 倒带到任意时段，事件流、过滤、详情照常可用（§3.2）。
- **状态维度**：`/map` 底部 scrub bar 拖到历史 tick t → 请求 `GET /api/snapshot?tick=t`（服务端取 ≤t 的最近 `world_state_snapshot` + 其间事件增量合并，物化表契约见 05）→ 地图 pawn/名牌/在场人数静态重建该时刻投影；拖回右端或点"跳至 live"恢复 WS 订阅。

**简化版能力边界（写死，防范围爬行）**：

1. 只支持"跳到某 tick 看静态世界投影 + 读当时事件流"，**不做**播放/暂停/seek 的连续状态机动画；
2. 历史时刻的对话显示整段完成文本，不逐句重播；
3. 重建字段以快照字段为准（位置/情绪/需求/关系/经济），不承诺 reducer 全覆盖；
4. 无 seek <500ms 硬指标——目标尽力 ≤2s（副本库局域查询 + 快照间距 1 模拟日，事件量双档见 §6.3）；
5. "重放事件流复现 bug 现场"由 `/timeline` 过滤 + 事件详情（trigger / `payload.caused_by` 链）承担，不需要状态动画。

**正确性自检**：服务端 `/api/snapshot?tick=` 合并结果每日与下一份 `world_state_snapshot` diff，字段级不一致即告警——该 diff 进 CI 常跑（§8.2），同时充当事件落库完整性的回归测试。

### 4.3 完整回放引擎（backlog：W5+ 或门禁③ 之后）

完整形态移出 W3，届时单独立项验收，预登记范围如下（**本期不实现**）：

- 独立 `/replay` 页 + 回放控制台（wireframe §2.2(g)）；状态机 `idle / loading / playing / paused / seeking`；任何状态下 scrub 到尾部可"追上 live"（退出回放回到 WS 订阅）。
- **快照 + 增量连续重建**：`world_state_snapshot`（05 物化，每模拟日 00:00 落全量世界状态 JSONB：40 人位置/需求/情绪/关系矩阵/经济；体积 ≈ 40 人 × ~2KB ≈ 80KB/份，月 30 模拟日 ≈ 2.4MB）+ 快照后事件按序应用（事件 → 状态归约器 `reduce(state, event)` 纯函数，约 25 个 reducer，只覆盖影响 UI 的字段：位置、情绪、需求、关系、对话气泡、公告）。
- **seek <500ms**（副本库局域查询）：向后 seek 取目标 tick 前最近快照 + 应用其间事件增量——单模拟日事件数估算 **1,500~2,500**（明星层 ~768 + 次要层 ~144 + 背景层 ~40 + 对话等，源方案 §5.2 同量级），**W2 用 8 人世界实测回填**；预算按区间上下限**双档设计**：上限档最坏 ~2,500 个 reducer × <0.05ms ≈ <150ms 达标，下限档 ~1,500 则 <100ms。向前 seek 直接消费队列推进；落地后预取前后各 1 模拟日快照+增量（LRU 4 份）。
- **双实现 diff 自检进 CI 常跑**（评审 P2-10）：服务端 `/api/snapshot?tick=` 与客户端引擎是同一 `reduce` 语义的两套实现，字段级 diff 不一致即构建失败（W3 期间先跑 §4.2 的服务端单边 diff）。

## 5. 数据协议（核心章节）

协议双层：**REST 拉快照/历史，WS 推增量**。时间字段双写：`tick`（裁决节拍整数）与 `sim_time`（ISO-8601 模拟时间，展示用）。

**标识与排序口径（跨文档统一，评审 P1-2）**：事件的唯一标识是 DB 主键 `seq`（BIGINT，全局单调，04 §5.2）；叙事/日志/UI 中的事件引用形态为 `'e<seq>'`（如 e1102）。同一 tick 可落多个事件，故**排序、续传、去重、分页 cursor 一律以 `seq` 为准**；`tick`/`sim_time` 用于时间轴展示与时段定位。Agent 标识全链路统一为字符串 `'A01'~'A40'`（DB TEXT / 人设 YAML / UI 同形，01 §2.2）。事件类型命名遵循 `<domain>.<object>[.<verb>]`，**注册表唯一持有方是 `06-契约登记表.md`**——本文出现的 type 取值以 06 定稿为准同步，不自行登记。

事件顶层字段与源方案 §3.3 Schema v1 一致（工程字段见 04 §5.1/§5.2）：语义字段 `tick / sim_time / type / source / payload / rng_seed / trigger / arc_id`；**UI 展示字段统一收敛在 `ui` JSONB**（如 `ui.grade`，04 §5.2 `ui` 列）。观察端只消费 `payload` 与 `ui`，不要求改顶层。

### 5.1 REST 接口（全部只读，云端 API 网关 → 副本库）

通用约定：响应包 `{ "ok": true, "data": ..., "meta": { "watermark_tick": 12345 } }`；`watermark_tick` 为副本库当前已同步的最大 tick，客户端据此判断"看到的有多新"。错误 `{ "ok": false, "error": { "code": "...", "message": "..." } }`。分页统一 `cursor`（上一页末条 **seq**，全局单调无并列）+ `limit`（≤500，默认 200）。

**GET /api/snapshot?tick=**
> 世界状态全量投影。无参数 = 最新；带 tick = 取 ≤tick 的最近 `world_state_snapshot`（05）+ 增量合并（服务端完成——W3 简化回放 §4.2 的唯一状态数据源）。

```jsonc
// data

  "compression_ratio": 3.2,            // 当前内核压缩比档位（源方案 §4.1）
  "agents": [{                          // 40 人，UI 状态子集
    "id": "A07", "name": "林小满", "lod": "star",        // id 形态 'A01'~'A40'；star|secondary|background
    "location_id": "corp.pantry", "activity": "chatting",
    "mood": 72,                         // 情绪 0~100
    "needs": { "hunger": 40, "energy": 55, "mood": 72,
               "social": 80, "achievement": 61, "wealth": 35 }
  }],
  "economy": { "stock_index": 1012.4 },
  "active_dialogues": [{ "event_seq": 1102,              // UI 引用形态 e1102
                         "participants": ["A07","A12"],
                         "location_id": "corp.pantry",
                         "lines": [{ "speaker": "A07", "text_display": "今晚约吗?",
                                     "at_offset_s": 0 }, "..."] }] // 整段落库+逐句相对时刻（§3.1）

```

**GET /api/agents** → 40 人列表（人设摘要字段）。
**GET /api/agents/:id** → 人设卡全字段（含 Big Five、经历、目标、标志性视觉符号）。

**GET /api/agents/:id/schedule?day=** → 指定模拟日日程。
**GET /api/agents/:id/reflections?limit=** → 最近反思（**仅 display 字段**，§7）；副本库侧查 `memory_projection WHERE agent_id=:id AND kind='reflection' ORDER BY sim_time DESC`（表契约见 05）。

**GET /api/events?from=&to=&type=&actor=&location=&trigger=&grade=&q=&cursor=&limit=**
> 时间轴主查询。`from/to` 接受 tick 或 sim_time；`type` 逗号分隔多值（注册表见 06）；`trigger` 枚举含 `system`；`grade` 匹配 `ui->>'grade'`。`q` 匹配展示文本——**中文全文索引用 zhparser（SCWS 分词；备选 pg_jieba）建 `to_tsvector('zh', text_display)` 索引**；云端无法安装分词扩展时降级 `pg_trgm` 三元组索引兜底（召回粗但中文可用，评审 P2-8；原生 `to_tsvector('english', …)` 对中文不分词，禁用）。

```jsonc
// data.items[] —— 单条事件的协议形态（所有推送/查询共用此 schema）
{
  "seq": 12338,                        // 唯一标识（DB 主键）；UI 引用形态 "e12338"
  "tick": 12338, "sim_time": "2026-10-12T19:38:11+08:00",
  "type": "agent.chat",                // <domain>.<object>[.<verb>]，注册表见 06
  "source": "agent:A07",               // 'agent:<id>' | 'world' | 'director' | 'system'（04 §5.2）
  "trigger": "autonomous",             // autonomous|world|director|gift|vote|system
  "arc_id": "arc_crush_01",
  "ui": { "grade": "A" },              // UI 展示字段统一在 ui.* 下；grade A|B|C（01 §6.4 规则自动判定 + 编剧复核，A级=可剪辑）
  "payload": {
    "location_id": "corp.pantry",
    "participants": ["A07", "A12"],
    "witnesses": ["A21"],              // 目击投影对象（源方案 §4.5 / 04 §6.3）
    "text_display": "林小满压低声音问王强：今晚约吗？",  // 展示通道（§7）
    "caused_by": 1089,                 // 因果链：前因事件 seq（UI 渲染 e1089，涟漪追踪依赖）
    "distortion": null                  // gossip 事件才有：与源事件失真度 0~1
  }
}
```

**GET /api/events/histogram?from=&to=&bucket=sim_hour** → `[{bucket_start, count, a_count}]`。
**GET /api/ripple/today** → "今日热涟漪"推荐位（§3.4）：当前模拟日 `ui.grade='A'` 事件按涟漪统计排序 Top 5。
**GET /api/ripple/:eventId** → §3.4 五段查询的聚合结果 `{projections[], chain[], followups[], relation_changes[], stats{...}}`（读 `memory_projection` / `ripple_edge` / `relation_change_log`，05）。
**GET /api/relations/snapshots?from=&to=&step=** → 每日关系矩阵（40×40 有序对，稀疏编码：只返回非零边 `[{a,b,aff,ten,label}]`；读 `relation_daily`，05）。
**GET /api/relations/pair?a=&b=&from=&to=** → 双向 affinity/tension 时序 + 关键事件标记（`relation_change_log` 按对聚合，05）。
**GET /api/health** → 五指标当前值 + **阈值（随响应下发，阈值唯一持有方 01 §9）** + 阈值色 + 干预率 + ¥/模拟日 + 副本延迟（读 `health_daily` + 实时小查询，05）。

完整回放引擎的专用数据源（`/api/replay/*`）随 §4.3 移入 W5+ backlog，届时再定；W3 简化回放只依赖上文的 `/api/snapshot?tick=` 与 `/api/events`。

### 5.2 WebSocket 通道（`/ws`，wss 强制）

**连接与订阅**（客户端 → 服务端）：

```jsonc
// 1) hello（连接后首帧）
{ "op": "hello", "token": "dev_xxx", "client": "obs/1.0.0" }
// 服务端 → 客户端
{ "op": "welcome", "watermark_tick": 12340, "server_time": "...",
  "session_id": "s_abc" }

// 2) subscribe：声明兴趣集（服务端按此过滤推送，降带宽）
{ "op": "subscribe", "channels": [
    { "name": "events", "filter": { "types": [], "actors": [],
        "locations": [], "grades": [] } },   // 空=全量；types 注册表见 06，grades 匹配 ui.grade
    { "name": "world_state" },               // 位置/情绪等轻量差分
    { "name": "health" }                     // 每分钟一次
] }
```

**事件推送**（服务端 → 客户端）：

```jsonc
{ "op": "event", "seq": 88421, "data": { /* §5.1 单条事件 schema */ } }
{ "op": "state_diff", "seq": 88422, "data": {
    "tick": 12341,
    "agents": [{ "id": "A07", "location_id": "apt.L3.302", "mood": 70 }] } }
{ "op": "health", "seq": 88423, "data": { /* 同 /api/health */ } }
```

**断线重连与 resume**：

- 客户端记录已收最大事件 `seq`；重连后 hello 中携带 `{ "last_seq": 12338 }`，服务端按 seq 补推（seq 全局单调，无同 tick 并列问题）。
- 缺口小（服务端内存环缓冲覆盖，默认 10,000 事件 ≈ 4~6.7 模拟日——按事件量 2,500/1,500 双档估算，W2 实测回填后复核容量）：服务端直接补推缺口段，再接 live。
- 缺口大（环缓冲不够，如断网追平场景）：服务端回 `{ "op": "resync_required" }`，客户端丢弃内存态，走 `/api/snapshot?tick=latest` 全量重建——与 §4.2 简化回放复用同一服务端合并路径。
- 心跳：客户端每 30s `{ "op": "ping", "t": ... }`，服务端 `pong`；90s 无心跳服务端断开。重连指数退避 1s→2s→…→30s 封顶，带 ±20% 抖动。

## 6. 状态管理

### 6.1 store 划分（Zustand，React 外可写）

| store | 职责 | 写入方 |
|---|---|---|
| `worldStore` | 当前世界投影：agents 位置/情绪/需求、经济、活跃对话、`watermark_tick`、副本延迟 | WS `state_diff`、snapshot 响应 |
| `agentsStore` | 40 人静态档案 + 按需详情缓存（LRU 20 人） | REST |
| `timelineStore` | 时间轴窗口：事件环形缓冲（容量 3,000，≈1.2~2 模拟日——按事件量 2,500/1,500 双档估算，W2 实测回填后复核）、过滤条件、live/历史模式 | WS `event` + REST 历史页 |
| `rippleStore` | 当前涟漪查询结果（一次只查一个源事件） | REST |
| `uiStore` | 路由上下文、选中角色/地点、跟拍、调试叠加层、播放倍率 | 用户操作 |

### 6.2 事件增量合并规则

1. 所有事件按 `seq` 升序进入 `timelineStore`；乱序（resume 补推与 live 交错）按 seq 插入排序，重复 `seq` 去重（append-only 语义保证幂等）。
2. `state_diff` 按 tick 顺序 apply 到 `worldStore`；`diff.tick <= worldStore.tick` 直接丢弃（快照重建后的旧推送）。
3. 快照重建（resync / §4.2 历史时刻重建）：先整体替换 `worldStore`，再令 `timelineStore` 只保留 ≥快照 tick 的事件。
4. 气泡播放队列与事件队列分离：对话事件到达只入队"剧本"（含 `lines[].at_offset_s`），播放由 `uiStore` 的倍率时钟驱动——**客户端倍率是唯一播放节拍权威**（P2-7），暂停/倒带不影响数据完整性。

### 6.3 40 人规模性能预算

| 指标 | 预算 | 手段 |
|---|---|---|
| 地图帧率 | ≥55fps（40 pawn + 气泡动画同屏） | pawn 组件 `memo`，坐标变化走单 `<g>` transform，不触发 React 重渲染整树；>2× 倍率跳动画（§3.1） |
| 事件缓冲 | 内存 ≤3,000 条（约 5MB），≈1.2~2 模拟日（双档，见表下注） | 环形缓冲，溢出丢弃最旧段；时间轴历史滚动走 REST 分页补段；W2 实测回填后复核容量 |
| 时间轴滚动 | 万级条目不卡 | @tanstack/react-virtual，行高固定 44px |
| WS 吞吐 | 均值 <1 事件/真实秒；峰值预算按 2 事件/s 设计（双档上限 2,500 事件/模拟日 × 黄金档集中系数估算）；断网追平走 resync，不占本预算 | 单消息即 setState 一次；`state_diff` 服务端 500ms 合帧；W2 实测回填后复核 |
| 首屏 | <2s（4G） | 首屏只拉 `/api/snapshot` + 最近 200 事件；图表库 ECharts 按需异步 chunk |
| 内存泄漏防线 | 8h 连续开着不增长 | store 全部有界（环形缓冲/LRU）；订阅随路由切换 `unsubscribe` |

> **事件量口径（评审 P1-1）**：单模拟日 **1,500~2,500 事件**为当前估算（明星层 ~768 + 次要层 ~144 + 背景层 ~40 + 对话等，与源方案 §5.2 单价构成同量级），**W2 用 8 人世界实测回填**。回填前，环缓冲容量、seek/历史重建预算、WS 吞吐一律按区间上下限**双档设计**（上限 2,500 保容量不失真，下限 1,500 校体验指标）；04 侧按真实日口径的估算同样待 W2 实测对账，以实测值统一两处。

## 7. 双通道分离（安全合规）

源方案 §10：**观察端展示的 Agent 文本与内部记忆双通道分离**。落到字段级：

| 通道 | 字段 | 生成 | 谁能看到 |
|---|---|---|---|
| **展示通道** | `payload.text_display`、`reflection.text_display`、记忆 `content_display` | 内核内容安全管线（本地 Qwen3-4B/8B 初筛 → 云端复核，§10）**通过后**写入 | 观察端、切片素材 |
| **内部通道** | `payload.text_raw`、记忆原文、prompt/检索上下文、LLM 网关全量日志 | 认知循环原始产物 | 仅本机主库 + 开发期本机直连调试；**云端副本库不存此列** |

脱敏规则的**唯一持有方是 `05-云端物化层设计.md`**（副本库 `events` 为白名单物化表；同步白名单、`text_raw` 物理剥除、digest 适配均由 05 定义）。本节只规定观察端侧实现约束：

1. **管道级分离**（05 持有规则，此处引用）：本机→云端的摄入同步器按列白名单同步——`text_raw`、prompt 日志、embedding 向量不出本机。副本库 schema 里这些列**不存在**（不是同步但置空），从根上断绝误暴露；digest 在双方应用同一白名单后的"同步规范形"上计算，或仅覆盖 COUNT/SUM(seq) 等不依赖 payload 的量（评审 P1-3 口径，05 持有），观察端不参与 digest 计算。
2. **前端零信任**：观察端 proto 类型里只有 `*_display` 字段；即使协议被篡改注入 `text_raw`，zod 校验剥除并告警。
3. **未过审占位**：展示文本未生成/被安全管线打回时，前端渲染 `▮内容审核中▮` 占位气泡，事件本身仍可见（调试需要），但无任何原文泄漏面。
4. 门禁① 外部评判用的"脱敏纯文本剧本"同样从展示通道导出，与观察端同源。

### 8.3 访问控制

- **开发期（W3~门禁③）**：单 token。URL `?token=` 或 `Authorization: Bearer`，nginx 层校验透传，obs-api 验签。token 写云端环境变量，不入库不入仓。

## 9. 验收标准

### 9.1 W3 里程碑功能 checklist（源方案 §9：W3 交付地图/角色/地点/事件时间轴/详情 + 涟漪追踪 + 关系演化；评审 P1-6：完整回放引擎与独立 `/replay` 页移出 W3，`/health` 归调试态）

- [ ] 双通道：副本库 schema 无 `text_raw` 列（白名单口径见 05）；前端抓包无内部通道字段；未过审内容渲染占位符。
