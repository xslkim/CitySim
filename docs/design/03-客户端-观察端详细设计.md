## 0. 部署上下文与技术选型

### 0.1 部署上下文（硬约束）

观察端部署在**云端公网机**，数据链路：

```
本机 GPU 机（NAT 后，零入站端口）
  └─ 模拟内核 ──出站 HTTPS/WSS 推事件──► 云端摄入 API ──► 云端事件副本库(PostgreSQL)
                                                            │ 只读
                                    Web 客户端 ◄──WS/REST── 观察端服务(nginx + 只读 API/WS 网关)
```

- 观察端服务**只连接云端副本库，永不回连本机**。断网期间本机正常跑、事件堆积，恢复后批量追平副本库——观察端因此对"副本库延迟于内核"完全无感，设计上把副本库当唯一事实源。
- 观察端感知到的"现在"本来就是内核的"过去"（§3.4 呈现/内核时间偏移），断网追平只是把这个偏移拉大，语义不变。UI 顶部常驻 `数据延迟：副本 tick - 最新事件 tick` 指示条。

### 0.2 技术选型（定死版本与理由）

| 项 | 选型 | 版本 | 理由 |
|---|---|---|---|
| 框架 | React + TypeScript | React 18.3 / TS 5.5 | 团队（单人）最熟生态；并发特性用不上但 18 的 `useSyncExternalStore` 是接 Zustand 与 WS 增量合并的标准姿势 |
| 构建 | Vite | 5.x | dev 启动 <300ms；库模式与单页构建都够；不引入 Next.js——没有 SEO 与服务端渲染需求，纯内部工具/订阅产品形态 |
| 状态管理 | Zustand | 5.x | 事件流是高频外部队列，Redux 的 action/reducer 模板是负担；Zustand 可在 React 外读写 store，WS 回调直接 `store.setState`，绕过组件树 |
| 样式 | Tailwind CSS | 3.4 | 单人开发免去命名与样式文件切换；三栏布局、卡片、告警色全是 utility 一把梭 |
| 地图渲染 | **SVG + CSS transform**（门禁③ 前）→ 预留 Canvas/精灵图切换 | — | 源方案 §6 明定"先用简洁 SVG/格子图，像素美术是门禁③ 之后的事"。SVG  DOM 可点选、可吸附事件委托、调试可见，40 个 Agent + 30 个地点节点远低于 SVG 性能红线（~1k 动态节点）；切 Canvas 时只换渲染层，数据层（坐标/布局描述 JSON）不动 |
| 关系图与曲线 | **Apache ECharts 5.5** | 5.5 | 关系结构演化要 force graph + 时间轴动画 + 双曲线图，ECharts 的 `graph`+`timeline`+双 y 轴 line 开箱即用；D3 自由度更高但单人开发要把力导向、缩放、tooltip 全手写，不值。涟漪追踪的传播树是定制布局（分层 DAG + 失真标注），ECharts 树图不够，用 **D3-hierarchy 算布局 + SVG 自绘**——只用 D3 的布局算法不用其 DOM 绑定 |
| WebSocket | 原生 `WebSocket` 自封装（~150 行） | — | 不引 socket.io：它绑定服务端实现，而我们服务端是 Python；协议自己定（§5），需要 resume-from-tick、心跳、指数退避，socket.io 的机制反而对不上 |
| 表格/虚拟列表 | `@tanstack/react-virtual` 3.x | — | 事件时间轴/事件流可能滚动上万条，必须窗口化 |
| 测试 | Vitest + React Testing Library（store 合并逻辑与协议解析的纯函数测试为主） | — | UI 组件不做重测试，调试工具阶段 ROI 低 |

## 1. 产品定位与信息架构

### 1.1 定位

观察端是目标②"观察这个小社会"的载体，也是开发期**唯一的调试手段**（§1.3）。两个身份决定信息架构：

- **观察者视角**：跟拍角色、看关系演化、追八卦传播——读故事的界面。
- **调试者视角**：同一套数据换个切法——某事件为什么发生（trigger 链）、某角色当时看到了什么（感知注入）、涟漪是否按预期扩散（目击投影验证）、干预率是否越线（trigger 字段审计）。

因此所有页面共用一个原则：**每个 UI 元素都能反查到事件 id**。气泡、关系边、曲线点、健康度指标，全部可点击跳到 `/timeline?focus=<event_id>`。调试 = 顺着事件链走。

### 1.2 页面清单与路由表

| 路由 | 页面 | 观察者用途 | 调试者用途 | 主要数据源 |
|---|---|---|---|---|
| `/map` | 空间地图（首页） | 看全公寓/公司谁在干嘛、点气泡读对话 | 位置一致性（"不在两地"审计）、LOD 层分布 | WS 实时流 + `/api/snapshot` |
| `/agent/:id` | 角色详情 | 人设、心情、关系、今日干了啥 | 认知循环产物检查：最新反思、需求值、检索是否生效 | `/api/agents/:id` + `/api/events?actor=` |
| `/location/:id` | 地点详情 | 这个房间/部门发生了什么 | 目击投影覆盖验证、场所容量校验 | `/api/events?location=` |
| `/timeline` | 事件时间轴 | 倒带看任意时段 | 全文过滤检索事件、trigger 审计 | `/api/events?from&to&type` |
| `/ripple/:eventId` | 涟漪追踪 | "一句话如何毁掉两段关系" | 记忆投影数、八卦链路、失真度 | `/api/ripple/:eventId` |
| `/relations` | 关系结构演化 | 全网关系动画、两人曲线 | 关系图周变化率、负向社交动作效果 | `/api/relations` 系列 |
| `/health` | 叙事健康度 | 这剧最近好不好看 | §8.3 五指标 + 干预率 + 成本熔断状态 | `/api/health` |
| `/replay` | 回放 | 补看错过的黄金档 | 事件流重放复现 bug 现场 | `/api/replay/*` |

导航：顶部固定导航条（8 项 + 数据延迟指示 + 当前模拟时钟 + 压缩比档位）。所有跨页跳转带上下文 query，如 `/agent/:id?at=<tick>`。

## 3. 核心组件详设

### 3.1 空间地图（`/map`）

**布局数据**：静态 JSON（`map_layout.json`，随前端发版），描述节点图：

```jsonc
{
  "sites": [
    { "id": "apt", "name": "单身公寓", "type": "building",
      "floors": 6, "roomsPerFloor": 4,
      "rooms": [{ "id": "apt.L3.302", "floor": 3, "col": 1, "w": 96, "h": 64 }],
      "commons": [{ "id": "apt.lobby" }, { "id": "apt.roof" }] },
    { "id": "corp", "name": "公司",
      "zones": [{ "id": "corp.tech" }, { "id": "corp.market" },
                { "id": "corp.pantry" }, { "id": "corp.meeting" }] },
    { "id": "ext", "name": "外部", "zones": [{ "id": "ext.restaurant" }] }
  ]
}
```

- 公寓渲染为 6×4 网格 + 走廊横带，公司为分区平面；三个 site 用顶部 tab 切换（同屏只渲染一个 site，降低 SVG 节点数）。
- **缩放平移**：一个外层 `<g transform="translate(x,y) scale(k)">`，滚轮缩放（0.5×~4×）、拖拽平移、双击归位。所有角色名牌/气泡反缩放（`transform: scale(1/k)`）保证文字恒定字号。
- **角色名牌与气泡**：每个 Agent 一个 `<g class="pawn">`：圆形头像占位（门禁③ 后换精灵图）、下方名牌（姓名+LOD 徽标）、头顶气泡。气泡三态：`💬对话中`（双人连线）、`💭内心/反思`（灰虚线框，调试态才显示全文）、`📢公告波及`。
- **对话播放节奏**：遵守 §3.4——对话整段已在内核生成完并落库（6~8 轮），观察端收到的是**完整事件 + 逐句时间表**，前端按每句 2~4 秒逐句弹气泡（速度随播放倍率缩放）。正在播放的对话气泡带进度点 `●●○○○`。
- **跟拍模式**：勾选后，被跟拍角色移动时中栏视口平滑跟随（`requestAnimationFrame` 插值），角色进另一 site 自动切 tab。跟拍中右栏锁定该角色摘要卡。
- **移动动画**：`agent.move` 事件到达时，pawn 沿节点间直线 300ms 缓动；跨 site 移动淡出/淡入。倍率 >2× 时跳过动画直接跳变（防队列堆积）。
- **调试叠加层**（快捷键 `d` 切换）：显示每个房间当前在场人数与 `location_id`、事件 id 悬浮 tooltip——直接服务"不在两地"审计的目检。

### 3.2 事件时间轴（`/timeline`）

- **数据**：REST 分页拉取（§5.1 `/api/events`），live 模式下 WS 增量追加。
- **倒带浏览**：scrub bar 以模拟时间为轴；拖到过去 → 自动从 live 切到历史模式（顶部"跳至 live"按钮提示），再拖回右端恢复订阅。
- **播放速度**：`0.5× / 1× / 2× / 4× / 8×`，作用于气泡逐句播放与事件流滚动节奏；注意这是**观察端播放倍率**，与内核压缩比（§4.1 时段变速表）是两个独立旋钮，UI 上分别显示，避免混淆。
- **过滤**：类型多选（枚举见 §5.3 映射表）、角色多选、地点多选、trigger（`autonomous|world|director|gift|vote`）、关键词（匹配展示文本）、A 级事件开关（`payload.grade=="A"`，为剧集化切片选题服务）。过滤条件下推到 REST 查询参数，不在前端滤。
- **密度直方图**：每模拟小时事件计数，`/api/events/histogram` 聚合接口返回，A 级事件红色叠加，点击柱子跳至该时段。
- **性能**：虚拟列表（@tanstack/react-virtual），渲染窗口 ±50 条；详情见 §6.3。

### 3.3 角色详情面板（`/agent/:id`）

| 区块 | 内容 | 数据源 |
|---|---|---|
| 人设卡 | 姓名/性别/年龄/房间号/部门/职位/Big Five 五维条/成长经历(折叠)/标志性视觉符号占位 | `/api/agents/:id`（人设 YAML 的 JSON 投影） |
| LOD 状态 | 当前层徽标 + 升降格历史（`agent.promoted/demoted` 事件列表） | `/api/events?actor=&type=agent.promoted,demoted` |
| 需求六维雷达 | 饥饿/精力/情绪/社交/成就/财富 0~100 雷达图，附 24 模拟小时趋势线 | `/api/agents/:id/state` |
| 今日日程 | 当前模拟日日程条目（含已执行✓/爽约✗标注） | `/api/agents/:id/schedule?day=` |
| 最新反思 | 最近 3 条反思（**展示文本通道**，§7） | `/api/agents/:id/reflections` |
| 关系列表 | 该角色全部有序关系出边，按 \|affinity\| 排序，双人对比跳转 `/relations?pair=A,B` | `/api/relations?agent=` |
| 周目标 | 目标文本 + 受阻计数 + 挫败值进度条 | `/api/agents/:id/state` |

**调试钩子**：需求值与关系值旁各有一个"⏱"小图标，点开显示该值最近 10 次变更的来源事件 id 列表——回答"这数字哪来的"。

### 3.4 涟漪追踪（`/ripple/:eventId`，独有功能）

源方案 §6 明确要求：选中任意源事件，可视化其扩散——记忆投影数、八卦几手传到谁、内容失真、后续事件链、最终改变的关系边。

**数据查询逻辑**（云端副本库 SQL，封装为 `/api/ripple/:eventId` 单接口，避免前端多次往返）：

```sql
-- 1) 直接投影：哪些 Agent 的记忆含来源事件 e0（双人单源投影 + 目击投影）
SELECT m.agent_id, m.memory_id, m.importance, m.is_witness, m.content_display
FROM memory m WHERE m.source_event_id = :e0;

-- 2) 八卦传播链：由 e0 投影记忆驱动的 gossip 事件（payload.cites 含投影记忆 id），递归
WITH RECURSIVE spread AS (
  SELECT ev.*, 1 AS hop, m.agent_id AS teller
  FROM memory m JOIN events ev ON ev.payload->'cites' @> to_jsonb(m.memory_id::text)
  WHERE m.source_event_id = :e0 AND ev.type = 'agent.gossip'
  UNION ALL
  SELECT ev.*, s.hop + 1, m2.agent_id
  FROM spread s
  JOIN memory m2 ON m2.source_event_id = s.event_id
  JOIN events ev ON ev.payload->'cites' @> to_jsonb(m2.memory_id::text)
  WHERE ev.type = 'agent.gossip' AND s.hop < 6
)
SELECT * FROM spread ORDER BY hop, sim_time;

-- 3) 失真度：每手 gossip 事件的展示文本与源事件展示文本的编辑距离/语义相似度
--    （相似度由副本库离线任务预计算存 events.payload->'distortion'，前端只读）

-- 4) 后续事件链：triggered_by = e0 或链上任意事件的事件（裁决因果）
SELECT * FROM events WHERE payload->>'caused_by' IN (:e0_plus_chain) ORDER BY sim_time;

-- 5) 关系边变化：链上事件引发的 relation 变更日志
SELECT pair, delta_affinity, delta_tension, event_id
FROM relation_change_log WHERE event_id IN (:chain_ids);
```

> 依赖内核侧两个落库约定（本文向上游提出的接口要求，需写入 01-内核设计）：记忆条目带 `source_event_id` 与 `is_witness` 标志；gossip 事件 payload 带 `cites`（引用的记忆 id 列表）；任何由事件直接触发的事件带 `caused_by`。三者都是 append-only，符合 Schema v1 扩展方向（payload 内扩展，不改顶层字段）。

## 4. 回放引擎（`/replay`）

### 4.1 语义锚定

源方案 §3.3 写死：**可回放 = 重放事件流（replay），不是重算世界（recompute）**。回放引擎因此纯前端实现：不重跑任何规则/LLM，只按序消费事件流并重建每个 tick 的世界状态投影。这天然保证回放所见 = 当时所发生（同一份 append-only 事件）。

### 4.2 状态机

```
         ┌──────────┐  load(range)   ┌─────────┐
         │  idle    │───────────────▶│ loading │
         └──────────┘                └────┬────┘
                                          │ snapshot+delta ready
                                          ▼
        ┌────────┐  play   ┌─────────┐  seek(tick)  ┌──────────┐
        │ paused │◀───────▶│ playing │─────────────▶│ seeking  │
        └────────┘  pause  └─────────┘◀─────────────┘└──────────┘
                                   ▲        rebuild done
                                   └─────────────────
```

- `loading`：拉取起点前最近的**世界状态快照** + 快照到起点的事件增量。
- `playing`：按倍速（0.5×~8×，复用 §3.2 速度档）消费事件队列驱动世界状态投影推进；事件按到达顺序高亮闪烁。
- `seeking`：见 §4.4。
- 任何状态下 scrub 到尾部可"追上 live"（退出回放，回到 WS 订阅）。

### 4.3 世界状态重建策略：快照 + 增量

- **快照**：副本库 `world_state_snapshot` 表，由摄入任务每模拟日 00:00 落一份全量世界状态 JSONB（40 人位置/需求/情绪/关系矩阵/经济）。体积估算：40 人 × ~2KB ≈ 80KB/份，月 30 模拟日 ≈ 2.4MB，无压力。
- **增量**：快照之后的事件按序应用到投影（事件 → 状态归约器 `reduce(state, event)`，纯函数，逐类型实现约 25 个 reducer——只覆盖影响 UI 状态的字段：位置、情绪、需求、关系、对话气泡、公告；不影响 UI 的字段跳过）。
- 重建正确性自检（开发期）：回放终点状态与下一份快照 diff，字段级不一致即告警——这同时是事件落库完整性的回归测试。

### 4.4 seek 性能方案

- 目标：任意 seek 定位到可交互（<500ms，副本库局域网内查询）。
- 向后 seek（早于当前游标）：不回放全程——取目标 tick 前最近快照 + 应用其间事件增量。单模拟日平均事件数 ≈ 明星层 768 + 次要层 144 + 背景层 40 + 对话等 ≈ **1,500~2,500 事件/模拟日**（§5.2 单价构成同量级），快照间距 1 模拟日 ⇒ 最坏情况应用 ~2,500 个 reducer，每个 <0.05ms，总 <150ms，达标。
- 向前 seek：直接消费队列推进。
- 预取：seek 落地后立即后台预取前后各 1 模拟日的快照+增量进内存缓存（LRU 4 份）。

## 5. 数据协议（核心章节）

协议双层：**REST 拉快照/历史，WS 推增量**。所有时间字段双写：`tick`（单调递增整数，裁决序）与 `sim_time`（ISO-8601 模拟时间，展示用）。排序与续传一律以 `tick` 为准（sim_time 在多事件同 tick 时不保证唯一序）。

事件顶层字段与源方案 §3.3 Schema v1 完全一致：`tick / sim_time / type / source / payload / rng_seed / trigger / arc_id / UI 展示字段`。观察端只在 payload 内消费，不要求改顶层。

### 5.1 REST 接口（全部只读，云端 API 网关 → 副本库）

通用约定：响应包 `{ "ok": true, "data": ..., "meta": { "watermark_tick": 12345 } }`；`watermark_tick` 为副本库当前已同步的最大 tick，客户端据此判断"看到的有多新"。错误 `{ "ok": false, "error": { "code": "...", "message": "..." } }`。分页统一 `cursor`（上一页末条 tick）+ `limit`（≤500，默认 200）。

**GET /api/snapshot?tick=**
> 世界状态全量投影。无参数 = 最新；带 tick = 取 ≤tick 的最近快照 + 增量合并（服务端完成，回放引擎 §4.3 的服务端版）。

  "tick": 12340, "sim_time": "2026-10-12T19:42:00+08:00", "sim_day": 12,

  "agents": [{                          // 40 人，UI 状态子集
    "id": "ag07", "name": "林小满", "lod": "star",       // star|secondary|background
    "location_id": "corp.pantry", "activity": "chatting",
    "mood": 72,                         // 情绪 0~100
    "needs": { "hunger": 40, "energy": 55, "mood": 72,

  }],
  "economy": { "stock_index": 1012.4 },
  "active_dialogues": [{ "event_id": "e1102", "participants": ["ag07","ag12"],
                         "location_id": "corp.pantry",
                         "lines": [{ "speaker": "ag07", "text_display": "今晚约吗?",
                                     "at_offset_s": 0 }, "..."] }] // §3.4 整段+逐句时间表

> 时间轴主查询。`from/to` 接受 tick 或 sim_time；`type` 逗号分隔多值；`q` 匹配展示文本（副本库 `to_tsvector` 中文全文索引）。

### 5.2 WebSocket 通道（`/ws`，wss 强制）

**连接与订阅**（客户端 → 服务端）：

```jsonc
// 1) hello（连接后首帧）
{ "op": "hello", "token": "dev_xxx", "client": "obs/1.0.0" }
// 服务端 → 客户端
{ "op": "welcome", "watermark_tick": 12340, "server_time": "...",
  "session_id": "s_abc" }

// 2) subscribe：声明兴趣集（服务端按此过滤推送，降带宽）
{ "op": "subscribe", "channels": [
    { "name": "events", "filter": { "types": [], "actors": [],
        "locations": [], "grades": [] } },   // 空=全量
    { "name": "world_state" },               // 位置/情绪等轻量差分
    { "name": "health" }                     // 每分钟一次
] }
```

**事件推送**（服务端 → 客户端）：

```jsonc
{ "op": "event", "seq": 88421, "data": { /* §5.1 单条事件 schema */ } }
{ "op": "state_diff", "seq": 88422, "data": {
    "tick": 12341,
    "agents": [{ "id": "ag07", "location_id": "apt.L3.302", "mood": 70 }] } }
{ "op": "health", "seq": 88423, "data": { /* 同 /api/health */ } }
```

**断线重连与 resume**：

- 客户端记录已收最大 `seq` 与最大事件 `tick`；重连后 hello 中携带 `{ "last_tick": 12338 }`。
- 缺口小（服务端内存环缓冲覆盖，默认 10,000 事件）：服务端直接补推缺口段，再接 live。
- 缺口大（环缓冲不够，如断网追平场景）：服务端回 `{ "op": "resync_required" }`，客户端丢弃内存态，走 `/api/snapshot?tick=latest` 全量重建——与回放引擎复用同一 `reduce` 代码路径。
- 心跳：客户端每 30s `{ "op": "ping", "t": ... }`，服务端 `pong`；90s 无心跳服务端断开。重连指数退避 1s→2s→…→30s 封顶，带 ±20% 抖动。

## 6. 状态管理

### 6.1 store 划分（Zustand，React 外可写）

| store | 职责 | 写入方 |
|---|---|---|
| `worldStore` | 当前世界投影：agents 位置/情绪/需求、经济、活跃对话、`watermark_tick`、副本延迟 | WS `state_diff`、snapshot 响应 |
| `agentsStore` | 40 人静态档案 + 按需详情缓存（LRU 20 人） | REST |
| `timelineStore` | 时间轴窗口：事件环形缓冲（容量 3,000，≈1.5 模拟日）、过滤条件、live/历史模式 | WS `event` + REST 历史页 |
| `rippleStore` | 当前涟漪查询结果（一次只查一个源事件） | REST |
| `uiStore` | 路由上下文、选中角色/地点、跟拍、调试叠加层、播放倍率 | 用户操作 |

### 6.2 事件增量合并规则

1. 所有事件按 `tick` 升序进入 `timelineStore`；乱序（resume 补推与 live 交错）按 tick 插入排序，重复 `event_id` 去重（append-only 语义保证幂等）。
2. `state_diff` 按 tick 顺序 apply 到 `worldStore`；`diff.tick <= worldStore.tick` 直接丢弃（快照重建后的旧推送）。
3. 快照重建（resync / replay seek）：先整体替换 `worldStore`，再令 `timelineStore` 只保留 ≥快照 tick 的事件。
4. 气泡播放队列与事件队列分离：对话事件到达只入队"剧本"，播放由 `uiStore` 的倍率时钟驱动——暂停/seek 不影响数据完整性。

### 6.3 40 人规模性能预算

| 指标 | 预算 | 手段 |
|---|---|---|
| 地图帧率 | ≥55fps（40 pawn + 气泡动画同屏） | pawn 组件 `memo`，坐标变化走单 `<g>` transform，不触发 React 重渲染整树；>2× 倍率跳动画（§3.1） |
| 事件缓冲 | 内存 ≤3,000 条（约 5MB） | 环形缓冲，溢出丢弃最旧段；时间轴历史滚动走 REST 分页补段 |
| 时间轴滚动 | 万级条目不卡 | @tanstack/react-virtual，行高固定 44px |
| WS 吞吐 | 峰值 ~2 事件/真实秒（黄金档 1:1）~ 8/s（4× 白天） | 单消息即 setState 一次；`state_diff` 服务端 500ms 合帧 |
| 首屏 | <2s（4G） | 首屏只拉 `/api/snapshot` + 最近 200 事件；图表库 ECharts 按需异步 chunk |
| 内存泄漏防线 | 8h 连续开着不增长 | store 全部有界（环形缓冲/LRU）；订阅随路由切换 `unsubscribe` |

## 7. 双通道分离（安全合规）

源方案 §10：**观察端展示的 Agent 文本与内部记忆双通道分离**。落到字段级：

| 通道 | 字段 | 生成 | 谁能看到 |
|---|---|---|---|
| **展示通道** | `payload.text_display`、`reflection.text_display`、记忆 `content_display` | 内核内容安全管线（本地 Qwen3-4B/8B 初筛 → 云端复核，§10）**通过后**写入 | 观察端、切片素材 |
| **内部通道** | `payload.text_raw`、记忆原文、prompt/检索上下文、LLM 网关全量日志 | 认知循环原始产物 | 仅本机主库 + 开发期本机直连调试；**云端副本库不存此列** |

实现要点：

1. **管道级分离**：本机→云端的摄入同步器按列白名单同步——`text_raw`、prompt 日志、embedding 向量不出本机。副本库 schema 里这些列**不存在**（不是同步但置空），从根上断绝误暴露。
2. **前端零信任**：观察端 proto 类型里只有 `*_display` 字段；即使协议被篡改注入 `text_raw`，zod 校验剥除并告警。
3. **未过审占位**：展示文本未生成/被安全管线打回时，前端渲染 `▮内容审核中▮` 占位气泡，事件本身仍可见（调试需要），但无任何原文泄漏面。
4. 门禁① 外部评判用的"脱敏纯文本剧本"同样从展示通道导出，与观察端同源。

## 8. 部署

### 8.1 云端拓扑

```
公网
  │ 443
  nginx（cloud 机）
  ├── /            → 静态站点（Vite 构建产物，/var/www/obs）
  ├── /api/        → 反代 obs-api:8080（只读 REST 网关，连接副本库只读账号）
  └── /ws          → 反代 obs-api:8080（Upgrade 头，idle 超时 300s > 心跳 30s）
  obs-api (Python FastAPI 或 Node，随云端摄入管线同语言栈)
  └── PostgreSQL 副本库（只读角色 obs_ro：SELECT on 白名单表/列）
```

- 本机→云端摄入链路与副本库归属详见 02-数据/部署篇；本文只约束：**观察端服务账号为只读角色**，DDL/DML 权限为零。
- 静态资源带 `content-hash` 文件名 + `immutable` 缓存；`index.html` no-cache。

### 8.2 构建发布流程

```
web/ 本地开发 (vite dev, 指向云端 dev 实例或本地 mock WS)
  → pnpm build → dist/
  → rsync dist/ cloud:/var/www/obs-<git_sha>/
  → ln -sfn 切换 current 符号链接（原子发布，可秒级回滚）
```

无 CI 重型流水线（单人项目），但 `pnpm build` 前强制 `tsc --noEmit` + `vitest run`（协议解析与 reducer 的纯函数测试）。

### 8.3 访问控制

- **开发期（W3~门禁③）**：单 token。URL `?token=` 或 `Authorization: Bearer`，nginx 层校验透传，obs-api 验签。token 写云端环境变量，不入库不入仓。
- **商业化预留（观察端订阅 ¥19~39/月，§7.2）**：协议与页面不假设永久免费——`hello` 帧的 `token` 字段、订阅过滤的服务端执行、以及"免费用户只能看 24h 前回放"这类策略都只需在 obs-api 加中间件实现，前端协议不变。用户体系与支付合规届时单独立项，不在本期范围。

## 9. 验收标准

### 9.1 W3 里程碑功能 checklist（源方案 §9：W3 交付地图/角色/地点/事件时间轴/详情 + 涟漪追踪 + 关系演化）

- [ ] `/map` 渲染公寓 6×4 + 公司布局，40 pawn 位置与副本库快照一致；缩放/平移/跟拍可用；对话气泡按 §3.4 逐句节奏播放（6~8 轮对话逐句出，每句 2~4s × 当前倍率）。
- [ ] 角色切换：点任意 pawn 或列表项，右栏摘要 + `/agent/:id` 完整详情（人设卡/需求雷达/今日日程/最新反思/关系列表）五项齐全，且每个数值可反查来源事件 id。
- [ ] 地点切换：地点树选中 → 该地点事件流 + 在场角色；`/location/:id` 直达。
- [ ] 事件时间轴：倒带浏览任意时段；0.5×~8× 变速；类型/角色/地点/trigger/关键词/A 级六维过滤生效；密度直方图可点击定位。
- [ ] **涟漪追踪**：任选一条 gossip 起源事件，页面上能回答五个问题——投影给了几人、几手传到谁、每手失真多少、引发哪些后续事件、改变了哪几条关系边（对应 §3.4 五段查询全通）。
- [ ] 关系结构时间演化：force graph 按模拟日播放动画；任选两人出 affinity/tension 双曲线，曲线点可跳事件。
- [ ] 叙事健康度：五指标卡片数值与 §8.3 口径一致，阈值变色正确，干预率红线 15%。
- [ ] 回放：`/replay` 任选过去时段播放/暂停/seek；seek <500ms；回放终点状态与下一份快照 diff 自检通过（开发期每日跑）。
- [ ] 断线重连：拔网 5 分钟恢复后 resume 不重不漏（事件 tick 连续性校验通过）；拔网 2 小时恢复后走 resync 全量重建成功。
- [ ] 双通道：副本库 schema 无 `text_raw` 列；前端抓包无内部通道字段；未过审内容渲染占位符。
