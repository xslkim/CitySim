# WorldSim · 05 云端物化层设计（副本库 schema 与摄入派生管线）

> 版本 v1.0 · 2026-09-20
> 上游：`docs/WorldSim-最终方案.md`（v3.4，下称"源方案"）；同步协议与摄入 API 契约见 `docs/design/04-服务器详细设计.md`（下称 04）§1.3/§9；页面需求见 `docs/design/03-客户端-观察端详细设计.md`（下称 03）。
> 本文是**云端副本库的唯一 schema 权威**（评审 P0-1 的核心交付）：`events`（白名单列）、`memory_projection`、`relation_change_log`、`relation_daily`、`health_daily`、`world_state_snapshot`、`ripple_edge` 七张表为契约名，**不得改名**；03 各页面、04 同步协议、digest 校验均以本文为准。事件类型命名注册表唯一持有方 = `docs/design/06-契约登记表.md`（下称 06）；跨文档字段口径（agent id `TEXT 'A01'~'A40'`、事件引用 `'e<seq>'`、`payload.caused_by`、`payload.cites`、`ui.grade`）见 04 §5.1。

## 1. 定位与数据流

云端副本库是源方案 §6"事件库只读投影 + WebSocket 推送"的落地载体，PostgreSQL 16 独立实例（非流复制）。设计原则：

1. **本机是唯一事实源**：副本库只读投影、永不回写；云端被入侵不影响主库与 LLM 账单（04 §11.2/§11.3）。
2. **脱敏在出站前完成（管道级）**：`text_raw`、记忆原文、embedding、`llm_calls` 明细物理上不存在于副本库 schema（不是同步后置空，是列根本没有）。
3. **全部派生表可由原始层重算**：原始层（`events` 白名单 + `memory_projection` + `world_state_snapshot`）是派生层（`relation_change_log` / `relation_daily` / `health_daily` / `ripple_edge`）的唯一输入；任何派生表损坏或口径变更，按模拟日分区重灌即可（§4.3）。
4. **断网语义**：断网期间本机照跑、事件积压，恢复后按 seq 追平（04 §1.3）；观察端以副本库为唯一事实源，对"副本滞后于内核"无感（03 §0.1）。

```
本机主库                          云端
┌──────────────┐  三流（04 §1.3）  ┌─────────────────────────────────────┐
│ events       │─events 白名单批──►│ ingest API（FastAPI×4，无状态）      │
│ memories     │─memories 投影批──►│   │ 事务：写原始层 + 插 derived_task │
│ world_state  │─日快照──────────►│   ▼                                 │
└──────────────┘                  │ 原始层：events(白名单)               │
                                  │         memory_projection            │
                                  │         world_state_snapshot         │
                                  │   ▼ derived worker（§4，SKIP LOCKED）│
                                  │ 派生层：relation_change_log          │
                                  │         relation_daily / health_daily│
                                  │         ripple_edge                  │
                                  │   ▼ 只读账号 obs_ro（§5）            │
                                  │ obs-api → 03 前端（REST + WS）       │
                                  └─────────────────────────────────────┘
```

## 2. 同步规范形与脱敏规则（digest 适配总纲）

### 2.1 列白名单与键白名单

- **events 白名单列**（04 §5.2 DDL 标注）：`seq, tick, sim_time, wall_time, type, source, trigger, arc_id, location_id, actors, rng_seed, payload, visibility, ui, schema_version`。
- **payload 键白名单**：06 注册表逐事件类型标注每个 payload 键为 public / internal；同步器**默认剥除**，仅放行标注 public 的键。保底规则：`text_raw`、prompt 片段、检索上下文、内部评分中间量一律剥除；`text_display`、`lines[].at_offset_s`、`caused_by`、`cites`、`amount_cents` 等展示/结构键放行。
- **memories → memory_projection**：只出 `content_display`（过安全管线后，04 §11.1/§11.2），`content` 原文与 `embedding` 永不出站；投影行在写入时定型、此后不可变（`archived` 标志不同步——副本保留历史展示文本，检索集收缩是本机侧行为）。
- **快照字段白名单**：见 §3.6。

### 2.2 canonical JSON 与 digest 算法

digest 两端（本机 sync 协程 / 云端校验任务）对同一"同步规范形"计算，**绝不对 `payload::text` 直接 hash**（评审 P1-3：jsonb 键序不保证，且本机 payload 含 `text_raw` 而副本物理剥除，直接 hash 必致每日"不一致→全量重传"死循环）：

```
canonical(payload) = 键白名单剥除 internal 键 → 递归按键名字典序排序
                   → 无冗余空白的 UTF-8 JSON（RFC 8785 风格；两端同一实现）
digest_events(sim_day) = sha256( string_agg( md5(canonical(payload)), '' ORDER BY seq ) )
                       + COUNT(*) + SUM(seq)        -- 按 date(sim_time) 分组
```

- 快速校验（每日例行）可只用 `COUNT(*)/SUM(seq)`；内容级校验（每周 + 重灌后）用完整 digest。
- `memory_projection`：行不可变，`COUNT(*)/SUM(memory_id)` 按 `date(sim_time)` 分组即可（注意口径：只计已出行——`content_display` 未过审的行尚未出站，本机 digest 按同一过滤条件计算，允许两侧时滞，追平后必须一致）。
- `world_state_snapshot`：本机生成快照时算好 `digest = sha256(canonical(state))` 随帧送达，云端复核（§3.6）。

### 2.3 脱敏总表

| 数据 | 处置 |
|---|---|
| `events.payload.text_raw`、prompt/检索上下文 | 键白名单剥除，副本无此内容 |
| `memories.content` 原文、`embedding` | 列不存在于副本 schema |
| `llm_calls` 明细、`interventions` 审计明细 | 不出站；成本/干预率以日聚合形态出站（§3.5） |
| `agents.balance_cents` / `holdings` | 不进快照白名单（余额守恒审计在本机侧，04 §10.1） |
| 事件 `trigger='system'` 等全枚举 | **透传**（04 §1.3；03 过滤枚举必须包含，评审 P2-17） |
| `visibility='internal'` 事件（`state.needs_delta`/`relation.changed`/`time.*`/`system.llm.*`） | 元数据与结构化 payload 出站（回放/健康度/涟漪依赖），无展示文本，前端非调试态不渲染 |

## 3. 逐表定义（契约表，七张）

### 3.1 `events`（白名单列同步）

| 项 | 内容 |
|---|---|
| 产生方 | **sync 白名单直传**（本机主库 `events` → 04 §1.3 events 流） |
| 源 | 主库 `events`（04 §5.2 DDL） |
| 刷新频率 | 实时攒批（200 条或 2s）；断网恢复后 500 条/批流水追平 |
| 脱敏规则 | 列白名单 + payload 键白名单（§2.1）；副本 schema 无 `text_raw` 键落库可能 |
| digest 适配 | 同步规范形 canonical digest（§2.2），或仅 `COUNT/SUM(seq)`；按 `date(sim_time)` 分组，不一致 → 当日重灌 |
| 幂等 | `ON CONFLICT (seq) DO NOTHING`；乱序批拒绝（04 §9.1） |

```sql
CREATE TABLE events (
  seq BIGINT PRIMARY KEY,                 -- 与主库同值（幂等与重灌键）
  tick BIGINT NOT NULL,
  sim_time TIMESTAMPTZ NOT NULL,
  wall_time TIMESTAMPTZ NOT NULL,
  type TEXT NOT NULL,                     -- <domain>.<object>[.<verb>]，注册表见 06
  source TEXT NOT NULL,
  trigger TEXT NOT NULL,                  -- autonomous|world|director|gift|vote|system（全枚举透传）
  arc_id TEXT, location_id TEXT,
  actors TEXT[] NOT NULL DEFAULT '{}',    -- 'A01'~'A40'
  rng_seed BIGINT,
  payload JSONB NOT NULL,                 -- 同步规范形（键白名单后；无 text_raw）
  visibility TEXT NOT NULL,
  ui JSONB,                               -- ui.grade 等（04 §6.6）
  schema_version SMALLINT NOT NULL DEFAULT 1
);
CREATE INDEX events_simday_idx ON events (date(sim_time));          -- 重灌/digest 分组
CREATE INDEX events_type_time ON events (type, sim_time DESC);
CREATE INDEX events_actors_gin ON events USING GIN (actors);
CREATE INDEX events_loc_time ON events (location_id, sim_time DESC);
CREATE INDEX events_caused_by ON events ((payload->>'caused_by'))   -- 涟漪后续链
  WHERE payload ? 'caused_by';
```

### 3.2 `memory_projection`（记忆展示通道投影，含"最新反思"数据源）

| 项 | 内容 |
|---|---|
| 产生方 | **sync 白名单直传**（主库 `memories` 插入时投影，04 §1.3 memories 流） |
| 源 | 主库 `memories`；`is_witness` 为主库列直传（04 §5.2/§6.3，06 §2） |
| 刷新频率 | 随事件批同连实时发送（`content_display` 过审后出站，§2.2 口径） |
| 脱敏规则 | 只出 `content_display`；原文/embedding 不出站；行不可变 |
| digest 适配 | `COUNT(*)/SUM(memory_id)` 按 `date(sim_time)` 分组（§2.2） |
| 幂等 | `ON CONFLICT (memory_id) DO NOTHING` |

```sql
CREATE TABLE memory_projection (
  memory_id BIGINT PRIMARY KEY,           -- 主库 memories.id
  agent_id TEXT NOT NULL,                 -- 'A01'~'A40'
  sim_time TIMESTAMPTZ NOT NULL,
  kind TEXT NOT NULL,                     -- event|projection|reflection|summary|plan
  content_display TEXT NOT NULL,          -- 仅展示通道文本
  importance SMALLINT NOT NULL,
  source_event_seq BIGINT,                -- 主库 memories.source_event_seq（= events.seq；06 §2 定名）
  is_witness BOOLEAN NOT NULL DEFAULT FALSE  -- 目击投影=true（04 §6.3 写入，直传）
);
CREATE INDEX memproj_agent_time ON memory_projection (agent_id, sim_time DESC);
CREATE INDEX memproj_src_event ON memory_projection (source_event_seq);       -- 涟漪第 1 段
CREATE INDEX memproj_reflection ON memory_projection (agent_id, sim_time DESC)
  WHERE kind = 'reflection';                                               -- 角色页"最新反思"
```

### 3.3 `relation_change_log`（关系变更流水，由 `relation.changed` 事件投影）

| 项 | 内容 |
|---|---|
| 产生方 | **摄入任务派生（从 events 投影）**：derived worker 展开 `relation.changed` 事件的 `payload.changes`（04 §6.5） |
| 源事件 | `relation.changed`（每 tick 合并写入，含交互结算、债务逾期日结算、每周自然回归） |
| 刷新频率 | 摄入后微批（事件到达即投影） |
| 脱敏规则 | 纯数值流水，无文本 |
| digest 适配 | 随 events 重灌按模拟日重算（§4.3）；`UNIQUE(event_seq,a_id,b_id)` 保证投影幂等 |
| 消费方 | 03 `/ripple` 第 5 段（关系边变化）、`/relations` 双人曲线与关键事件标注、`/agent` 数值反查（⏱ 来源事件） |

```sql
CREATE TABLE relation_change_log (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  event_seq BIGINT NOT NULL,              -- relation.changed 事件 seq（引用形态 'e<seq>'）
  a_id TEXT NOT NULL, b_id TEXT NOT NULL, -- 有序对 A→B
  delta_affinity SMALLINT NOT NULL,
  delta_tension SMALLINT NOT NULL,
  sim_time TIMESTAMPTZ NOT NULL,
  sim_day DATE NOT NULL,
  UNIQUE (event_seq, a_id, b_id)
);
CREATE INDEX rcl_pair_time ON relation_change_log (a_id, b_id, sim_time);
CREATE INDEX rcl_event ON relation_change_log (event_seq);
CREATE INDEX rcl_simday ON relation_change_log (sim_day);          -- 重灌单位
```

### 3.4 `relation_daily`（每日关系矩阵快照）

| 项 | 内容 |
|---|---|
| 产生方 | **摄入任务聚合**：derived worker 每日任务（§4.2 refresh_relation_daily） |
| 源 | `relation_change_log` 累计 + 基线（首日取 `world_state_snapshot` 首日 relations 矩阵，含人设初始关系 01 §2.2 `relations_initial`）；labels 取当日最后值 |
| 刷新频率 | 每模拟日 1 次（新快照到达触发对前一模拟日定稿，§4.2）；云端每日兜底重算最近 2 日 |
| 脱敏规则 | 纯数值/标签矩阵 |
| digest 适配 | 派生表不进逐日 digest；正确性由"可由原始层重算"保证（§4.3 重灌后比对行数） |
| 消费方 | 03 `/relations` force graph 时间轴动画（`/api/relations/snapshots`）、周变化率小卡 |

```sql
CREATE TABLE relation_daily (
  sim_day DATE NOT NULL,
  a_id TEXT NOT NULL, b_id TEXT NOT NULL,
  affinity SMALLINT NOT NULL,
  tension SMALLINT NOT NULL,
  labels TEXT[] NOT NULL DEFAULT '{}',
  PRIMARY KEY (sim_day, a_id, b_id)
);
```

递推口径：`relation_daily(d) = relation_daily(d−1) + Σ relation_change_log(sim_day=d)`（同边多次变更取 delta 求和、labels 取最后值）；首日 = 基线矩阵。**聚合幂等**：按 `sim_day` `DELETE + INSERT` 单事务完成（§4.3）。

### 3.5 `health_daily`（五指标 + 干预率 + 成本日聚合）

| 项 | 内容 |
|---|---|
| 产生方 | **摄入任务聚合**：derived worker 每日任务（§4.2 refresh_health_daily） |
| 源 | 五指标与干预率由副本侧按 `events` 白名单 + `relation_change_log` **复算**；`¥/模拟日` 成本由本机 audit 日结后写入 `world_state` 键 `health.cost_daily` 随快照流送达（`llm_calls` 明细不出站），本表只落其数值 |
| 刷新频率 | 每模拟日 1 次（与 relation_daily 同触发）；断网追平后自动覆盖重算 |
| 脱敏规则 | 聚合数值，无文本；**阈值不存本表**（阈值唯一持有方 = 01 §9，03 卡片阈值色按 01 §9 判定） |
| digest 适配 | 同 §3.4（派生表可重算） |
| 消费方 | 03 `/health` 五指标卡片 + 干预率红线 + 成本熔断状态（`/api/health`） |

```sql
CREATE TABLE health_daily (
  sim_day DATE PRIMARY KEY,
  a_grade_gap_days NUMERIC,        -- A 级事件间隔（ui->>'grade'='A'）
  type_entropy NUMERIC,            -- 事件类型熵（bit）
  gini NUMERIC,                    -- 出场基尼系数
  ngram_dup NUMERIC,               -- 对话 3-gram 重复度（0~1；判定阈见 01 §9）
  relation_week_change NUMERIC,    -- 关系图周变化率（滚动 7 模拟日窗口，0~1）
  intervention_rate NUMERIC,       -- trigger='director' 占比（红线 15%，源方案 §4.8）
  cost_micro_cny BIGINT,           -- ¥/模拟日（微元；本机 audit 日结经快照流送达）
  computed_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

五指标计算口径以 04 §10.2 为准（04 持有口径、01 §9 持有阈值，本文不重复数字）。

### 3.6 `world_state_snapshot`（每模拟日全量状态）

| 项 | 内容 |
|---|---|
| 产生方 | **sync 白名单直传**（本机内核每模拟日落全量快照 → 04 §1.3 快照流；与 04 §12.1 本地快照同源、字段取白名单子集） |
| 源 | 主库 `world_state` + `agents`/`relations`/`goals` 当前态 |
| 刷新频率 | 每模拟日 1 次（模拟日界 00:00，即 04 §12.1"每模拟日结束"）；断档按 `sim_day` 补发 |
| 脱敏规则 | 字段白名单（下）；不含余额/持仓、不含 secrets、不含记忆原文 |
| digest 适配 | 本机生成时算 `digest=sha256(canonical(state))` 随帧送达，云端落库前复核（§2.2） |
| 幂等 | 按 `sim_day` 覆盖（`ON CONFLICT (sim_day) DO UPDATE`） |

```sql
CREATE TABLE world_state_snapshot (
  sim_day DATE PRIMARY KEY,
  state JSONB NOT NULL,            -- 字段白名单见下
  digest TEXT NOT NULL,            -- 'sha256:…'，本机生成，云端复核
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

`state` 字段白名单（快照 JSON 的允许键）：

```
state = {
  sim:   { day, sim_time },                                   -- 模拟时钟
  agents: [ { id, name, gender, age, room_no, department, job_title,
              cognition_tier,                                 -- LOD 层（日内变动由 agent.promoted/demoted 事件补充）
              persona_display: { big_five, backstory, appearance, speech_style_public },
              needs, mood, position,                          -- 03 需求雷达/地图位置
              goals: [ { goal, blocked_count, frustration } ] } ],  -- 03 周目标+挫败进度条
  relations: [ { a, b, affinity, tension, labels, one_line } ],     -- 关系矩阵（relation_daily 基线）
  economy: { stocks: [ {symbol, price} ] },
  health: { cost_daily_micro_cny },      -- 本机 audit 日结 ¥/模拟日（health_daily 成本列数据源，04 §10.2）
  announcements: [ ...近期公告展示文本... ]
}
```

### 3.7 `ripple_edge`（八卦传播边 + 失真度离线预计算）

| 项 | 内容 |
|---|---|
| 产生方 | **摄入任务派生**：derived worker 对每个 gossip 事件计算其在各传播链上的入边（§4.2 compute_ripple_edge），按链根预聚合——03 涟漪页以源事件直接查 `root_event_seq = :e0`（03 §3.4） |
| 源 | `events`（gossip 事件 `payload.cites`，类型名以 06 注册表为准）+ `memory_projection.source_event_seq`；hop 由 cites 链递归得出，深度上限 4 手（01 §4.1，跨文档统一口径） |
| 刷新频率 | 摄入后微批（gossip 事件到达即算）；每日兜底重算近 2 模拟日防追平乱序 |
| 脱敏规则 | 只用 `content_display`/`text_display` 计算，无原文 |
| digest 适配 | 派生表可重算（§4.3）；`UNIQUE(root_event_seq, dst_event_seq)` 幂等（同一 gossip 事件可出现在多条根的链上） |
| 消费方 | 03 `/ripple/:eventId` 传播树与失真标注（03 §3.4 第 2/3 段直读本表；失真度统一落本表，不回写 events） |

```sql
CREATE TABLE ripple_edge (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  root_event_seq BIGINT NOT NULL,   -- 链根：被转述链的源事件 seq（涟漪页查询键）
  dst_event_seq BIGINT NOT NULL,    -- 本手 gossip 事件 seq
  src_event_seq BIGINT NOT NULL,    -- 上一手事件 seq（hop=1 时 = root_event_seq；重算/调试用）
  hop SMALLINT NOT NULL CHECK (hop BETWEEN 1 AND 4),   -- 深度上限 4 手（01 §4.1）
  teller_id TEXT NOT NULL,          -- 转述者 agent id（'A01'~'A40'）
  listener_id TEXT NOT NULL,        -- 听者 agent id
  distortion NUMERIC(4,3),          -- 0~1：见下
  sim_time TIMESTAMPTZ NOT NULL,
  sim_day DATE NOT NULL,
  UNIQUE (root_event_seq, dst_event_seq)
);
CREATE INDEX ripple_root ON ripple_edge (root_event_seq, hop, sim_time);
CREATE INDEX ripple_simday ON ripple_edge (sim_day);
```

失真度 V1 口径：`distortion = normalized_levenshtein(dst 事件 payload.text_display, 被引用记忆的 content_display)`（归一化到 0~1；对齐 03 失真分级色 ≤15% 灰 / 15~40% 黄 / >40% 红）。语义相似度为 V2 预留（embedding 不出站，如需语义失真度由云端独立 embedding 计算，阶段 1 不做）。

## 4. 摄入 worker 架构与派生任务

### 4.1 架构

```
本机 sync 帧 ──► ingest API（FastAPI/uvicorn ×4，无状态，04 §9.1）
                    │ 单事务：写原始层行 + 插 derived_task 任务行
                    ▼
              derived_task（PG 内队列表）
                    │ SELECT ... FOR UPDATE SKIP LOCKED
                    ▼
              derived worker（worldsim-derived.service，2 进程，单元见 04 §1.4）
                    ├─ project_relation_change   relation.changed → relation_change_log
                    ├─ compute_ripple_edge       gossip 事件     → ripple_edge
                    ├─ refresh_relation_daily    模拟日界        → relation_daily
                    └─ refresh_health_daily      模拟日界        → health_daily
                    ▼
              obs-api（只读账号 obs_ro）→ 03 前端
```

摄入与派生解耦的理由：摄入事务保持短（追平吞吐 ≥2000 events/min，04 §9.2 不受派生计算拖累）；派生失败可独立重试，不回堵事件流。WS 推送由 obs-api 直读原始层事件（不等派生），派生表只服务查询型页面。

```sql
CREATE TABLE derived_task (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  task_type TEXT NOT NULL,            -- project_relation_change|compute_ripple_edge|
                                      -- refresh_relation_daily|refresh_health_daily
  dedupe_key TEXT NOT NULL UNIQUE,    -- 如 'relchg:e12345' / 'ripple:e12346' / 'relation_daily:2026-10-12'
  sim_day DATE,
  status TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','running','done','failed')),
  attempts INT NOT NULL DEFAULT 0,
  run_at TIMESTAMPTZ, done_at TIMESTAMPTZ, last_error TEXT
);
CREATE INDEX derived_task_pending ON derived_task (id) WHERE status = 'pending';
```

### 4.2 派生任务清单

| 任务 | 触发 | 逻辑 | 幂等键 |
|---|---|---|---|
| `project_relation_change` | `relation.changed` 事件摄入 | 展开 `payload.changes` 逐边插 `relation_change_log` | `relchg:e<seq>`（表上 `UNIQUE(event_seq,a_id,b_id)` 双保险） |
| `compute_ripple_edge` | gossip 事件摄入 | 取 `payload.cites` → `memory_projection` 得被引用记忆的 `source_event_seq`（上一手事件）：是非 gossip 源事件 → `root=该事件, hop=1`；是 gossip 事件 → 取其已有 `ripple_edge` 全部 root、`hop+1`（>4 弃链）→ 插 `(root, dst)` 行并算 distortion | `ripple:e<seq>`（表上 `UNIQUE(root_event_seq,dst_event_seq)` 双保险） |
| `refresh_relation_daily` | 新 `world_state_snapshot(sim_day=d)` 到达 → 定稿 d−1；云端每日 05:00 兜底重算最近 2 日 | 按 §3.4 递推口径，`DELETE WHERE sim_day=d−1` + 重算插入，单事务 | `relation_daily:<date>` |
| `refresh_health_daily` | 同上 | 按 04 §10.2 口径在副本侧复算五指标与干预率；成本取自快照 `state` 中 `health.cost_daily` 键 | `health_daily:<date>` |

追平模式：派生任务按 `dedupe_key` 去重，投影类批量消费（单次拉 ≤500 任务）；聚合类以模拟日为单位全量重算，追平完成后最近若干模拟日自动被兜底任务覆盖——**派生层对乱序/积压最终一致**，无需与事件流强同步。

### 4.3 幂等与按模拟日重灌（runbook）

- **投影幂等**：所有派生写都有唯一约束兜底，重复执行安全；任务失败指数退避重试（1m/5m/30m），3 次失败置 `failed` 告警。
- **按模拟日重灌**（口径变更、数据损坏、digest 重灌后的派生对齐）：

```
reproject --table relation_change_log --from 2026-10-01 --to 2026-10-12
  ① DELETE FROM relation_change_log WHERE sim_day BETWEEN ...   -- 按 sim_day 分区删除
  ② 扫 events 白名单区间内的 relation.changed 事件重新投影       -- 原始层是唯一输入
  ③ 对 refresh_*_daily 类：逐日 DELETE+INSERT 重算
  ④ 校验：行数 vs events 侧计数；relation_daily 末日 vs 最新快照关系矩阵抽查 10 条边
```

- 事件重灌（digest 不一致，04 §9.2）后，自动对相关 `sim_day` 排一轮全量派生重算。

## 5. 一致性校验与只读账号

- **digest 校验**：每日 04:30（04 §9.2）对 `events`（同步规范形 / COUNT/SUM(seq)）、`memory_projection`（COUNT/SUM(memory_id)）、`world_state_snapshot`（随帧 digest）逐日比对；结果写审计日报，不一致按 04 §9.2 重灌 + §4.3 派生重算。**W1 演练必过项**：人为删改一行 → 报不一致 → 当日重灌 → 复检一致（04 §13 W1）。
- **只读账号**：`obs_ro` 仅 `SELECT` 于本文七表（DDL/DML 权限为零，03 §8.1 要求）；`derived_task` 与摄入写账号不对 obs-api 暴露。
- **schema 版本**：`events.schema_version` 逐行校验，未知版本拒收（04 §9.1）；派生口径变更走"重灌"而非改历史行。

## 7. 容量估算（W2 实测回填）

以下仅为容量规划假设，**W2 用 8 人世界实测后回填**（与 04 §5.2、03 §6.3 共用同一实测值，评审 P1-1）：

| 表 | 量级假设 | 依据 |
|---|---|---|
| `events` | 万级/真实日 | 04 §5.2（实测回填项）；追平吞吐按 ≥2000 events/min 规划（04 §9.2） |
| `memory_projection` | 与事件同量级 | 参与者投影 + 目击投影 + 反思/摘要 |

| `health_daily` | 1 行/模拟日 | — |
| `world_state_snapshot` | ~100KB/份，1 份/模拟日 | 03 §4.3 同口径（40 人 × ~2KB） |
| `ripple_edge` | gossip 事件数 | 每 gossip 事件 1 行 |
