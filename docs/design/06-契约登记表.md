## 1. 事件类型注册表

### 1.1 命名规则与 trigger 枚举

- **类型命名**：`<domain>.<object>[.<verb>]`，全小写，object/verb 用 snake_case。域清单（封闭集，新增域需修订本表）：`time / agent / dialogue / social / world / economy / director / system / state / relation`。第二轮新增 4 个事件类型均归入**既有域**（`world.overtime`/`world.layoff_rumor`/`economy.bill.rent.overdue`/`economy.bill.rent.notice`，见 §1.2），01 侧的 `work.`/`company.`/`bill.` 旧名不扩域、进 §1.4 更名对照表。
- **trigger 枚举**（6 值，与 04 §5.1 CHECK 一致）：`autonomous | world | director | gift | vote | system`。`gift/vote` 为直播形态预留，阶段 1 无类型使用。观察端过滤枚举必须包含 `system`（评审 P2-17）。
- **source 形态**（04 §5.2）：`'agent:A07'`（agent 域动作）| `'world'` | `'director'` | `'system'`。
- 对话类事件（dialogue 域）`payload.lines[]` 必有，逐句播放时间为 `lines[].at_offset_s`（见 §2 字段表）。
- 干预审计只看 `trigger` 字段不看域：编剧发起的世界事件（如 L0 扰动）类型仍在 `world.*`，但 `trigger='director'` 并落入干预率统计（01 §6.3）。

### 1.2 注册表（全量）

> **"payload 键标注"列口径**（评审第二轮 N-P0-2；05 §2.1 同步器白名单的**唯一实现依据**）：
> - `public` = 同步放行；`internal` = 同步剥除；`条件` = 仅 `visibility='public'` 事件放行（适用 `text_display` 等展示文本键，即 05 §2.1"展示文本条件放行"）。
> - 通用保底（恒 internal，不再逐行赘述）：`text_raw`、prompt 片段、检索上下文、内部评分中间量。
> - `visibility='internal'` 事件（`state.needs_delta`/`relation.changed`/`time.*`/`system.llm.*`）：结构化 payload 照常出站（回放/对账/涟漪依赖），但**不携带任何展示文本键**。

### 1.3 economy 域前缀对账规则（评审 P1-2 裁决）

1. 凡引起 `agents.balance_cents` 结算的事件类型，必须在本表标记**审计域 = economy**，且金额统一落 `payload.amount_cents`（BIGINT，单位分，正=入账、负=出账）。
2. 纯系统经济事件（无 agent 动作主体）一律 `economy.*` 前缀；agent 动作产生的结算（`agent.eat/shop/trade_stock`、`social.give_gift/borrow_money/repay_money` 等）保留动作域命名，但同样打 economy 审计标记。
3. 审计 SQL（04 §10.1 ①余额守恒）的经济类型清单**由本表 economy 标记生成**（`type IN (...)`），不得再仅凭 `LIKE 'economy.%'` 对账——此前口径会系统性漏掉动作域结算、误报红灯；`LIKE 'economy.%'` 仅保留为兜底 sanity check。
4. 新增任何含 `amount_cents` 的类型而未登记本表 = 契约违规，W1 后按 schema 演进流程处理。
