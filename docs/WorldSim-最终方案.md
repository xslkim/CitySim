## 1. 项目概述

### 1.1 场景设定

| 设定 | 内容 |
|---|---|
| 住所 | 一栋单身公寓，6 层 × 每层 4 房间 = 24 间，每间 1 人，男女各半 |
| 工作 | 24 人均为都市白领，在同一家公司不同部门上班；公司另有 16 名员工（含部门经理），总计 **40 个 Agent** |
| 世界 Agent | 负责全局事件（发工资、工作事务、股票涨跌）并兼任**编剧** |
| 触发机制 | 认知频率全部**锚定模拟时间**（v3.3，见 §4.2）；被交互时事件唤醒（进入裁决队列） |

### 1.2 事件双源（核心设定）

1. **全局事件**：世界 Agent 按日历/规则/随机触发（发工资、股价波动、公告）。
2. **自主行为事件**：人物 Agent 因动机主动发起。典型链路：A 暗恋 B（关系状态）→ 傍晚社交需求高（动机）→ 产生"约 B 吃饭"意图 → 系统校验 B 可达 → B 被唤醒自主决定 → 生成约定事件 → 双方记忆同源写入。

两类事件走**同一条裁决与落库管道**——世界只有一个事实来源。

### 1.3 目标与优先级

| 优先级 | 目标 | 对应载体 |
|---|---|---|
| ① | **模拟器本身**：规模可控、逻辑自洽、行为可信 | 内核 + 事件库 |
| ② | **观察渠道**：能观察这个小社会 | **Web 观察端（W3，前置）**——同时是唯一的调试手段 |
| ③ | **商业化**：仅探索可行性 | 剧集化剪辑先行验证需求；直播打赏为可选升级，不预设必须做 |

设计原则：**把最便宜的验证放最前面，外部依赖（平台审批）不进关键路径。**

## 3. 总体架构（A+C 融合，已确认）

### 3.1 分两阶段

**阶段 1（A+ 形态）**：单体 Python 进程，**首日起 append-only 事件表落库**，事件 Schema v1 在 W1 冻结，**存储 W1 直接定死 PostgreSQL + pgvector**（向量检索与阶段 2 复用都指着它）。

```
┌─────────────────── Python 单进程 (asyncio) ───────────────────┐
│ 时间引擎(时段变速表) ──┬─► 世界Agent/编剧(规则+Kimi K3)          │
│                       ├─► Agent调度(LOD 三层 + 裁决队列)         │
│                       │    明星层(滚动): 完整认知循环             │
│                       │    次要层: 廉价决策(每模拟2小时)          │
│                       │    背景层: 日程规则+每日批量摘要           │
│                       ├─► Web 观察端(W3 前置, 调试+观察两用)      │
│                       └─► (可选) 渲染/演出链路                    │
└────────────────────────────────────────────────────────────────┘
 PostgreSQL + pgvector(append-only 事件表 + 世界状态 + 记忆流 + 关系)
 LLM 网关(路由+降级链+全量记录)      GPU 预算(W1 实测后定本地/云端分工)
```

**阶段 2（C 完整形态，独立立项）**：触发条件 = 规模扩展或观察端留存达标。单体调度器替换为 Redis Streams + Agent Worker 集群（LangGraph），Schema/人设/观察端资产全部复用。

### 3.2 LOD 三层梯度认知架构

分层必须是梯度而非二元开关——纯"明星/背景"二分会让 32 人退化成会走路的家具：不产生动机、不主动邀约、不八卦、关系冻结，等于架构亲手制造"三周坍缩成 5 人节目"。三层设计：

| 层 | 人数 | 认知模式（频率锚定模拟时间，§4.2） | 成本 |
|---|---|---|---|
| **明星层（滚动）** | 8 | 每 **模拟 15 分钟**完整认知循环（感知→检索→决策→反思） | 全价（~96 次/模拟日/人） |
| **次要层** | ~12 | 每 **模拟 2 小时**一次廉价决策（小模型+短 prompt，只出高层意图与情绪变化）——保证有动机、会主动发起事件、关系会演化 | 低（~12 次/模拟日/人，合计 ~144 次/模拟日） |
| **背景层** | ~20 | 日程规则推进 + **每模拟日一次批量摘要**（一次调用总结一整天，生成摘要记忆+状态变更） | ≈0 |

关键规则：

- **明星层不固定**：由当前叙事线 + 出场基尼系数驱动轮换，**带迟滞**（避免每日 churn）；指标与架构同向——基尼系数报警时架构自动给冷门角色升格资源。
- **次要层频率已定死**（每模拟 2 小时）：这是成本与"社会感"之间的主旋钮，默认值不可含糊；调它必须同步更新 §5.2 单价。
- **升格/降格是事件**（`agent.promoted / agent.demoted`），落库可审计；被交互、进镜头、被编剧点名即升格。
- **内心状态无断档**：次要层/背景层也在演化（廉价决策、每日摘要），升格时检索衔接的不只是公开事实。
- 次要层是"这是一个社会"和"这是 8 个人加布景"的分界线，增量成本极小，不可砍。

### 3.3 事件 Schema 与"可回放"的准确语义（W1 冻结 v1）

一切事实都是 append-only 事件：`tick / sim_time / type / source / payload / rng_seed / trigger（autonomous|world|director|gift|vote）/ arc_id / UI 展示字段预留`。

**写死的语义**：`rng_seed` 入库只能复现**规则骰子**；LLM 输出即使 temperature=0 服务端也不保证确定性——**"可回放"= 重放事件流（replay），不是重算世界（recompute）**。A/B 实验只能分叉重跑并接受 LLM 噪声。

### 3.4 串行裁决与演出节奏

- 内核按 tick 串行裁决（防并发写冲突），"事件唤醒"实际是"进队列、下一个裁决点处理"。
- **LLM 延迟与观众体验解耦**：对话在内核内**整段生成完毕**（6~8 轮 × 每轮 2~5 秒 = 16~40 秒）落库后，呈现层再**按节奏逐句播放**（每句 2~4 秒）。
- ⚠️ **呈现时间 vs 内核时间偏移**：观众看到的"现在"是内核的"过去"。剪辑/观察端形态无影响；**直播形态下礼物/投票无法影响正在播放的缓冲内容**——已写入直播预案（§7.1），启用直播时必须先解决（如投票只指向"下一段"排期）。

## 4. 核心机制设计

### 4.1 时间引擎：时段变速表

| 真实时段 | 压缩比 | 说明 |
|---|---|---|
| 黄金档 18:00~24:00 | ≈1:1 | 内容主时段，模拟晚间社交高峰与真实对齐 |
| 白天 8:00~18:00 | 2~4× | 加速推进（底线：每真实周 ≥8 模拟日） |
| 凌晨 0:30~8:00 | 批量粗粒度推进（背景层日摘要模式扩展到全员） | 逐 Agent 一次性总结 8 小时 |

**变速表的正确语义（v3.3 修正）**：压缩比只调"**现实里要花多久看完**"，不调"**世界里发生了多少事**"。因为所有认知频率锚定模拟时间（§4.2），**每个模拟日的行为密度恒定**——加速不会稀释世界，"加速养关系"才成立，**¥/模拟日也因此成为真正的不变量**（§5.2）。

### 4.2 触发模型（频率锚定模拟时间）

- 事件唤醒（进裁决队列）> 时钟兜底。
- **一切认知频率锚定模拟时间，真实调用频率 = 模拟频率 × 压缩比**（v3.3 修正：若锚定真实时间，压缩比一变各层相对活跃度漂移；4× 时每个模拟日明星层只思考 1/4 次数，世界密度被稀释）：
  - 明星层：每**模拟 15 分钟**一次决策兜底（1:1 黄金档时恰为真实 5 分钟，与最初设定一致）；
  - 次要层：每**模拟 2 小时**一次廉价决策；
  - 背景层：无 tick，每日批量摘要 1 次。

### 4.3 世界模型

- **空间**：地点节点图——公寓（6 层 × 4 房间 + 公共区）、公司（各部门 + 茶水间/会议室）、餐厅等外部场所；移动=切换节点。
- **状态**（唯一事实源，入库，不让 LLM 编）：模拟时间、位置/余额/持仓/情绪/需求值、股价、公告、关系值。
- **感知**：唤醒时系统注入结构化观察（在哪、几点、谁在场、相关事件）。

### 4.4 认知循环（明星层完整版）

```
感知(系统注入) → 记忆检索(配额制) → 决策(LLM: 意图+结构化动作JSON)
→ 系统校验执行(非法动作拦截) → 结果同源写入各方记忆 → 反思
```

动作空间（枚举）：`move / chat / invite / work / rest / eat / shop / trade_stock / think / argue / gossip / refuse / ...`

### 4.5 记忆系统

- 记忆条目：`{agent_id, sim_time, 内容, 重要性1-10, embedding, 来源事件id}`。
- **配额制检索**：不用混合排序——长跑后 top-k 会被"语义相关但无关紧要"的旧记忆挤占。改为分桶取：**top-k 强制包含 N 条近期 + M 条高重要性 + K 条语义相关**。存储不是瓶颈（pgvector 几十万条无压力），检索质量才是；门禁① 的采访评估是其最直接的检验手段（§8.1）。
- **反思双通道**：重要性累计超阈值触发深度反思 + **每模拟日一次廉价摘要式反思兜底**（防平淡期人格僵化）。
- **双人事件单源**：同一场对话只生成一条事件，双方记忆均为其投影。
- **目击投影**：同场所旁观者获得事件简略投影——八卦自然传播。
- **膨胀治理**：反思合并旧记忆为摘要、低重要性归档、embedding 索引定期重建。

### 4.6 关系与动机系统

- **关系**：有序对 `(A→B)`：亲密度 affinity(-100~100)、张力 tension、关系标签、一句话摘要。
- **需求**（0~100，按模拟时间衰减、被行为满足；衰减率与满足方式按 Big Five 人格差异化）：饥饿、精力、情绪、社交、成就、财富。
- **目标系统（第一公民）**：每 Agent 持有周目标 + 受阻计数，注入决策 prompt；长期受阻 → 挫败值 → 换策略/迁怒/放弃并反思。
- **负向社交动作集**：`argue / gossip / refuse` 入动作空间。
- **意图冷却**：意图被挫败进冷却表（按模拟时间计冷却时长），防重复刷屏。

### 4.7 邀约协议（决策权在 LLM）

```
A 产出 invite(B, 活动, 时间)
   ├─ 校验 B 可达? 不可达→降级"发消息"或作废(写记忆)
   ├─ "邀约送达"事件 → 唤醒 B(按层升格)
   ├─ B 响应：LLM 出决策（人格驱动），规则只做软约束与 sanity 校验
   │    （关键社交决策必须由人格驱动；接受率通过意愿分先验与
   │      人设分布间接控制，目标带 40~60%，作为调参指标而非硬改判）
   │    ├─ 接受→生成约定事件(两人日程) → 到点提醒 → 执行
   │    ├─ 拒绝→双方写记忆+关系微调+A 的 invite 进冷却
   │    └─ 改期→回提议(限 2 轮)
   └─ 每步都是事件记录
```

对话限 6~8 轮；整段生成后呈现层逐句播放（§3.4）。

### 4.8 世界 Agent 与编剧干预分级

职责：日历事件（发工资/账单）、工作事务（任务/绩效/晋升）、经济系统（股价随机游走）、随机扰动、**编剧**（Kimi K3）。

- **干预分级**：L0 环境扰动 / L1 场景排期 / L2 动机助推；**L3 心智控制永禁**。
- **干预率 <15% KPI**；干预事件 `trigger` 字段全量审计；故事弧线多线状态机 + fail-forward。
- 叙事节奏目标：每模拟日 ≥1 个可剪辑的 A 级事件（为剧集化服务；直播后转为每晚黄金档 ≥1 个）。

### 4.9 自洽性保障清单

| 风险 | 对策 |
|---|---|
| LLM 编造事实 | 客观信息全由系统注入；动作枚举化+校验拦截 |
| 两人记忆矛盾 | 交互事件单源落库，记忆为同一事件投影 |
| 人格漂移 | 人设卡每次决策必带；反思受人设约束；每日摘要反思兜底；Big Five 周测 |
| 时间穿帮 | 行为消耗模拟时间；日程冲突拒绝新约定 |
| 密度稀释（v3.3 新增） | 认知频率锚定模拟时间，压缩比只调观看节奏不调世界密度 |
| 经济穿帮 | 余额/持仓只由系统按事件结算 |
| 随机语义混淆 | 骰子可复现（rng_seed）；LLM 不可复现；"可回放=重放事件流"写死 |
| 编剧干预失控 | 分级 + 干预率 KPI + trigger 审计 |
| 并发冲突 | tick 串行裁决 + 队列，后到者收到"已被占用"事实 |
| LOD 穿帮 | 三层梯度保证内心状态持续演化，升格无记忆断档 |

### 4.10 人设系统

- 字段：姓名/性别/年龄/房间号/部门/职位/Big Five/3~5 条成长经历/初始目标/初始关系网/标志性视觉符号（后期美术用）。
- **戏剧拓扑选角**：先设计 40 人关系拓扑（暗恋链、职场对手、老乡、前任），再生成人设——三层 LOD 保证拓扑上每个人都有最低限度的内心演化，无死线；首发 8 个明星角色承载主要故事线（明星层滚动，名单不是终身制）。
- 流水线：LLM 批量生成 → 规则校验（男女各半、经理唯一、部门配比）→ 人工抽查 → YAML 入库。16 名公司 NPC 与租客同构。

## 5. 模型选型与成本

> ⚠️ 型号与定价以开工当天官方文档核实为准，下表为 2026-09 时点的估算口径，不基于记忆写预算。

### 5.1 模型分配

| 负载 | 模型 | 说明 |
|---|---|---|
| 明星层决策/对话 | DeepSeek V4-Flash 档 | 低价+前缀缓存；用现行型号 ID（旧别名已弃用） |
| 次要层廉价决策/批量摘要 | GLM Flash 免费档，或本地 8B | 短 prompt 低质量要求；**开工当天核实免费档 RPM 上限**——次要层压在其上，撞墙（连续限流/延迟超阈值）即切本地 8B |
| 世界 Agent 文案/编剧 | Kimi K3 档 | 中文叙事+1M 上下文；输出贵→限每天几十次 |
| 内容安全初筛/打分/兜底 | 本地 Qwen3-4B/8B | 见 §5.3 GPU 预算 |
| Embedding | **W1 实测后定**：本地 bge-m3 或云端批量 | 每次决策都调用，GPU 忙时云端更稳 |

### 5.2 成本口径：¥/模拟日

**主口径 ¥/模拟日——认知频率锚定模拟时间后，每个模拟日行为密度恒定，它是不变量**（v3.3 修正了 v3.2"准不变量"的说法；唯一变量是事件触发密度，量级远小于兜底频率）。换算：**月成本 = ¥/模拟日 × 每月模拟日数**（由变速表决定，是排期选择）。

- **单价主体构成**：明星层 ~96 次/模拟日/人 × 8 ≈ 768 + 次要层 ~144 + 背景层摘要 ~40 + 对话（每场 6~16 次）+ 反思 + 编剧 K3 + 打分/审核。
- **W2 用 8 人小世界初测单价；W4 扩 40 人后复测**；预算、熔断线、开发期估算全部挂在它上面。
- LOD 节省幅度的诚实口径：对话与反思集中在明星层不按人头缩、次要层与升格调用有增量——**LOD 后成本约为无 LOD 的 35~45%**。
- 无 LOD 反面教材：40 人全量 ≈ 1.15~1.9 万次调用/模拟日 → **¥2,000~4,000/月量级**（1:1 下），不可接受。
- **开发期成本明算**：一次 40 人 2 模拟周预热 = **单价 × 14**；迭代轮数 = 开发预算 ÷ 该值。W4 复测后必须给出这个数。
- **熔断线** = 实测单价基线的 **1.5× 报警 / 2× 自动降速**（¥/模拟日口径）。
- 极端故障：暂停虚拟时钟，恢复后追平。

### 5.3 GPU 资源预算（W1 实测）

同一台消费级机器可能同时承担：安全审核（高频低延迟）、embedding（高频）、TTS（内容期）、渲染/推流编码（直播期）。仓库已有 `.gpu.lock` 说明 GPU 是抢占资源。W1 产出**实测显存/吞吐预算表**，据此决定每项负载的本地/云端归属；原则：**直播期之前不常驻渲染/推流负载**，embedding 在 GPU 忙时切云端批量调用。

## 6. 观察端（W3 前置，目标②的载体）

Web 观察端是"观察一个小型社会"的真正载体，也是开发期**唯一的调试手段**——便宜得多：不需要 OBS、TTS、BGM、立绘、值守、平台报备。

| 功能 | 说明 |
|---|---|
| 空间地图 | 公寓 6×4 + 公司布局（先用简洁 SVG/格子图，像素美术是门禁③ 之后的事） |
| 角色切换 | 点选任意角色：跟拍其位置与行为 |
| 地点切换 | 地点树：楼层/房间/部门 |
| 事件时间轴 | 倒带浏览任意时段的事件流（重放语义，§3.3） |
| 角色详情 | 人设卡、需求值、今日日程、最新反思、关系图 |
| **涟漪追踪（独有功能）** | 选中任意源事件，可视化其扩散：在多少人的记忆里留下投影、经几手八卦传到谁、内容如何失真、引发哪些后续事件、最终改变哪几条关系边。由 append-only 事件流+双人事件单源+目击投影三件套天然支持。同时是：观察视角（目标②）、信息传播链路的调试手段、切片选题来源（"一句话如何在三天内毁掉两段关系"） |
| **关系结构时间演化** | 关系图时间轴动画、任意两人 affinity/tension 曲线——社会的有趣之处在结构变化，不在单点快照 |
| 叙事健康度面板 | §8.3 指标可视化 |

技术上是事件库的只读投影 + WebSocket 推送，与后续演出渲染共用投影层。

## 7. 内容与商业化（仅探索可行性）

### 7.1 内容形态顺序（直播降级为可选升级）

1. **剧集化剪辑（首发形态，W4 起）**：每周 3 条、每条 3~8 分钟。零值守、零平台报备、零断播风险；切片数据是比直播留存更干净的需求信号。
2. **像素美术 + VN 立绘（门禁③ 通过才投）**：数据好 → 投；不好 → 不投，换题材或触发渠道止损。
3. **直播链路（W7+，可选升级）**：此时才需要抖音权限报备、值守制度、礼物互动——**报备从 W1 并行去办，不 gate 任何开发**。
4. 直播形态设计沉淀（值守分级、AI 导播、VN 演出、礼物"保证事件不保证结局"）保留为预案，启用时细化。**预案必带警示：呈现时间 vs 内核时间偏移（§3.4）——礼物/投票无法影响正在播放的 16~40 秒对话缓冲，互动设计必须指向"下一段"排期。**

### 7.2 商业化路径对比（探索，不预设单一答案）

| 路径 | 门槛/成本 | 风险 | 与目标契合 |
|---|---|---|---|
| **切片自媒体分成** | 零门槛，W4 即可验证 | 低 | 中（验证需求） |
| **Web 观察端订阅**（¥19~39/月） | 低（观察端已存在）；注意支付合规 | 低-中 | **高（直接对应目标②）** |
| 抖音直播打赏 | 高：分成约一半、AI 政策最严、每日值守 | 高 | 低-中 |
| YouTube/Twitch 双发 | 中 | 低（AI 政策宽松，Neuro-sama 先例） | 中 |
| 引擎/语料 B 端授权 | 远期 | 低 | 中 |

### 7.3 止损线（两条，硬数字）

- **渠道止损**：门禁③ 完播率/涨粉趋势不达标 → 停投内容渠道与美术；**模拟器与观察端继续跑**（LOD 后 ¥几百/月，自用可持续）。"没人看"只是优先级③失败，不该让①②陪葬。
- **项目止损（任一触发 → 归档为技术资产）**：
  1. 累计投入超过 **¥8,000** 或满 **10 周**（事前写死，防事后自我说服）；
  2. 实测 **¥/模拟日** 超上限——上限数值在 W2 初测后写死（判据示例：单价高到单次 2 模拟周预热即超预算 → 架构需重做，否则止损）；
  3. W6 时事件流仍无聊到自己都不愿读。

## 8. 评估与质量门禁

### 8.1 门禁

| 门禁 | 方法 | 时点 |
|---|---|---|
| ⓪ 内容市场校准 | 摸 B站/抖音同类内容（AI 小镇/AI 村民/虚拟角色连续剧）的真实播放/完播/粉丝量，校准门禁③阈值 | **W0（开工前 1 天）** |
| ① 有意思 + 像人（两项都要） | (a) **外部评判**：2~3 个**不了解项目**的人读脱敏成纯文本剧本的事件流，只问"你想知道后来怎么样吗"（判定人不能是作者本人——确认偏误最重）；(b) **采访评估**（Smallville 式）：随机抽 5 个角色问"你和 X 什么关系""上周最糟的一天是哪天""你现在想做成什么"，对照事件库打分——同时检验配额制检索是否生效 | W2 末初评（8 人）；W4 复评（40 人） |
| ② 真实成本 | 测出 **¥/模拟日** 单价（W2 初测，W4 复测），校准预算/熔断线，算出开发期迭代轮数，写死项目止损单价上限 | W2 / W4 |
| ③ 要不要投美术 | **每周 3 条 × 4 周**（12~15 条切片），看**完播率与涨粉趋势**（抗算法噪声）；定位是"是否投美术重资产"的决策门，**不挂止损** | W4 起 4 周 |

### 8.2 一致性审计（每日自动）

余额守恒 / 不在两地 / 双人记忆同源 / 干预率 <15% / LOD 升降格记录完整。

### 8.3 叙事健康度指标（与审计同跑）

一致性审计防穿帮，这组指标防"无聊"：

| 指标 | 治什么 |
|---|---|
| A 级事件间隔 | 剧情密度是否达标 |
| 事件类型熵 | 是否退化为吃饭睡觉循环 |
| 角色出场基尼系数 | 集中度预警——**且直接驱动明星层轮换**（§3.2），指标与架构同向 |
| 对话 n-gram 重复度 | LLM 台词套路化 |
| 关系图周变化率 | 关系网是否死水 |

## 9. 排期（最便宜的验证最先）

> 内核是整个项目最难、最不可预测的部分，允许多轮推翻重来（4~8 周为正常量级）；门禁不达标顺延，不带病推进。

| 周 | 做什么 | 门禁 |
|---|---|---|
| **W0（1 天）** | 同类内容市场调研（播放/完播/粉丝），校准门禁③阈值 | 门禁⓪ |
| **W1~W2** | Schema v1 + PostgreSQL/pgvector 定死；**8 人小世界**跑通认知循环；**LOD 只做接口预留**（认知模式作为 agent 字段、调度器按字段分发——此时 8 人全是明星层，升降格实现推到 W3~W4）；GPU 实测预算表；认知频率锚定模拟时间从第一天就按 §4.2 实现 | 门禁①初评 + ¥/模拟日初测（写死项目止损单价上限） |
| **W3** | **Web 观察端**：地图/角色/地点/事件时间轴/详情 + **涟漪追踪** + 关系结构时间演化 | — |
| **W3~W4** | 扩到 40 人：**三层 LOD 真实落地**（次要层廉价决策、背景层日摘要、明星层滚动+升格衔接）；离线预热 2 模拟周 | 门禁②复测+预算校准；门禁①复评 |
| **W4 起 4 周** | 手剪切片**每周 3 条**发布（抖音/B站/小红书）。⚠️ **认账：切片每条 2~3 小时，此阶段开发速度约减半，排期已按此放宽**（门禁③ 看趋势与完播率，不看密度） | **门禁③ → 决定投不投美术** |
| **条件触发** | 数据好 → 投像素美术与 VN 立绘；不好 → 不投，换题材或渠道止损 | — |
| **W7+** | 剧集化日更；直播链路作为可选升级启用（先解决呈现/内核时间偏移） | — |

并行事项：抖音权限与报备 W1 起并行办理，不阻塞任何开发。
